## 4. 스크롤 질감 — `scroll-feel`

| 지표 | r4 (65점) | **r5** | 레퍼런스 |
|---|---|---|---|
| **scrubτ** (스크럽 감쇠 시정수) | **0 ms** (감쇠 없음 = 진단서의 핵심 결손) | **32 ms** | 감쇠 계열 |
| **따라오기 프레임** | 7f | **3f** | higgsfield 5f · runway 5f · locomotive 5f |
| 시각 정착 프레임 | 3f | 2f | 3~6f |
| 페이지 스크롤 α / τ | 0.532 / 22ms | 0.672 / 15ms | locomotive 0.053 / 306ms |
| 지터 | 3.08 | 3.26 | locomotive 0.54 |

읽는 법: **스크럽에는 상태가 생겼다**(τ 0 → 32ms, 따라오기 7f → 3f). 반면 **페이지 스크롤 자체의 α·지터는 개선되지
않았고, 그것은 의도한 것**이다 — 엔진 README 의 금기가 "스무스 스크롤과 혼동하지 마라. 이 엔진은 값만 감쇠하고
페이지 스크롤은 네이티브로 둔다(접근성·스크롤바·키보드 유지)"이기 때문이다. 진단서 처방 5개 중 **#2(Lenis 류 문서
전체 보간)만 채택하지 않았다.** locomotive 급 지터(0.54)를 원하면 그 결정을 뒤집어야 하고, 그건 이 런의 범위 밖이다.
`scroll-feel` 이 고르는 추적 요소는 화면 중앙의 가장 큰 요소라서 스티키 핀(스크롤과 1:1)을 잡을 수 있다 —
그래서 팀리드 지시대로 **정착·홀드는 `--e` 직독으로 따로 쟀다**(§5).

## 5. 핀 — `--e` 직독 정착·홀드 (LC-48)

트랙을 40분할이 아니라 **25스텝으로 스크롤하며 매번 200ms 기다린 뒤 `getComputedStyle(track).--e` 를 직접 읽었다.**

| 핀 | 트랙 | 선언 k | `--e`≥0.99 도달 진행률 | 섹션 진행 기준 정착% | **정착 후 홀드** | `--e` 시작→끝 |
|---|---|---|---|---|---|---|
| S2 Control (1440) | 2.40vh | 0.55 | p = **0.44** | **47.5%** | **0.78vh** | 0.139 → 1.000 |
| S5 Worlds (1440) | 2.30vh | 0.53 | p = **0.44** | **47.6%** | **0.73vh** | 0.144 → 1.000 |
| S2 Control (390) | 2.30vh | 0.55 | p = 0.44 | 47.6% | 0.73vh | 0.141 → 1.000 |
| S5 Worlds (390) | 2.20vh | 0.53 | p = 0.44 | 47.7% | 0.67vh | 0.125 → 1.000 |

- LC-48 요구: 정착 45~75% ✓ · 정착 후 홀드 ≥0.6vh ✓ (네 경우 모두).
- **선언 k 와 실측 정착이 다른 이유**: `--e` 는 `1-(1-p/k)³` 이라 시각적 도착이 k 보다 이르다. p/k ≥ 0.785 에서
  이미 0.99 다 → 실측 정착 p = 0.55×0.785 ≈ 0.43. 스토리보드가 "k=0.55 → 정착 55%"라고 쓴 것은 이징을 뺀 값이었다.
- 홀드에 읽을 것: S2 는 `Eight frames, one sentence…`(`data-result`, `--e` 로 나타남), S5 는
  `Now on top: a drained swimming hall…`. 둘 다 정착 구간에서 화면에 남는다(LC-56).
- **두 시계**: 핀 트랙에는 `.sc-stage` 자식을 **두지 않았다**. 엔진은 그때 `stage = track` 으로 폴백하는데,
  스티키 스테이지는 핀 동안 rect 가 얼어 `--v` 가 0.5 에 고정되기 때문이다(엔진 코드 변경 없이 마크업으로 해결).
  그래서 홀드 동안에도 `--v` 가 계속 걸어가고, S2 스테이지는 `--v` 로 위로 밀리고 S5 뒷판 3장은 `--v` 로 표류한다.

  r4 는 24s·5% 였고 그중 5개 섹션은 자율 모션이 아예 없었다.

- 층 예산: 섹션당 모션 채널 **최대 2**(진입 + 유휴), 초과 0 — `landing-integrity` LI-38 실측. 스크럽 채널은

- 이징: 호흡 루프는 UI 이징이 아니라 **대칭 곡선 `cubic-bezier(.45,.05,.55,.95)`** 을 쓴다. 처음에 지배

- `prefers-reduced-motion: reduce` 에서 위 전부 정지, 스크럽 α=1, `[data-rv]` 진입 즉시 완료.

## 9. 스토리보드와 달라진 것 (전부 의도적, 근거 포함)

1. **명도 반전 3회 → 1회.** 스토리보드는 paper(S1~S3) → petrol(S4~S5) → paper(S6~S7) → petrol(S8)이었다.
   `landing-integrity` **LI-11** 은 섹션 ≤9 인 페이지에서 톤 변화가 **1회를 넘으면 FAIL**(엄격 교대는 예외)이다.
   임계를 낮추지 말라는 지시에 따라 **디자인을 고쳤다**: paper S1~S4 → petrol S5~S8, 반전 지점을 **피크(S5,
   판이 쌓였다 펼쳐지는 순간)**에 두었다. 결과 톤열 `L L L L D D D D`. petrol 이 4개 섹션으로 늘어난 대신
   "밝은 종이가 주 지면"이라는 축은 유지된다(길이 기준 paper 6.41vh vs petrol 5.30vh).
2. **길이 산술.** 스토리보드 섹션 표의 합은 1.6+2.6+1.4+1.2+2.4+1.1+0.9+1.2 = **12.4** 인데 본문에는 11.4 로
   적혀 있다. 게이트 F 의 선언 대역(11.0~11.8)을 지키는 쪽을 택해 각 섹션을 깎았다 → 실측 **11.71vh**.
3. **홀드**: 선언 0.9/0.8vh → 실측 **0.78/0.73vh**(LC-48 최소 0.6 충족). C7 줄은 실측값으로 덮어썼다(게이트 C10).
4. **S6 부유 대상**: 스토리보드는 "선택되지 않은 두 판이 2px 부유"였는데 칩 높이 56px 에서 2px 는 진폭 0.35%로
   바닥(1.5%) 아래다. 부유를 **프리뷰 판**으로 옮기고 −2.8%(≈16px)로 키웠다.
5. **LC-57 호버 아웃 타이밍(250~450ms)** 을 지키지 못했다. `filter` 는 LI-14 의 허용 속성 목록에 없어 200ms 를
   넘기면 FAIL 이다. 호버 in/out 을 모두 **160ms** 로 두었다(LC-57 의 in 대역 120~160 은 만족).
6. **진단서 처방 #2(문서 전체 스무스 스크롤)** 는 채택하지 않았다 — §4 참조.
