# rx4-a — 스케일 / 간결함 / 호버 실측 프로브

- 도구: `test-v2/tools/scale-probe.mjs` (신규, 재사용 가능)
- 원자료: `research/r4/scale-probe.json` (사이트별 화면 단위 raw), 중간 파일 `sp-g1~g4.json`(레퍼런스) · `sp-local.json`(r3/r2), 집계 `agg.mjs`
- 캡처: `research/r4/captures/<site>-fold.jpg`, `-peak.jpg` (JPEG, 각 ≤200KB)
- 조건: 1440×900, dark colorScheme, 1뷰포트 단위 스크롤, 각 화면 1.2초 정착 후 2회 샘플링, 레퍼런스는 앞 10화면 · r3/r2는 15화면 전량(비교표는 앞 10화면으로 통일)
- 측정하지 못한 값은 전부 `error` 로 남겼다. 추정치는 이 문서에 없다.

## 0. 지표 정의 (중요 — 박스 ≠ 보이는 것)

| 지표 | 정의 |
|---|---|
| **커버리지(covMed/foldCov)** | 화면을 24×15 격자(360점)로 히트테스트해, 각 점에서 **실제로 먼저 칠해지는** 요소가 미디어(img/video/canvas/svg/background-image)인 비율. clip-path·오버레이·z-order·투명도를 모두 반영한다. **주 지표.** |
| 박스(boxMed/boxMax) | 가장 큰 미디어 요소의 바운딩 박스 ∩ 뷰포트 ÷ 뷰포트. 잘림·가림을 못 본다. **참고용.** |
| 지배도(domMed) | 최대 미디어 박스 ÷ 2위 미디어 박스. 1.0 = 균등 격자, 높을수록 한 장이 지배. |
| 요소 수(elMed) | 화면에서 24×24px 이상, 자식이 없는 말단 요소(텍스트·미디어·버튼) 수. |
| 유휴 애니(idleMed) | `getAnimations()` 실행 중 + 입력 없이 1.2초 간격 두 샘플에서 transform/위치/투명도가 바뀐 요소 수 + 실제 재생 중인 in-view video 수. |
| 호버 관문(hovGate) | CSSOM `:hover` 규칙이 transform/opacity/clip-path/size 를 바꾸는 요소 중 **비호버 기본 상태가 접혀 있는**(opacity<0.05 / max-height:0 / height<2px / clip 100% / scale 0) 것. |
| 호버 실측(hovReveal/hovChanged) | `addEventListener` 를 후킹해 hover 리스너 보유 요소를 표시하고, 화면당 최대 2개(≥2% 면적)를 실제로 hover → 850ms → 이탈 → 850ms 하며 상태 지문을 3회 비교. `revealed` = 숨김→표시로 바뀐 요소, `changed` = 호버로 상태가 바뀐 요소. |

> `getEventListeners()` 는 DevTools 전용이라 페이지 컨텍스트에서 쓸 수 없다. 대신 `EventTarget.prototype.addEventListener` 를 초기 스크립트로 감싸 mouseenter/mouseover/pointerenter/pointerover/mousemove 등록 요소를 실측했다.

### 측정 실패 · 신뢰도 주석 (추정 없음)
- **lusion.co / igloo.inc — `page did not scroll via window.scrollTo nor mouse.wheel`.** 커스텀 스크롤러라 폴드 1화면만 측정됐고, igloo 는 헤드리스에서 본문이 아예 렌더되지 않았다(말단 요소 1개). **두 사이트는 불변량 집계에서 제외**했다. 값이 필요하면 실제 브라우저에서 수동 재측정해야 한다.
- `browser.close() timed out after 10s` (tasteskill, open-design, krea, apple, linear, runway, midjourney): **측정은 완료된 뒤** 크롬 종료만 지연된 것으로, 수치에는 영향이 없다.
- \* **apple hovReveal 33 은 아티팩트**다. 호버 이탈 기준점을 (4,4)로 잡는데 애플 글로벌 내비가 그 지점에 있어 플라이아웃이 열렸다 닫힌다. 애플의 호버 수치는 신뢰하지 말 것.
- † **cosmos foldCov 3.6% 는 과소측정**이다. cosmos 폴드는 작은 타일 수십 개가 떠다니는 구성이라 24×15 격자가 타일 사이를 지나간다. 같은 화면의 박스 중앙값 54.0 · 지배도 6.0 이 실제에 가깝다(캡처 `cosmos-fold.jpg` 참조).

## 4. 정성 관찰 (캡처 근거)

- **tasteskill** (`tasteskill-fold.jpg`) — 큰 이미지가 아니라 **큰 활자 + 여백**이 시원함을 만든다. h1 72px, 좌측 절반은 텍스트 한 덩어리, 우측은 브라우저 목업 3장이 겹쳐 흐른다. 페이지 전체를 덮는 배경 사진은 opacity 0.55 로 깔려 "질감"으로만 작동(커버리지 14.8%). 지배도 8.7 — **한 장이 나머지를 압도한다**.
- **affinity** (`affinity-peak.jpg`) — 폴드 커버리지 89.7%, 최대서체 112px. 화면 중앙에 거대한 세리프 헤드라인 두 줄, 주변에 작품 타일이 흩뿌려져 **"하나의 초점 + 주변부 장식"** 구조. 텍스트블록 중앙 15개로 전 레퍼런스 중 최소급 — 화려한데 읽을 게 적다.
- **cosmos** (`cosmos-fold.jpg`) — 96px급 헤드라인 두 줄 + 사인업 버튼 2개, 폴드 요소 15개. 나머지 전부가 떠다니는 이미지 타일이다. **중앙 텍스트는 정지, 배경만 움직인다** — 사용자가 아무것도 안 해도 화면이 살아 있다.
- **luma** (`luma-fold.jpg`) — 폴드 커버리지 96.4%(전 사이트 1위). 화면 전체가 재생 중인 video(opacity 0.35)이고 그 위에 52px 헤드라인 두 줄 + 버튼 하나. 폴드 요소 20개. **"풀블리드 영상 + 최소 UI"의 교과서.**
- **higgsfield** (`higgsfield-fold.jpg`) — 우리가 경쟁하는 대상이지만 **wow 레퍼런스가 아니다**. 폴드 요소 64개, 텍스트블록 51.5개, 최대서체 40px, 지배도 1.0(균등 카드 격자). 정보 밀도형 대시보드 랜딩. 여기를 따라가면 "화려한데 간결"에서 멀어진다.
- **r3** (`r3-fold.jpg`) — 폴드 커버리지 **6.9%**. 93.6px 헤드라인은 크지만 화면의 93%가 어두운 빈 배경이고, 이미지는 250–380px 타일 8장이 우측에 흩어져 있다. 바운딩 박스로는 100%(풀블리드 `img.shot.cut-b`)지만 **실제로 칠해지는 픽셀은 6.9%** — "이미지를 소극적으로 쓴다"는 사용자 지적의 정확한 실체.

- **LC-53 유휴 모션 예산 (상한 규칙)** — 화면당 유휴 애니 요소 **≤ 10**. 유휴 모션을 늘려 이미지 스케일 부족을 보상하지 말 것. *근거: 레퍼런스 유휴 애니 중앙값 2 (tasteskill 1 / cosmos 2 / luma 1 / apple 0). "저절로 움직임"은 wow 의 불변량이 아니다 — r3 는 유휴 9 로 늘리고 점수는 내려갔다.*

### 5.3 검사기 규칙 후보 (LI-34 ~ LI-38)

- **LI-34 폴드 커버리지** — 폴드 히트테스트 커버리지 < 25% 이면 FAIL. (r3 6.9 → FAIL)
- **LI-35 지배도** — 커버리지 ≥25% 인 화면 중 지배도 ≥2.0 인 화면이 40% 미만이면 FAIL. (r3 1.1 중앙 → FAIL)
- **LI-36 호버 관문 0** — CSSOM `:hover` 규칙이 transform/opacity/clip-path/size 를 바꾸면서 **비호버 기본 상태가 접혀 있는** 요소가 1개라도 있으면 FAIL. 전 레퍼런스 0/0/0. (r3 PASS)
- **LI-37 호버 독점 스펙터클 금지** — 한 화면의 **최대 호버 변화량(hover 시 상태가 바뀐 요소 수)이 같은 화면의 유휴 변화량보다 크면** FAIL. 즉 "그 화면에서 가장 큰 사건"이 호버로만 일어나면 안 된다. *근거: r3 는 `fx-cyl` 화면 2개에서 호버 25요소 변화(유휴 대비 동률~우세), r2 는 0. 사용자의 "매번 호버해야 펼쳐지고 돌아온다"는 이 항목으로만 잡힌다.*
- **LI-38 활자 바닥** — 폴드 h1 < 72px @1440 또는 본문 최대서체 중앙 < 48px 이면 FAIL. (r3 93.6 PASS / 44 FAIL)

### 5.4 산업 중립성
LC-49·LC-50·LC-51·LC-53 과 LI-34~38 은 전부 **기하·개수·시간**만 쓴다. 이미지 소재(제품샷·스크린샷·일러스트·타이포그래피 판)에 대한 가정이 없어 IT·디자인 스튜디오·ERP 어디에도 적용된다. 실제로 대조군 linear(B2B SaaS)는 지배도 11.0 으로 LC-50 을 통과하고 LC-49(폴드 4.4%)에서 떨어지는데, 이는 linear 가 "wow" 가 아니라 "정보형"이라는 사실과 일치한다.

## 6. 프로브 한계 (다음 라운드에 고칠 것)

1. 24×15 격자 히트테스트는 **작은 타일이 많은 구성**(cosmos)에서 과소측정한다. 격자를 48×30 으로 올리거나 타일 개수 보정이 필요하다.
2. 커버리지는 **요소별 페인트 면적**을 주지 않는다. LC-50 지배도는 여전히 박스 기준이라 clip-path 를 많이 쓰는 사이트에서 과대평가될 수 있다.
3. 호버 실측은 **화면당 최대 2개 후보(≥2% 면적)**만 시험한다. 작은 카드 그리드의 호버는 놓친다.
4. 커스텀 스크롤러(lusion, igloo)는 `window.scrollTo`·`mouse.wheel` 둘 다 안 먹는다. Lenis 인스턴스 직접 호출 경로가 필요하다.
5. 호버 이탈 기준점 (4,4) 이 글로벌 내비 위에 있는 사이트(apple)에서 오탐이 난다. 기준점을 화면 하단 여백으로 옮겨야 한다.
