# 스크롤 질감 실측 — "딱딱하다"의 해부 (2026-09-05)

> 사용자 지적(r4 65점): "스크롤 기반의 움직임이 딱딱하다."
> 도구: `test-v2/tools/scroll-feel.mjs` · 원자료: `scroll-feel.json` · 1440×900, 헤드리스 크로미움.
> 측정 방법: 휠 한 번(600px)을 준 뒤 **프레임마다** 스크롤 위치와 추적 요소의 시각 위치를 기록해
> 목표의 63.2%에 도달하는 시간을 시정수 τ 로, `α = 1 − e^(−16.7/τ)` 를 프레임당 보간 계수로 환산했다.

## 1. 한 줄 결론

**가설의 절반이 틀렸다.** 우리 페이지 스크롤은 레퍼런스 다수와 같은 대역에 있다(α 0.53 vs 0.45~0.78).
차이는 **페이지 스크롤이 아니라 감쇠 그룹의 존재**다 — 레퍼런스에는 α 0.05~0.16 의 **감쇠 계열**이 따로 있고
(locomotive 0.053 · higgsfield 0.15 · runway 0.16), 70점을 받은 우리 r2 는 0.25 로 그 쪽에 가까웠다.
r4 는 0.53 으로 **감쇠를 버리며 무감쇠 대역으로 이동**했다.

## 3. 무엇이 진짜 다른가 — 세 가지

### 3.1 관성(멈춘 프레임 0 vs 133)
네이티브 스크롤은 휠 이벤트가 올 때만 움직인다. 마우스 휠은 이산 입력이라 프레임의 **80% 이상이 정지**한다
(우리 133/약 165). locomotive 는 휠을 가로채 매 프레임 목표를 향해 조금씩 밀기 때문에 **정지 프레임이 0**이고
지터가 1/6 이다. "딱딱하다"의 가장 큰 몫은 여기다 — 사이트가 손끝의 입력을 **이어서 흘려주지 않는 것**.

### 3.2 감쇠 계열의 존재
higgsfield·runway 는 네이티브 스크롤을 쓰면서도 α 0.15 대다. 스크롤 자체가 아니라 **스크롤을 읽어 값을 만드는
층에 스프링/댐퍼**가 있다(framer-motion 의 `useSpring`, ScrollSmoother). 우리 r2 의 GSAP `scrub` 이 같은 역할을
했고, r4 에서 그 층을 없앴다.

### 3.3 우리 코드에는 상태가 없다 (재확인)
`runs/template-r4.html` `mountPins()` 은 스크롤 이벤트마다 위치→값을 계산하고 끝난다. `scrubτ = 0` 으로 측정됐다 —
목표값에 **같은 프레임에 도달**한다는 뜻이다. 감쇠·속도·상시 루프가 없다
(`docs/reviews/scroll-stiffness-diagnosis-2026-09-05.md`).

## 4. 기각한 것 · 주의

- **"레퍼런스는 다 스무스 스크롤"은 사실이 아니다.** 13곳 중 진짜 스무스 스크롤은 locomotive 1곳,
  감쇠 계열이 2곳, 나머지 8곳은 우리와 같은 네이티브다. 스무스 스크롤 도입은 선택이지 필수가 아니다.
- **속도 결합 수치는 신뢰하지 않는다.** 우리 페이지가 13(r4)·7(r3)·2(r2), 레퍼런스는 0~1 로 나왔지만,
  우리 쪽 값은 핀 구간에서 같은 화면 좌표가 다른 진행률을 갖기 때문에 생긴 **아티팩트**다. 이 지표는 다음 판에서
  트리거 진행률을 고정한 뒤 다시 재야 한다.
- **lusion·igloo 는 측정 실패**다(문서 높이가 1화면이고 DOM 이 움직이지 않는 WebGL 월드). α=1 로 기록된 값은
  버린다. 이 계열의 질감은 다른 방법(캔버스 프레임 차분)으로 재야 한다.
- 스크럽 감쇠(`scrubτ`)는 `--e` 를 노출하는 우리 페이지에서만 읽혔다. 레퍼런스의 스크럽 감쇠는 α 와 라이브러리
  지문으로 **추정**한 것이지 직접 측정이 아니다.

## 5. 처방 (r5 구현값)

| 항목 | 목표값 | 근거 |
|---|---|---|
| **상시 rAF 루프** | 스크롤 이벤트가 아니라 매 프레임 갱신 | 멈춘 프레임 133 → 0 |
| **스크롤 위치 보간** | `cur += (target − cur) × α`, **α = 0.10~0.16** (τ 100~160ms) | higgsfield 0.15 · runway 0.16 · r2 0.25 보다 조금 더 깊게 |
| **스크럽 값 감쇠** | 진행률에도 같은 보간을 적용, 정착 지점(LC-48)은 보간 **이후** 값으로 판정 | `scrubτ = 0` → 감쇠 도입 |
| **양자화 임계 제거** | `Math.abs(v-last) > 0.0015` 삭제 | 느린 스크롤의 계단 제거 |
| **지터 목표** | 등속 스크롤 지터 ≤ 1.0 (현 3.08) | locomotive 0.54 |
| **스무스 스크롤 층** | 선택 — 도입 시 Lenis(MIT, ~7KB gz) 인라인, α 0.05~0.08 | locomotive 0.053. 접근성(키보드·스크롤바 동기) 확인 후 |
| **속도 결합** | 도입한다면 **한 속성만**(스큐 ≤ 3° 또는 블러 ≤ 3px), 상한을 규칙으로 | 레퍼런스 0~1개 — 남용 금지 |

GSAP 재도입 여부는 선택지 중 하나다. `scrub: 0.6~1.0` 하나로 위 2·3번이 해결되지만(114.7KB raw),
자작 rAF+lerp 는 **20줄 남짓**이고 예산을 쓰지 않는다. **자작을 권한다** — 우리가 이미 핀 엔진을 갖고 있고,
필요한 것은 그 안에 상태 한 줄을 넣는 일이기 때문이다.
