# test-v2 — 브랜드 이미지·영상 데이터셋 + 3자 비교

목적: **9개** 대기업 각각에 대해 **근거 기반 이미지셋·영상셋·데이터셋**을 만들고,
omd CLI와 경쟁 스킬 2종을 같은 조건에서 붙인다. omd 쪽은 UI만이 아니라
**DESIGN.md · 디자인 시스템 · omd book**까지 내놓는지를 중점 검증한다.

작성 2026-08-22. 상태: 증거 캡처 단계 도구 완성, musinsa 1건 실측 완료.

## 0. 왜 이 순서인가

이전 시도(sol 위임분)의 결과물이 나빴던 이유는 생성기가 아니라 **입력**이었다.
근거 없이 "무신사st 이미지"를 프롬프트로 지어내면 어느 회사 것도 아닌 그림이 나온다.

그래서 파이프라인은 생성이 아니라 측정에서 시작한다.

```
00 증거 캡처 → 01 프롬프트 유도 → 02 생성 → 03 대조 검증 → 90 3자 비교
```

각 단계는 앞 단계의 산출물만 인용할 수 있다. 프롬프트에 등장하는 수치는 전부
`00-evidence/<brand>/evidence.json`에 실재해야 한다.

## 1. 재현 강도 (확정)

**구도·광질은 복제, 피사체와 에셋은 새로, 로고는 넣지 않는다.**

| 가져오는 것 | 가져오지 않는 것 |
|---|---|
| 구도 그리드(피사체 위치·여백 비율·크롭 강도) | 그들의 사진·모델·제품 그 자체 |
| 팔레트 실측 hex와 커버리지 | 워드마크·로고·심볼 |
| 조명 방향·확산도·다이내믹 레인지 | 카피 문구 그대로 |
| 모션 페이싱(컷 길이·모션 크기) | 실적·지표 주장 |

근거: 이 레포는 이미 로고를 genuine-only로만 다룬다(추적 불가한 재현·트레이싱 금지).
생성물에 브랜드 마크를 넣는 순간 데이터셋 전체가 공개 비교 자료로 못 쓰게 된다.

## 2. 증거 도메인은 둘로 나뉜다 (실측에서 나온 교훈)

첫 캡처는 무신사 홈 첫 화면의 가장 큰 시각 요소를 히어로로 잡았다. 결과는
**세이지 그린 팔레트**였다. 그날 프로모션 배너의 색이었고, 무신사의 색은 검정이다.

커머스 홈의 첫 화면은 브랜드 언어가 아니라 **광고**다. 그래서 도메인을 갈랐다.

| 도메인 | 무엇 | 어떻게 측정 | 안정성 |
|---|---|---|---|
| `chrome` | 브랜드가 소유한 UI — 헤더·내비·주 버튼·타입 스케일 | computed style | 캠페인과 무관하게 유지 |
| `imagery` | 브랜드가 게시하는 사진 | 표본 12장의 **분포** | 캠페인마다 바뀜 |
| `motion` | 히어로 영상 | 프레임 8장 샘플링 → 모션 크기·컷 간격 | 캠페인마다 바뀜 |

한 장으로 브랜드를 규정하지 않는다. imagery는 항상 분포로 말한다.

## 3. 측정하지 못한 것은 비운다

`subject`(피사체 위치)는 프레임 테두리를 배경 기준으로 삼아 이탈 영역의 무게중심을
구한다. 테두리가 이미 복잡하거나 이탈 영역이 프레임 전체면 **분리 실패로 기록하고
좌표를 내보내지 않는다.**

이유: 프롬프트는 숫자가 있으면 무조건 인용한다. 쓸 수 없는 값은 없는 값보다 나쁘다.

**다만 해석을 앞서가지 않는다.** 무신사 12장 중 분리된 건 2장인데, 이건 "알고리즘이
분리하지 못했다"는 사실이지 곧바로 "엣지투엣지 크롭"의 증거가 아니다 — 복잡한 테두리,
다중 피사체, 텍스처 배경도 같은 실패를 만든다. 구도 성격은 별도 근거로 확인한다.

그리고 **해상 표본이 적으면 집계값도 내보내지 않는다.** 2/12에서 나온 중앙값은
거의 프레임 중앙이라, "10/12가 엣지투엣지"라는 관찰과 동시에 쓸 수 없다.

## 5. 증거 캡처 실행

```sh
cd test-v2/tools
node capture-media-evidence.mjs --brand musinsa --url https://www.musinsa.com/
```

쿠키·동의 모달은 Escape + accept 계열 셀렉터로 자동 처리한다.
캐러셀은 화면 밖 슬라이드를 제외하고, 표본 요소마다 고유 표식을 박아
같은 이미지를 반복 측정하는 사고를 막는다.

산출 요약(무신사, 2026-08-22 실측):

| 항목 | 값 |
|---|---|
| chrome 배경 | `#000000` |
| chrome 주 버튼 | ⚠️ `#5ccca8` — **유효하지 않다.** 라벨이 빈 문자열이고, 카탈로그의 무신사는 primary `#000000`이다. 수집기가 캠페인 CTA를 잡았다 (T3-0 #1에서 수정) |
| imagery 표본 | 12장 |
| 평균 휘도 / 다이내믹 레인지 | 0.752 / 0.609 |
| 광 방향 분포 | top 6 · left 3 · even 2 · bottom 1 |
| 종횡비 중앙값 | 0.833 (4:5) |

## 5.1 차단 사이트 — Aside 채널

쿠팡은 Playwright 구동 Chrome에 **403 "Access Denied"**를 준다(이미지 0개). 같은 URL을
**Aside Browser**로 열면 실제 홈이 온다(타이틀 정상, 큰 이미지 39개).

```sh
open -a Aside https://example.com          # 프로필에 창이 하나 열려 있어야 한다
node capture-via-aside.mjs --brand coupang --url https://www.coupang.com/
```

측정은 `analysis.mjs`를 두 채널이 공유한다 — 채널이 달라도 수치가 같은 의미여야
비교가 성립한다. 구조적 차이는 하나뿐이다: Aside REPL에는 파일시스템이 없어서
스크린샷이 base64로 stdout을 타고 나오고, 크롭은 호스트에서 자른다.

**넘지 않는 선**: CAPTCHA 우회도, 봇 탐지 회피도 하지 않는다. 사이트가 페이지 대신
챌린지를 주면 그건 거절이고 해당 브랜드는 세트에서 뺀다. 쿠팡은 첫 요청에 평소 홈을
그대로 줬다.

쿠팡 실측(2026-08-22): 표본 12장, 평균 휘도 0.844, 다이내믹 레인지 0.796,
종횡비 1.0(정사각 타일), figure-ground 3/12, 피사체 중심 (0.505, 0.582),
`pageBackground`는 투명이라 **미해결로 비움**.

## 6. 원본 캡처는 커밋하지 않되, 버리지도 않는다

`capture/*.png`는 타사 저작물이라 레포에 커밋하지 않는다. 측정값(`evidence.json`)은
사실이라 커밋한다.

**재캡처는 원본의 대체재가 아니다.** 커머스 크리에이티브는 캠페인마다 바뀌므로
같은 `evidence.json`은 두 번 다시 나오지 않는다. 원본을 잃으면 "근거에서 유도했는가"라는
이 프로젝트의 핵심 질문 자체가 감사 불가능해진다.

원본은 **git 밖 불변 저장소**에 보관하고, `manifest.json`(레포에 커밋)이 URL · 캡처 시각 ·
viewport · locale · 세션 상태 · 파일 SHA-256으로 그것을 묶는다. 스냅샷 하나가 3자 비교의
공유 입력 단위다.

```sh
node ingest-captures.mjs --all       # 저장소로 입고 + manifest 생성
node ingest-captures.mjs --verify    # manifest SHA == 저장소 파일 SHA
```

저장소 기본 경로는 `~/.omd/evidence-store/<brand>/<capturedAt>/`이고
`OMD_EVIDENCE_STORE`로 바꿀 수 있다. 캡처 시각이 스냅샷의 신원이다 — 같은 URL이
내일은 다른 페이지를 준다.

**세션 상태는 기록하되 추정하지 않는다.** Playwright 채널은 새 익명 컨텍스트라
`authenticated: false`가 사실이지만, Aside 채널은 사용자의 실제 프로필을 쓰므로
쿠키 상태를 우리가 모른다 — 그래서 `unknown`으로 적는다. 익명이라고 적으면 근거 없는
주장이 된다.

## 7. 생성 채널 — Grok Imagine (실측 2026-08-22)

| 항목 | 확인된 값 |
|---|---|
| 접근 | 로그인 유지됨, 추가 인증 불필요 |
| 이미지 | 프롬프트 1개 → 4변형, 약 18초, 1792×1008, 품질 v2.0 |
| 영상 | 스틸 → 6초 1080p, 약 40초. 6/10/15초, 오디오 토글 |
| 이미지→영상 | `동영상 만들기` → Add Prompt(모션 지정) / Quick Animate |
| 부가 | 세그먼트 자동 분리, 배경 제거, 정밀 편집, 종횡비 변경 |
| 추적 | 생성물마다 post UUID + conversation ID, EXIF에 xAI 서명 |

**다운로드 경로**: grok.com CSP가 localhost 전송을 막으므로 로컬 수집 서버는 못 쓴다.
인증된 페이지 안에서 에셋을 fetch → blob → `<a download>`로 저장한다. 실측 통과
(이미지 224KB, 영상 3.5MB).

## 8. 추적 (03-runs)

3번 항목의 요구사항: **무엇을 요청했고 피드백 과정에서 무엇이 나왔는지 전부
남는다.** run 하나당 다음을 기록한다.

- 입력 프롬프트 원문과 그것이 인용한 evidence 필드
- grok post UUID / conversation ID (원본 추적)
- 생성 결과 파일과 해시
- 대조 검증 결과(구도 좌표 차이, 팔레트 거리, 휘도 차이)
- 재요청했다면 무엇을 바꿨고 왜 바꿨는지

## 9. 남은 단계
