## 1. 비교 단위와 두 레인의 경계

비교 단위는 `레인 × 브랜드 × arm × 반복`이다. 브랜드는 계획에 확정된 9개이며,
각 브랜드·arm·레인을 **4회** 독립 실행한다. 따라서 레인 하나의 arm당 36 run,
세 arm 합계 108 run이다. 무신사 T3-3 파일럿은 교정에만 쓰고 이 36회에 포함하지 않는다.

모든 run은 같은 브랜드 스냅샷(고정 URL, 원본 PNG, 측정 JSON, manifest SHA), 같은 화면
브리프, 같은 필수 산출물 목록을 받는다. **공통 브리프에는 지정 화면의 과업, 공통 필수
산출물, 스냅샷 handle(`snapshot_id`, PNG SHA, `verify.json` block ID)만 넣는다.** T3-1의
슬롯 문장, evidence 필드 해석, 구도·브랜드·이미지 역할에 관한 우리 측 해석은 넣지 않는다.
화면별 과업과 핵심 콘텐츠는 §4.1 코드북에서 별도로 잠근다. arm 순서는 실행 전에
`SHA-256("<lane>|<brand>|<repeat>|T3")`의 첫 바이트를 6개 순열에 매핑해 정한다.
팩 SHA, 모델·버전, 브리프 SHA, 스냅샷 SHA, 순서, 시작·종료 시각을 run manifest에 남긴다.

| 구분 | 레인 A — Controlled | 레인 B — Native |
|---|---|---|
| 질문 | 같은 근거·같은 생성 채널에서 누가 더 잘 지시하는가 | 각 팩의 본래 워크플로가 무엇을 완성하는가 |
| 입력 | 동일 브리프 + 동일 스냅샷 | 동일 브리프 + 동일 스냅샷 |
| 생성 경로 | Grok Imagine 고정 | 각 팩의 고정 SHA가 정한 네이티브 경로 |
| 허용 주장 | **지시 품질** | **스킬 전체 능력** |
| 집계 | 레인 A 안에서만 순위·통과 판정 | 레인 B 안에서만 순위·통과 판정 |

레인 A와 B의 점수를 합산하거나 평균내지 않는다. 한 레인의 우승을 다른 레인의 우승처럼
서술하지 않으며, “종합 우승”도 만들지 않는다.

## 2. 공통 필수 산출물과 능력 커버리지

각 run의 공통 필수 산출물은 (1) 지정 화면의 실행 가능한 첫 렌더, (2) 그 화면에 쓰는
대표 생성 이미지, (3) **형식 자유인 디자인 시스템 설명 문서**다. 세 arm 모두 브리프에서
이 문서를 명시적으로 요청받는다. 파일명이 `DESIGN.md`인지, Core v2 절 순서를 따르는지,
결정 ID가 있는지는 채점하지 않는다. HTML 주석, README, native `design.md`, 추출 문서도
같은 내용 기준으로 읽는다.

다음은 공통 총점에서 **명시적으로 제외**하고 별도 능력 커버리지 표에만 `제공 / 미제공`,
실행 가능 여부, 0–4 유용성 평정과 근거를 기록한다.

- omd book 또는 이에 대응하는 별도 탐색기
- 컴포넌트 상태 매트릭스
- arm 고유 검사기·리포트·추가 화면
- **시맨틱 아트디렉션 주석 계층**

시맨틱 아트디렉션은 실행 화면·대표 이미지·디자인 시스템 문서와 분리된 별도 주석 계층
산출물이다. 이번 루브릭의 공통 브리프·공통 총점에서 **제외**한다. pack이 내부 추론에
쓰는 것은 막지 않지만, 주석 계층을 산출했거나 그 계층에서 이미지 역할을 선언했다는
이유로 §4.2를 포함한 어떤 공통 축에도 점수를 주지 않는다.
능력 커버리지는 순위·통과·우승 문장에 사용할 수 없다.

## 3. 평가자와 블라인드

**평가자는 모델이다. 사람 평가자는 쓰지 않는다** (사용자 결정 2026-08-22).
이 결정이 무엇을 바꾸는지는 §3.1에 명시한다 — 감추면 결과 해석이 틀린다.

### 3.1 이 결정이 줄이는 주장 범위

**모델이 채점하는 축은 네 개 전부다.** 면책을 한 절에 적고 §4 표에 "인간 판정"을
남겨두면 표가 이긴다 — 리포트는 표를 읽는다. 그래서 네 축 모두의 주장을 함께 줄인다.

| 축 | 못 하는 주장 | 할 수 있는 주장 |
|---|---|---|
| 첫 렌더 결함 | "사람이 과업을 못 끝낸다" | "모델 2종이 잠금표 기준 결함으로 합의했다(2026-09-01 개정)" |
| 근거 추종(의미 30%) | "사람 눈에 스냅샷과 같다" | "모델이 스냅샷 관계와 일치한다고 평정했다" |
| 모델 식별력 | "사람이 브랜드를 알아본다" | "모델이 브랜드를 구별한다" |
| 문서 내용 품질 | "구현자가 따라 만들 수 있다" | "모델이 따라 만들 수 있다고 평정했다" |

특히 하나는 별도로 짚는다.

- 원래 「모델 식별력」 축은 *사람이 로고 없이 브랜드를 알아보는가*를 물었다.
  모델이 채점하면 그건 **모델 식별력**이며 다른 능력이다.
- 따라서 이 축의 이름을 **`모델 식별력`**으로 바꾸고, 결과 문장에서
  "사람이 알아본다"는 표현을 쓰지 않는다. 천장 기준선도 같은 모델 구성으로 잰
  **모델 천장**이며, 사람 천장이 아니다.
- 이 한계는 리포트 본문 첫 절에 그대로 적는다.

### 3.2a-2 패널 축소로 생긴 독립성 한계 (2026-09-01 수정안)

패널이 2계열(xai·anthropic)로 줄었다. 서로 다른 2계열이 곧 독립 2인이 아니라는 경고는
§3.2a보다 한 겹 더 두꺼워진다. 추가로:

- **grok-4.6 평가자는 arm 호스트와 같은 계열·같은 서빙 경로(grok-build)다.** 다만 세 arm이
  전부 xai 호스트이므로 자기계열 대비가 arm 사이에 존재하지 않고(§3.2 C2 논리 그대로),
  동계열 상수 편향은 평가자 절편으로 흡수되어 순위에 남지 않는다. 이 문단은 그 한계를
  숨기지 않고 리포트 첫 절에 옮겨 적는 근거다.
- **전사자(opus5)와 최종 검수자(Fable 5)가 평가자 sonnet5와 같은 anthropic 계열이다.**
  전사 왜곡 통제는 §3.3(허용 변환·fail-close·전수 기계 검증)이 담당하며, 검수는 채점 이후
  단계라 채점 사전확률에 개입하지 않는다 — 그래도 계열 중첩 자체를 기재한다.

### 3.2a 개정으로 새로 생긴 독립성 한계 (2026-08-26 — **이력**: cursor 3인 명부 기준. 현행 한계는 §3.2a-2)

개정 평가자 3종은 **같은 서빙 플랫폼(cursor)** 을 지나고, 그중 `composer-2.5`는 그
플랫폼 사업자 자신의 모델이다. 모델 계열이 셋 다 다르므로 §3.2 요건은 만족하고, arm
호스트가 `grok-4.6`(xAI)이라 자기 산출물 채점도 아니다. 그러나 원안(3종이 공개 웹을
공유)에 더해 **서빙 경로까지 공유**하므로, "서로 다른 계열 3종"이 곧 "서로 독립인 3종"이
아니라는 §3.7의 경고가 한 겹 두꺼워진다. **이 한계는 리포트 첫 절에 기재한다.**

### 3.2 평가자 구성

- 독립 평가자는 **서로 다른 계열 모델 2종**이다(2026-09-01 명부 재봉인, 사용자 결정):
  `grok-4.6`(xAI, grok-build 직접) + `sonnet5`(Anthropic, claude-agent). 직전 3인 명부
  (`grok-4.6`·`composer-2.5`·`sonnet5`, cursor-agent 경유)는 이력이다: `grok-4.6`(xAI), `composer-2.5`(Anysphere),
  `sonnet5`(Anthropic). *(개정 2026-08-26 — 원안의 `sol`(codex)은 사용자 결정으로 은퇴했고
  비용이 교체 사유다. 근거·실측: `docs/reviews/t3-3-reseal-proposal-2026-08-26-opus5.md`.
  이 개정은 §9 실행 게이트의 **평가자 등록** 항목이며, 동결이 보호하는 임계값·가중치·결측
  규칙은 건드리지 않는다.)*
  같은 모델을 여러 번 돌린 것은 평가자 수로 세지 않는다 — 그것은 평가자 간 이견이
  아니라 샘플링 분산이다.
- 각 모델은 항목마다 **1회** 채점한다. 2 평가자 미만(2026-09-01 개정; 원문은 3 미만)으로 집계된 항목은 무효다.
- **자기 산출물 회피 규칙은 쓰지 않는다.** 2인 패널(2026-09-01)에서 1건 회피는 단독
  채점을 만들어 α 자체가 성립하지 않고, 애초에 arm 호스트가 셋 공통이라 회피가 성립할
  자기 산출물 대비가 없다. (원문: 평가자가 3종인데 1건만 회피해도 2가 남아
  항목이 무효가 된다. 그리고 이 레포의 벤치 MUT는 `grok-4.6`이고
  (`docs/PROVIDER_ROUTING_POLICY.md`), 레인 A 이미지는 Grok Imagine 고정,
  UIUX Pro Max의 네이티브 이미지는 `gemini-3-pro-image`·`imagen`·`flux`다. 회피를 강제하면 **모델 채점 축이 전항 무효**가 되고,
  강제하지 않으면 죽은 문장이다. 둘 다 실험이 아니다.

- **대신 자기선호를 측정하려 했고, 이 설계에서는 식별되지 않는다.** 그 사실을 적는다.

  `bias_j = mean(자기 계열 arm) − mean(타 계열 arm)`을 축별로 두려 했으나, 호스트가
  `grok-4.6`(`xai`)으로 확정된 뒤 모든 칸이 둘 중 하나가 된다.

  | 칸 | 상태 | 이유 |
  |---|---|---|
  | 레인 A · 전 축 | **N/A** | 호스트도 이미지도 세 arm 공통 `xai`. 달라지는 성분이 없다 |
  | 레인 B · composer·sonnet | **N/A** | 두 계열은 어느 arm에도 없다 (`|자기 계열| = 0`) |
  | 레인 B · grok · 시각 축 | **공선** | 달라지는 유일한 성분이 네이티브 이미지 계열이고, grok의 자기 계열은 omd뿐이다. 그 대비는 **레인 B 이미지 처치 그 자체**다 |
  | 레인 B · grok · 문서 축 | **무의미** | 이미지 계열로 조인하면 문서 축에는 omd vs 나머지 라벨만 붙는다 |

  **그래서 `SELF_PREFERENCE` 플래그를 어느 칸에도 붙이지 않는다.** 공선인 대비를
  자기선호 검출로 읽으면 처치 효과를 편향이라 부르는 것이고, CI가 0을 포함하면
  아래 금지 문장 2를 리포트가 그대로 다시 쓰게 된다.

  기술 통계로서의 `bias_j` 값은 계산해 부록에 남기되, **"처치와 공선 — 편향 추정치가
  아님"** 라벨을 값 옆에 붙인다. 라벨 없는 인용을 금지한다.

  **리포트가 자기선호에 대해 쓸 수 있는 유일한 문장**: *"이 설계에서 평가자 자기선호는
  식별되지 않는다. 측정하지 못했다는 뜻이며, 없다는 뜻이 아니다."*

- **계열 경계와 생성 모델 표.** 자기선호 진단이 이 표 없이는 계산되지 않는다.

  | 항목 | 계열 | 상태 |
  |---|---|---|
  | 평가자 | `xai`(grok-4.6) · `anysphere`(composer-2.5) · `anthropic`(sonnet5) | 확정 |
  | 레인 A 이미지 (세 arm 공통) | Grok Imagine → `xai` | 확정 |
  | 레인 B 이미지 — omd | Grok Imagine → `xai` | 확정 |
  | 레인 B 이미지 — hallmark | nanobanana · recraft · flux → `google` / `recraft` / `bfl` | 확정 |
  | 레인 B 이미지 — UIUX Pro Max | gemini-3-pro-image · imagen · flux → `google` / `bfl` | 확정 |
  | arm 호스트 (세 arm 공통) | `grok-4.6` → `xai` | 확정 (2026-08-23) |

- **C1. 세 arm은 같은 호스트에서 돌린다 (SHALL).** arm마다 다른 호스트를 쓰는 분기는
  닫는다. 그러면 비교 대상이 팩이 아니라 팩+모델이 되고, `bias_j`가 처치와 공선이 된다.
  공유 모델은 `grok-4.6`으로 확정됐다(위 표). §9에 남은 것은 확정 사실의 기록이지
  결정이 아니다.

  **이 선택의 약화를 리포트 첫 절에 적는다.** (i) 모든 추정량이 `grok-4.6` 조건부이고,
  2026-08-29부터는 **그 모델의 Grok Build CLI 서빙 경로**(`grok-build-cli:grok-4.6`)에도
  조건부다. 같은 모델이라도 호출 경로에 따른 시스템 프롬프트·툴셋·컨텍스트 주입 차이는
  측정되지 않았다. 세 arm에 공통이므로 arm 간 비교는 유지되나, 이 트리 밖으로 일반화할 때는
  경로까지 함께 적는다.
  (ii) omd는 이 MUT에 맞춰 개발된 팩이므로 팩×호스트가 처치와 겹치며, 그 크기는
  이 설계에서 산출되지 않는다. 호스트를 바꾸면 교란이 다른 것으로 바뀔 뿐
  레인 A는 살아나지 않는다.

- **C2. `자기 계열` 조인 키는 (호스트 ∪ 이미지)이되, arm 간 상수 성분은 제외한다.**

  호스트가 `grok-4.6`(`xai`)으로 확정되면서 세 arm의 계열 집합에 모두 `xai`가 들어간다.
  그대로 조인하면 `|자기 계열| = 3`이 되어 `bias_j`가 다시 전 항목 N/A다 — 이 조항이
  고치려던 상태로 되돌아간다.

  두 층을 나눠 적는다. **점수 모형에서** arm 전부에 공통인 호스트 일치항은 평가자
  절편으로 흡수되어 arm 차이에 남지 않는다. **조인 키는 그와 별개로 분류기이며**,
  불리언 (호스트 ∪ 이미지) 소속으로 판정하면 호스트가 `xai`일 때 세 arm 모두
  `xai ∈ S_a`가 되어 `|자기 계열| = 3`이 된다. 조인에서 상수를 빼는 직접 이유는
  소거가 아니라, **집합 소속이 의도한 대비를 가려버리기 때문**이다.

  | 레인 | 달라지는 성분 | grok 평가자의 `자기 계열` | 진단 |
  |---|---|---|---|
  | A | 없음 (호스트·이미지 모두 공통 `xai`) | 3 | `bias_j = N/A` |
  | B | 이미지 계열 (omd `xai` / hallmark `google·recraft·bfl` / UIUX `google·bfl`) | omd | **공선 — 처치 대비이지 자기선호 테스트가 아니다** |

  레인 B 칸이 「측정됨」이 아닌 이유는 위 칸 표와 같다. 달라지는 유일한 성분이
  네이티브 이미지 계열이고 grok의 자기 계열은 omd뿐이므로, 그 대비는 레인 B의
  **이미지 처치 그 자체**다. 값은 계산해 부록에 남기되 `SELF_PREFERENCE`로 읽지
  않는다. 시각 축이 섞인 총점의 단독 우승 폐쇄는 CI와 무관하게 그대로 닫힌다.

  **조인 절차 (레인 `L` · 축 `k` · 평가자 `j`마다).** 새 추정량이 아니라 위 표를
  만드는 절차다.

  1. 후보 성분을 `{호스트, 이미지}`로 둔다.
  2. 그 축의 **채점 입력에 들어갈 수 없는** 성분을 뺀다. 이미지 계열은 생성된
     이미지가 채점 입력인 축에만 남는다 — 모델 식별력, 근거 추종 의미 30%,
     그리고 첫 렌더에서는 **`HERO`만**이다. 첫 렌더 전체를 시각으로 묶지 않는다:
     내비 잘림이나 겹침은 이미지 생성기가 만든 결함이 아니다.
     **문서 축에서는 이미지 계열을 빼므로 남는 성분이 없다 → `N/A`, 「측정 불가」.**
  3. 세 arm에 값이 **같은** 성분을 뺀다. 호스트가 `xai`로 공통이면 여기서 빠진다.
     상수를 남기면 불리언 (호스트 ∪ 이미지)가 항등참이 되어 달라지는 이미지
     술어를 가린다 — 조인에서 상수를 빼는 직접 이유는 소거가 아니라 이것이다.
  4. 남은 성분으로 `own` / `other`를 나눈다. `|own| ∈ {0, 3}`이면 `bias_j = N/A`다.

  절차를 두 평가자에 돌리면(2026-09-01) 다음 한 장이 나온다. grok 한 줄만 적으면 구현자가
  composer·sonnet에 식을 새로 만들게 된다.

  | 평가자 | 레인 A | 레인 B 시각 (식별력 · 근거 추종 30% · `HERO`) | 레인 B 문서 |
  |---|---|---|---|
  | grok (`xai`) | N/A | `own = omd` — **공선** | N/A |
  | composer-2.5 (`anysphere`) | N/A | N/A (`|own| = 0`) | N/A |
  | sonnet5 (`anthropic`) | N/A | N/A (`|own| = 0`) | N/A |

  *(라벨 정정 2026-08-26 — grok-4.6 판정 Q2 REVISE. 판정 결론은 교체 전후로 같다:
  `anysphere`도 어느 arm 호스트·이미지 계열에 없으므로 `|자기 계열| = 0`이고 `bias_j = N/A`다.
  바뀐 것은 **그 N/A의 이유**뿐이다 — 「`openai`가 arm에 없다」가 아니라 「`anysphere`가
  arm에 없다」이다. 동결이 보호하는 것은 이 결론과 §3.2의 조인 절차이지 은퇴한 참가자의
  이름 문자열이 아니다. 근거: `docs/reviews/t3-3-reseal-drift-2026-08-26-opus5.md`)*

  - `|자기 계열| ∈ {0, 3}`이면 `bias_j = N/A`이며, **N/A에 `SELF_PREFERENCE`를 붙이지
    않는다.** 플래그가 안 붙은 것은 편향이 없다는 뜻이 아니라 **잴 수 없었다**는 뜻이다.
  - **레인 A는 구조적으로 잴 수 없다.** 세 arm이 같은 호스트·같은 이미지 채널을 쓰므로
    평가자 계열 대비가 존재하지 않는다. 리포트는 레인 A 자기선호를 "없음"이 아니라
    **"측정 불가"**로 적는다.
  - 레인 B 시각 축이 섞인 총점에서는 단독 우승을 닫는다.

- **C4. "arm 간 비교가 유지된다"는 주장의 범위.** 이 문장은 `(평가자 × 호스트 계열)`이
  세 arm에 같은 크기로 더해지는 **가법 성분에 한해서만** 참이다. 방법론이 만든
  산출물 모양에 대한 친화(예: 특정 평가자가 특정 팩의 문서 형태를 더 높게 주는 것)는
  공통 상수가 아니며 `bias_j`가 구분하지 못한다.

  **리포트가 쓸 수 없는 문장 두 개:**
  1. "같은 호스트를 썼으므로 자기선호가 없다"
  2. "`bias_j`로 측정해서 통과했으므로 편향이 없다"

- **C5. `bias_j`는 레인별·축별로 계산한다.** bootstrap 군집은 §7과 동일하게
  브랜드를 1차, run을 2차로 잡는다.

- **C6. 결원 처리.** §7의 예비는 **같은 계열의 재호출**이다. 4번째 계열을 투입하지 않는다.
  계열이 늘면 조인 키와 `bias_j` 대비가 함께 바뀌어 동결된 설계가 아니게 된다.

### 3.3 중립 전사 (변경 없음)

- 채점에 참여하지 않는 전사 담당이 원문의 문장·수치·예시를 내용 손실 없이 옮긴다.
  제목 계층만 중립화하고 원문의 절·문장 순서를 보존하며, 내용을 재분류·요약·보강·평가하지
  않는다. 허용 변환은 표지 삭제와 경로 삭제뿐이다. 원문 SHA와 전사본 SHA 및 문장 대응표를
  봉인한다.
- `evidence.*` 필드나 decision ID가 존재했다는 사실은 점수를 올리지 않는다. 제거된 표지
  아래의 실제 문장만 해당 내용 항목의 앵커를 만족할 때 점수에 들어간다.

### 3.4 레인 분리

- 레인 A와 레인 B는 **서로 다른 채점 호출**에서 채점한다. 한 호출에 두 레인의 산출물을
  같이 넣지 않는다. 두 레인의 난수 순서는 서로 다른 salt로 만들고, 두 전체 순서가
  같으면 B salt에 1을 더해 달라질 때까지 다시 만든다.
- 같은 브랜드의 A/B 산출물을 한 컨텍스트에 함께 제시하지 않는다.
- 평가자 2종 중 1종이 A→B, 다른 1종이 B→A 순서로 호출되도록 배정한다(2026-09-01 개정 —
  scoring-order 재생성본에서 grok-4.6=A-first, sonnet5=B-first로 교차 보존 확인).

### 3.5 파일럿 교정

T3-3 파일럿으로 결함 severity와 0–4 내용 앵커를 교정한다. 파일럿 점수는 본 실험에
들어가지 않는다. 파일럿 앵커도 본 실험과 같은 패킷 형식으로만 교정한다.
교정 후 채점 프롬프트를 재봉인하고 SHA를 갱신한다.

### 3.6 블라인드 파손률

모든 채점을 제출한 직후, 정답 공개 전 각 평가자는 각 레인의 각 익명 산출물마다 arm을
3지선다로 한 번만 추측하고 근거를 `형식 단서 / 내용 단서 / 시각 단서 / 추측` 중 하나로
표시한다. 원시 블라인드 파손률은 `B_raw = 정답 추측 수 / 전체 추측 수`, 우연 보정
파손률은 `B_adj = max(0, (B_raw - 1/3) / (1 - 1/3))`로 계산하고 Wilson 95% CI와 함께
레인별로 보고한다. 이 값은 점수 가산에 쓰지 않고 PASS를 죽이지도 않는다.
`형식 단서`로 표시된 추측만 모은 부분집합의 `B_raw` 95% CI 하한이 `1/3`보다 클 때만
해당 레인의 블라인드를 `COMPROMISED`로 표시하고 단독 우승을 선언하지 않는다.

**모델 평가자에서 파손률의 의미는 더 크다.** 모델은 학습 데이터에서 이 형식들을 봤을
수 있어 사람보다 형식을 잘 알아본다. 파손률이 높게 나오는 것 자체는 실패가 아니라
관측이며, 그대로 보고한다.

### 3.7 평가자 간 일치도

일치도는 레인별·모델 판정 축별로 **3 평가자 기준**으로 계산한다.

| 판정 | 측정 | 최소 기준 |
|---|---|---|
| 결함 존재 여부 | Krippendorff's alpha, nominal | `alpha >= 0.67` |
| 결함 severity와 0–4 내용 평정 | Krippendorff's alpha, ordinal | `alpha >= 0.80` |
| 브랜드 9지선다 (모델 식별력) | Krippendorff's alpha, nominal | `alpha >= 0.67` |

**임계값은 3종에도, 2026-09-01의 2인 패널에도 그대로 동결한다: 0.67 / 0.80 / 0.67.** 파일럿을 보고 정하겠다는
처리는 동결 배너("결과를 본 뒤 임계값을 바꾸지 않는다")와 모순이다. 파일럿도 같은
프롬프트의 관측 α이고, 그 숫자를 본 뒤 0.80을 내리면 INCONCLUSIVE를 피하는 기준을
관측 후에 고르는 것이다. 각주는 투명성이지 잠금이 아니다.

평가자 3으로 α 추정 분산이 커지는 것은 사실이며, 그래서 미달이 늘어날 수 있다.

**2026-09-01 수정안 — 2-rater 재정의.** 패널이 2인이 되면 Krippendorff's α는 그대로
계산 가능하나(단위=칸, 관측자 2) 추정 분산이 더 커진다. 임계값은 **바꾸지 않는다
(0.67 / 0.80 / 0.67)** — 결과를 본 뒤 임계를 조정하는 길을 막기 위해서다. 대신 미달 시
처분을 사전 선언한다: α 미달 축은 INCONCLUSIVE로 표기하고 두 평가자의 원점수를 병기하며,
합의점수·평균으로 대체하지 않는다. **α 미달 시 재채점 절차는 §3.7 원문(해당 레인·축 전
항목을 새 익명 순서로 재채점) 하나만 남긴다** — 예비 청크의 칸 단위 재채점은 α 절차가
아니라 §4.3의 결함 존재 불일치 해소 전용이다(2026-09-02 판정 집행으로 이원화 제거).
**미달은 조정 사유가 아니라 결과다** — `INCONCLUSIVE`로 보고한다.

**독립성 한계 (이 체제의 구조적 제약).** Krippendorff's α는 독립 평가자를 전제한다.
평가자 2종은 계열이 다르지만(2026-09-01) **공개 웹이라는 같은 학습 소스를 공유**하므로 완전한
독립이 아니다. 따라서 높은 α를 사람 합의의 대체값으로 읽지 않는다. 같은 이유로
원본 천장 `C_b`는 "이 스냅샷의 시각 언어"가 아니라 **"모델이 이 브랜드 페이지를
기억하는가"**를 섞어 재고 있을 수 있다. 두 한계 모두 리포트 첫 절에 적는다.

최소 기준에 못 미치면 결과를 공개하거나 순위를 내지 않는다. 파일럿 앵커를 한 번만
수정하고 해당 레인·축의 **전 항목을 새 익명 순서로 재채점**한다. 두 번째도 미달이면
그 레인 전체는 `INCONCLUSIVE — rater agreement failed`이며, 낮은 일치도를 다수결로
덮지 않는다.

적용이 결함을 체계적으로 덜 세는 문제와 단독 표기의 과다 집계를 모두 피하기 위함).
severity는 2인 병기, 불일치면 낮은 쪽을 채택하고 원값을 병기한다. (원문: 다수결, 동률이면

### 4.2 근거 추종

`verify.json`은 T3-0/T3-1을 통과해 **eligible**로 표시된 evidence 필드만 읽는다.
결측 필드를 추정하거나 인접 필드로 대체하지 않는다. 수치 점수는 아래 필드별 점수의
산술평균이다. `clamp(x)`는 0–100 범위 절삭이다.

| 필드 | 오차 `e` | 필드 점수 |
|---|---|---|
| 종횡비 | `abs(gen/source) - 1` | `clamp(100 × (1 - e/0.10))` |
| 평균 휘도 | 0–1 절대차 | `clamp(100 × (1 - e/0.20))` |
| 다이내믹 레인지 | 0–1 절대차 | `clamp(100 × (1 - e/0.20))` |
| 피사체 중심 | 정규화 좌표의 Euclidean 거리 | `clamp(100 × (1 - e/0.25))` |
| 팔레트 | 아래 고정 팔레트 절차의 coverage 가중 평균 `ΔE00` | `clamp(100 × (1 - e/25))` |

팔레트 절차는 `test-v2/tools/analysis.mjs`의 실제 측정과 동일하게 고정한다. source와
generated 이미지를 각각 sRGB의 채널별 **5-bit**(`channel >> 3`, 총 `32^3` bin)로
양자화하고, 픽셀 수 내림차순 상위 `k=6` bin을 쓴다. 각 bin 색은 그 bin 소속 원본 8-bit
RGB 픽셀의 채널별 산술평균이고, coverage는 `bin pixel count / frame pixel count`다.
source 상위 bin `i`마다 generated 상위 6 bin 중 CIEDE2000 `ΔE00`가 최소인 값을 `d_i`로
잡으며 일대일 매칭은 강제하지 않는다. 팔레트 오차는
`e_palette = Σ_i(coverage_i × d_i) / Σ_i coverage_i`다. RGB→Lab은 D65, sRGB 표준 전달
함수를 사용한다. `analysis.mjs`가 coverage를 소수 넷째 자리로 저장하므로 점수 계산도
그 저장값을 사용한다.

팔레트·휘도·다이내믹 레인지는 그날 스냅샷 추종 지표일 뿐 브랜드 불변량이나 브랜드
식별력으로 해석하지 않는다. eligible 수치 필드가 2개 미만이면 그 스냅샷은 비교 입력
불충분으로 보고 세 arm의 해당 block을 실행 전에 교체한다.

모델 의미 판정 30%는 **스냅샷 충실도만** 본다. 별도 시맨틱 아트디렉션 주석, pack이
선언한 이미지 역할, 브랜드 사실의 양, T3-1 슬롯 해석은 보지 않는다. 수치 지표가 직접
재지 않는 관찰 가능한 전경/배경 관계, 요소의 상대적 크기·겹침·반복, 시각적 위계와
크롭의 전체 인상이 스냅샷과 얼마나 일치하는지를 `0=관찰 가능한 관계가 거의 반대`,
`1=대부분 불일치`, `2=혼합`, `3=대부분 일치`, `4=핵심 관계와 전체 인상이 일치`로
평정해 25를 곱한다.
축 점수는 `0.70 × verify 수치점수 + 0.30 × 모델 의미점수`다.

**충돌 규칙:** 측정 가능한 필드에서는 `verify.json`이 승자이며 모델 평정이 숫자를 덮어쓰지
않는다. 비수치 스냅샷 관계·시각 위계에서는 모델 평정이 승자이며 verify가 이를
대체하지 않는다. 둘이 반대여도 위 70:30 식을 그대로 적용하고 사후 재량 조정은 없다.
verify 도구 오류가 세 arm에 공통이면 해당 block 전체를 보류·수리 후 재실행한다. 한 arm의
잘못된 파일 때문에 verify가 못 읽으면 그 arm의 verify 부분은 0점이다.

### 4.3 모델 식별력과 원본 천장

**원본 천장은 9개 중 5개 브랜드에서 측정된다 (2026-08-23 두 서피스 실측).**

천장 자극은 브랜드명·로고·워드마크·고유 카피가 없는 원본이어야 한다. 중앙 크롭으로
지우려던 최초 시도는 실패했다 — 웹 크리에이티브는 브랜드 카피를 가장자리가 아니라
프레임 한가운데 놓는다(애플 히어로를 크롭하니 "iPhone"·"MacBook Air"가 정중앙에
남았다). 그래서 변형이 아니라 **선별**로 바꾸고 전 표본을 눈으로 검토했다.

| 브랜드 | 적격 자극 | `C_b`에 쓰는 4개 | 판정 |
|---|---:|---|---|
| musinsa | 16 | d1 d2 d3 d4 | ✅ |
| karrot | 11 | d1 d2 d3 d4 | ✅ |
| naver | 7 | m3 m4 m5 m7 | ✅ |
| toss | 5 | d2 m6 m8 m11 | ✅ |
| figma | 4 | d1 d5 d8 d9 | ✅ |
| apple | 0 | — | ❌ 모든 히어로가 제품명을 싣는다 |
| baemin | 0 | — | ❌ 이미지가 브랜드 일러스트이고 워드마크·슬로건·모회사명을 싣는다 |
| coupang | 0 | — | ❌ 사진은 한 장뿐이고 그마저 자사 프로모 밴드를 싣는다 |
| wanted | 0 | — | ❌ 12장 전부에 「합격보상금 100만원」 캠페인 오버레이 |

라벨은 서피스 접두사다 — `d*`는 `desktop-1440`, `m*`는 `mobile-390`. 두 서피스를 함께
재면서 naver·toss가 처음으로 측정 가능해졌고(둘 다 모바일에서만 나온다), wanted는 반대로
0이 됐다.

적격 풀이 4를 넘으면 **식별 결과를 보지 않은 채** build 순서 앞 4개만 `C_b`에 쓴다.
더 큰 풀에서 사후에 고르면 천장을 결과에 맞춰 고르는 것이다.

브랜드 자기 제품 UI는 제외한다 — 피그마 펜툴 캔버스, 토스 `m3`(내 상점)·`m5`(금리
분석)·`m7`(내 보험 리포트)이 그렇다. 제3자 마크(무신사 옷의 나이키 스우시, 당근 매물의
LG 노트북)는 그 브랜드가 찍는 것이지 그 브랜드를 가리키는 라벨이 아니므로 허용한다.

**「이 결손은 캡처의 한계가 아니라 브랜드의 성질」은 apple·baemin·coupang·wanted에만
쓴다.** 나머지 다섯은 기준을 넘었다.

정본 판정: `docs/reviews/rubric-2026-08-23-capture-conflicts.md` C-CEILING REVISE.

**따라서 모델 식별력 축은 figma·karrot·musinsa·naver·toss에서 채점한다.**
apple·baemin·coupang·wanted의 그 축은 `CEILING_UNAVAILABLE`이며, §4.5의 가용 축
재정규화를 적용한다. 천장 없이 식별력 점수를 내면 비교 대상 없는 숫자가 된다.

**이 네 브랜드의 결손은 캡처의 한계가 아니라 브랜드의 성질이다.** 애플·배민·쿠팡·원티드의
시각 정체성은 타이포와 카피가 함께 만든다. 그런 브랜드에 "글자 없이 알아볼 수 있는가"를
묻는 것은 **브랜드 자신이 하지 않는 일을 생성물에 요구하는 것**이다. 리포트는 이
브랜드들의 식별력을 "낮다"가 아니라 **"이 방식으로는 물을 수 없다"**로 적는다.
나머지 다섯에는 이 문장을 쓰지 않는다 — 그쪽은 기준을 넘었다.


생성물 공개 전에 같은 2종이 브랜드명·로고·워드마크·고유 카피를 중성 패치로 지운
원본 자극을 보고 9개 브랜드 중 하나를 강제로 고른다. 브랜드별 원본 4개를 사용하며
마스크 좌표와 이미지 SHA를 보존한다. `C_b`는 브랜드 `b` 원본의 정답률, 우연 확률
`q`는 `1/9`다.

원본 천장은 run과 분리한다. 평가자 `j`, 원본 자극 `s`의 정답을 `c_{b,s,j}∈{0,1}`라 할 때
`C_b = (1/(4×2)) Σ_s Σ_j c_{b,s,j}` (2026-09-01: 평가자 2인)다. `C_b`는 브랜드당 한 번만 계산해 봉인하는 보정
상수이며 4회 반복 관측치로 복사하거나 bootstrap의 반복 표본으로 취급하지 않는다.

생성물도 같은 방식의 9지선다로 채점한다. arm `a`의 개별 run `r`에 대해 평가자 `j`의
정답을 `x_{b,a,r,j}∈{0,1}`라 하고, run별 식별률을
`g_{b,a,r} = (1/2) Σ_j x_{b,a,r,j}` (2026-09-01: 평가자 2인)로 둔다. run별 식별력 점수는
`I_{b,a,r} = 100 × min(1, max(0, (g_{b,a,r} - q) / (C_b - q)))`다. 모델 식별력 점수는
네 `I_{b,a,r}`의 평균이며 `G_b` 같은 브랜드 단위 값을 네 run에 복제하지 않는다.

단, `C_b <= q + 0.10`이면 원본조차 신뢰성 있게 구분되지 않는 브랜드이므로 그 브랜드의
네 run 모두 식별력 축은 `N/A-ceiling`이다. 원본 천장이 낮다는 이유로 생성물에 원본보다
높은 식별력을 요구하지 않으며, 100점을 넘겨 보상하지 않는다. 총점·축 macro-average와
PASS 입력의 정확한 처리는 §4.5를 따른다.

### 4.4 디자인 시스템 문서의 **내용** 품질

`spec/design-md-core-v2.md`의 고정 SHA-256
`f8cd0ddfb1696a59c431ee1d459964ba925ead29275f9a448444caff9c93a1a4`는 용어 해석 참고본일
뿐 형식 체크리스트가 아니며 채점·전사 패킷에는 첨부하지 않는다. 아래 다섯 항목을 각각
0–4로 평정해 가중합 후 25를 곱한다.

| 내용 항목 | 축 내부 가중치 |
|---|---:|
| 스냅샷 또는 pack이 밝힌 방법에서 읽히는 입력이 화면 결정으로 이어지는가 | 25% |
| 색·타입·공간·형태 선택의 일관성과 실제 구현 대응 | 25% |
| 상호작용 상태·반응형·접근성 결정의 충분성 | 20% |
| 가정·추론·한계·희생을 구현자가 구분하고 그 영향을 설명하는가 | 15% |
| 다른 구현자가 화면을 재현·변경할 수 있는 운영 가능성 | 15% |

공통 앵커는 `0=해당 항목에 사용할 내용 없음 또는 구현과 정면 모순`, `1=단편`,
`2=핵심 일부`, `3=대부분 구체적`, `4=구체적이고 구현과 모순 없음`이다. 항목 1은
스냅샷 관찰뿐 아니라 pack이 문서에서 밝힌 자기 방법·입력에서 결정으로 이어지는 연결도
동일하게 인정한다. 항목 4는 추론이라고 명시했다는 이유로 0점을 주지 않고, 가정·추론의
범위와 구현 영향이 얼마나 유용하게 설명됐는지를 본다. **값이나 설명을 생략한 사실
자체에는 점수를 주지 않는다.** 기본값을 사용한 완전한 시스템 문서는 그 선택의 일관성·
구현 대응·운영 가능성에 따라 항목 2·3·5와 해당되는 1·4에서 점수를 받을 수 있고, 빈
문서는 각 항목에 사용할 내용이 없어 0점이다. Core v2 준수, frontmatter, 절 번호,
`evidence.*`, decision ID, 파일명, omd book 연결은 점수에 들어가지 않는다. 구현은
완성했지만 문서를 안 내면 이 축만 0점이며 run 전체 abandon은 아니다.

### 4.5 `N/A-ceiling`·`N/A-evidence` 재정규화와 macro-average

레인 `l`의 원래 축 가중치를 `w_{l,k}`, run 축 점수를 `S_{b,a,r,k}`, 해당 브랜드에서
사용 가능한 축 집합을 `A_b`라 한다. 보통 `A_b`는 네 축 전부이고, `N/A-ceiling` 브랜드는
식별력만 제외한 세 축이다.

naver의 근거 추종 축은 `N/A-evidence`다(2026-09-02 판정, `docs/reviews/t3-naver-evidence-axis-2026-09-02.md`).
잠금표와 C-NAVER-H1이 두 첫 캡처의 `H1` 없음을 봉인했고, eligible 수치 필드가 2개 미만이면 그
스냅샷은 비교 입력 불충분이다. 교체할 다른 naver 스냅샷은 없다. 이 브랜드의 `A_b`는 근거
추종을 제외한 축이며, abandon이 아닌 run의 총점은 아래 `T` 식을 그대로 쓴다. 근거 추종의
`B_k`에서 naver를 빼고, `|B_k|=0`이 아니면 나머지 브랜드의 `M_{a,근거}`로 `>=60`을 판정한다.
§4.2·§7의 실행 전 block 교체는 다른 적격 스냅샷이 있을 때의 규칙이다. arm이 대표 이미지를 안
낸 경우(§7 부분 산출물 결측 → 근거 추종·식별력 0점)는 이 면제에 넣지 않는다.

abandon이 아닌 run의 재정규화 총점은 다음과 같다.

`T_{l,b,a,r} = [Σ_{k∈A_b} w_{l,k} S_{b,a,r,k}] / [Σ_{k∈A_b} w_{l,k}]`

abandon run은 §7에 따라 `T=0`이며 재정규화로 복구하지 않는다. 브랜드 총점과 레인 총점은
각각 `Tbar_{l,b,a}=(1/4)Σ_r T_{l,b,a,r}`,
`Tbar_{l,a}=(1/9)Σ_b Tbar_{l,b,a}`다.

축 `k`의 PASS 입력은 먼저 브랜드 평균
`Sbar_{b,a,k}=(1/4)Σ_r S_{b,a,r,k}`를 만들고, 그 축이 가능한 브랜드 집합
`B_k={b | k∈A_b}`만 분모로 쓰는
`M_{a,k}=[Σ_{b∈B_k} Sbar_{b,a,k}]/|B_k|`다. 따라서 일부 브랜드가 식별력
`N/A-ceiling`이면 식별력의 `>=60` 판정에는 나머지 브랜드의 `M_{a,식별력}`을 넣는다.
`|B_k|=0`일 때만 그 축의 60점 조건을 면제하고 `N/A`로 보고한다. 식별력 `N/A-ceiling`과 근거 `N/A-evidence`에 들지 않은 축의 분모는
9개 브랜드이며, 결측 산출물·abandon의 0점은 가능한 축의 분모에서 빠지지 않는다.

## 5. Grok Imagine 4변형 선택 규칙

레인 A에서 프롬프트 한 번이 내는 4변형은 생성 API/UI가 표시한 순서를 `v1..v4`로 저장한다.
사후 best-of-4 선택을 금지하고, **반복 1은 v1, 반복 2는 v2, 반복 3은 v3, 반복 4는 v4**를
대표 이미지로 채점한다. 네 장 모두 원본과 hash를 보존하지만 나머지 세 장은 공통 점수에
넣지 않는다. 품질 수정으로 두 번째 batch를 만들었다면 두 번째 batch의 같은 위치를
채점하고 첫 batch도 폐기하지 않는다. 변형 순서가 확인되지 않으면 그 batch는 도구 결측으로
세 arm 모두 다시 실행한다.

레인 B에서는 각 pack이 자기 워크플로로 최종 선언한 대표 이미지 한 장을 채점한다.
대표 선언 시각과 hash는 블라인드 공개 전에 고정하며, 평가자가 보고 고를 수 없다.

## 6. 질문, 턴·시간·재시도 예산

### 레인 A

- run당 arm별 assistant completion은 **최대 6턴**이다. brief 전달은 세지 않고,
  clarification 요청·구현 보고·자기검수·수정·최종 보고는 각각 1턴이다.
- 경과 시간은 brief 전달부터 최종 hash 고정까지 **45분**이다. 생성 서비스 queue 시간도
  포함한다. 세 arm 모두에 영향을 준 공급자 장애만 block 전체 중단 사유다.
- Grok Imagine은 **초기 batch 1회 + 품질 수정 batch 1회**까지 허용한다. 품질 수정은
  실패 retry가 아니라 예산 내 revision이며 수정 이유를 기록한다.
- HTTP/전송/다운로드 실패는 동일 payload로 **1회만** retry한다. prompt나 seed를 바꾸면
  전송 retry가 아니라 품질 수정 batch를 소비한다. 그 뒤 실패하면 abandon이다.
- 코드·문서 작업도 첫 구현 뒤 **수정 1회**만 허용한다. 평가자 피드백은 받지 않는다.

### hallmark 질문 처리

질문은 **허용한다.** hallmark의 기본 design-context gate를 제거하지 않는다. 모든 arm이
질문할 수 있지만 최초 clarification 한 batch만 허용하며 위 6턴에 포함한다. 답은 항상
다음 고정문이다.

> 추가 선호 정보는 제공하지 않는다. 잠긴 브리프와 스냅샷에서 확인되는 사실만 사용하고,
> 확인되지 않은 값의 처리를 포함한 나머지 선택은 해당 pack의 기본 방법론으로 결정하라.

침묵을 “다른 브리프”나 결측으로 보지 않는다. 침묵한 arm도 동일한 잠긴 브리프를 이미
받았고 clarification 기회를 쓰지 않은 것이다. 질문한 arm에도 새 브랜드 사실·취향·해석은
주지 않으므로 입력 정보량은 늘지 않는다. 두 번째 질문은 같은 고정문으로 답하되 turn을
소비하고, 예산이 끝나면 진행 실패로 처리한다.

### 레인 B

네이티브 경로를 훼손하지 않도록 tool·생성기·내부 단계 수는 pack 기본값을 허용한다.
다만 run당 60분, clarification 한 batch, 사람 피드백 0회, 전송 실패 동일 payload retry
1회라는 외부 예산은 공통이다. 품질을 이유로 한 재생성·수정 횟수는 pack이 스스로 종료한
최종 결과까지 허용하되 모든 중간 결과와 시간을 기록한다.

## 7. 동률·결측·abandon

### 결측

- **입력 결측**: snapshot SHA 불일치, eligible 수치 필드 2개 미만, 잘못된 URL/표면은
  arm을 실행하지 않는다. 세 arm block 전체를 새 repetition ID로 교체한다.
- **평가자 결측**: 결원은 사전 등록 예비 평가자가 해당 배치 전체를 다시 채운다. 끝내
  2종을 확보하지 못하면 해당 레인은 판정하지 않는다(2026-09-01 개정; 원문 3종).
- **부분 산출물 결측**: 실행 화면은 있으나 디자인 문서만 없으면 문서 축 0점이다.
  대표 이미지가 없으면 근거 추종·식별력은 0점이고 첫 렌더 결함은 실제 화면으로 센다.
- **측정 결측**: evidence에서 원래 absent인 최소 필드는 제외한다. arm 산출물 오류로
  eligible 필드를 측정 못 하면 해당 필드 0점이다. 공통 verify 도구 오류는 block 보류다.

### abandon

시간·턴·retry 예산 안에 지정 route의 첫 렌더를 만들지 못하거나 arm이 진행을 거절하면
`abandon`이다. abandon은 삭제하지 않고 해당 run 총점 **0점**, 완료율 분모에 포함한다.
정책상 정직한 거절이라는 설명은 별도 기록하되 점수를 복구하지 않는다. 공급자 전체 장애,
입력 오류, 평가 인프라 오류처럼 arm에 귀속되지 않는 실패만 세 arm block을 무효화하고
blind 해제 전에 재실행한다.

### 동률

arm 간 차이는 브랜드를 1차 군집, 그 안의 4회 **run 점수**를 2차 군집으로 한 paired
bootstrap 10,000회로 95% CI를 구한다. 식별력에서 재표집되는 값은 run별
`g_{b,a,r}`에서 계산한 `I_{b,a,r}`이며, 브랜드 보정 상수 `C_b`는 해당 브랜드 표본에
붙은 채 한 번만 적용되고 네 개의 반복 관측치로 복제되지 않는다. top arm이 아래 통과
조건을 만족하면서 runner-up보다
**5.0점 이상** 높고 차이의 95% CI 하한이 `> 0`일 때만 해당 레인의 단독 우승이다.
5.0점 미만이거나 CI가 0을 포함하면 `NO DECISIVE WINNER`다. 원점수가 같으면 공동순위로
기록하되 임의 tie-break를 하지 않는다.

## 8. 통과 임계값

arm이 한 레인에서 `PASS`하려면 다음을 모두 만족해야 한다.

1. 레인 가중 총점 `>= 75.0/100`.
2. §4.5의 축 macro-average `M_{a,k}` 각각 `>= 60.0/100`. 식별력 천장 때문에
   `|B_k|=0`인 축만 면제한다.
3. 36 run 중 abandon이 3개 이하, 즉 완료율 `>= 91.7%`, 그리고 어떤 브랜드도 4회
   모두 abandon하지 않는다.
4. 첫 렌더 `P0`가 36 run 중 1개 이하(`<= 2.8%`)다.
5. §3의 평가자 일치도 최소 기준을 모두 통과한다.

통과한 arm이 없어도 가장 높은 arm을 승자로 승격하지 않는다. 단독 우승은 `PASS`와
§7의 5점·bootstrap 조건을 모두 만족해야 한다. 레인 A와 B가 서로 다른 arm을 가리키면
그대로 두 개의 결론을 보고한다.

평가자와 겹친다.

### 2026-08-23 — 호스트 확정 후 자기선호 식별 가능성 재판정

arm 공유 호스트를 `grok-4.6`(`xai`)으로 확정한 뒤, 자기선호 진단을 살리려던 두 번의
정련이 모두 막혔다. 결과를 우회 설계가 아니라 **식별 불가 선언**으로 적는다.

| 시도 | 왜 막혔나 |
|---|---|
| 회피 규칙 (최초) | 평가자 3종에서 회피 1건 = 남은 2 = 항목 무효. 실험 성립 불가 |
| (호스트 ∪ 이미지) 불리언 조인 | 호스트가 `xai`라 세 arm 모두 `xai ∈ S_a` → `|자기 계열| = 3` → 전 항목 N/A |
| 상수 성분 제외 | 레인 B에서 달라지는 유일한 성분이 네이티브 이미지고, 그 대비가 **레인 B 이미지 처치와 공선** |

측정 가능한 칸은 `grok × 레인 B × 시각 축` 하나였고 그 칸이 공선이다. 나머지는
`|자기 계열| ∈ {0, 3}`으로 N/A다.

**채택한 처리**: `SELF_PREFERENCE` 플래그를 폐지한다. `bias_j` 값은 부록에 기술 통계로
남기되 "처치와 공선 — 편향 추정치가 아님" 라벨을 강제하고, 리포트 본문은
"이 설계에서 자기선호는 식별되지 않는다"만 쓴다.

호스트를 평가자 계열 밖으로 옮기는 대안은 채택하지 않았다. 레인 A는 이미지가 여전히
세 arm 공통 Grok Imagine이라 살아나지 않고, 교란이 다른 것으로 바뀔 뿐이다.
대신 조건부성(모든 추정량이 `grok-4.6` 조건부, omd가 이 MUT에 맞춰진 팩)을
리포트 첫 절에 적는다.
