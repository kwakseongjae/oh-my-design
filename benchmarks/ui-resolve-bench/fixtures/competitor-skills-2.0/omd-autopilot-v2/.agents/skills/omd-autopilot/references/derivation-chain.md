# Philosophy derivation chain (patch 10)

디테일의 부재는 철학의 부재다. 모든 미시 결정(모서리·상태·정렬·밀도·모션)은
선언된 철학에서 유도되어야 하며, 그 유도가 DESIGN.md에 남아 "왜 이 값인가"에
답해야 한다. 실존 시스템들이 실제로 이렇게 일한다(연구 검증):

- 토스: "One thing per one page" 원칙 → 화면당 1 메시지 + 하단 고정 CTA 1개,
  질문 3–4개/5초 비용 휴리스틱, 선택지 1개 추천. OKLCH 인지 균일 스케일로
  "리스트가 얼룩덜룩해지는" 문제를 토큰 레벨에서 제거.
- 토스 라이팅: Clear/Concise/Casual/Respect/Emotional → "잡초(weed) 제거"를
  문장→화면→화면 간 3층으로 스케일. 소리 내어 읽어 어색하면 탈락.
- 당근 SEED, 오늘의집, 무신사 MDS, 배민: 각자 철학 문장이 토큰·컴포넌트
  규칙으로 내려간다 (연구 리포트 R1 참조).

## 작업 순서 (기존 "시스템 초안 작성"을 이 사슬로 대체)

1. **PHILOSOPHY** — 브리프·도메인·데이터에서 한 문장 입장(stance)과 원칙
   2–3개를 선언한다. 각 원칙은 반드시 **"무엇을 얻기 위해 무엇을 희생하는가"**
   를 포함한다. "clean and modern"은 철학이 아니다 — 반박 가능해야 철학이다.
2. **DERIVE** — 원칙마다 결정 표를 쓴다. 결정 카테고리(전부 다룰 것):
   모서리·표면 장르 / 그림자·엘리베이션 / 색 밀도·악센트 예산 / 타이포 위계 /
   모션 커브·시간 / 정보 밀도 / 레이아웃 문법 후보 / 카피 보이스·톤.
   각 결정은 `D-<원칙>-<번호>` ID를 갖고 근거 한 줄을 단다.
   **근거 없는 결정은 쓸 수 없다** (게이트 GS7).
3. **TOKENS** — 결정 표를 토큰 값으로 옮기고 주석으로 역참조한다:
   `--radius-card: 12px; /* D-P2-1 */`
4. **COMPONENT SPECS** — 코드 전에 컴포넌트 명세를 문서로 쓴다. **0에서
   시작하지 않는다**: 먼저 `references/presets/INDEX.md`에서 장르가 맞는
   프리셋을 선택하고, 해부·상태·접근성 계약은 유지한 채 토큰 슬롯만 결정
   표(D-ID)로 파생한다. 사용 프리셋 ID를 명세에 기록하고, 부합 프리셋이
   없을 때만 "no-preset: <이유>"를 남기고 유도한다(게이트 GS8).
   상태 매트릭스, 기하(높이/패딩/히트 타깃), 광학 정렬은 프리셋 여부와
   무관하게 문서화한다. `references/component-craft.md`의 45규범이
   최저선이다.
5. **LAYOUT GRAMMAR** — 페이지마다 문법(격자/벤토/캐러셀/마스터-디테일/
   매거진/스크롤 내러티브)을 선언하고, **콘텐츠 수를 역산**한다: 문법이
   요구하는 최소 콘텐츠(캐러셀 4+, 벤토 5+, 매거진 이미지 4+)가 데이터에
   없으면 화면을 비워두지 말고 데이터·에셋 보강을 먼저 요청/수행한다.
   초광폭 전략(중앙 max/좌측 max/컬럼 추가) 중 하나를 명시한다.
6. **BUILD** — 페이지는 3·4·5를 소비만 한다. 새 값이 필요하면 2로 돌아가
   결정을 추가한 뒤 쓴다.
7. **RENDER CRITIQUE** — 실화면 기준 비평(slop-gates 전수) + 렌더-피드백
   패스(§7).
8. **DESIGN.md** — 1·2의 철학과 결정 표가 Core v2 experience/provenance에
   실려, 디자이너·프론트엔드가 읽고 "왜"에 답을 찾는 문서가 된다.

## 자주 틀리는 것

- 철학을 선언만 하고 유도하지 않는 것 — 원칙이 어떤 토큰도 바꾸지 않았다면
  장식 문장이다. 삭제하거나 유도하라.
- 결정 표를 건너뛰고 토큰부터 쓰는 것 — 그 토큰 값은 즉흥이고, 즉흥은
  "대충 AI가 만든" 화면의 근원이다.
- 콘텐츠 부족을 레이아웃 축소로 때우는 것 — 부족하면 채우는 게 먼저다.
