From scratch, build the order console for Terra & Tide, a fictional specialty-grocery wholesaler, as a four-page product in HTML/CSS/JS (no build step, no external network): index.html (overview), orders.html (order table), order-detail.html (single order), products.html (catalog). Establish a project-owned design system FIRST — one shared stylesheet, identical navigation with the current page marked, identical heading/body/primary-action styling everywhere.

The provided dataset at ./data/data.js (window.TERRA_TIDE_DATA, mirrored in data.json) is the single source of truth. Never copy its records into the markup by hand: every number and row on screen must be computed from it at runtime. Overview shows real aggregates (order counts by status, open cases, low-stock products) with a short operational readout. Orders is a real working table: filter by status, sort by date placed, and open any row's detail. Order-detail renders one actual order — its lines joined to product names, its customer, its status and note — and handles an unknown order id with an honest error state. Products renders the catalog with the provided images (explicit dimensions) and visible stock states.

This is an internal operations tool: information density matters, status must be readable at a glance through system tokens, and every state (loading, empty filter result, unknown id) arises from real interaction with real data. Aim for a current, confident product aesthetic with restrained micro-transitions behind prefers-reduced-motion. Label the workspace as sample data where an operator would need to know; revenue figures and carrier names are not part of this dataset — do not invent them.
