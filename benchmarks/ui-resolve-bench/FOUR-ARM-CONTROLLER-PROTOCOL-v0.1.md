# Four-arm controller protocol v0.1 — provider-zero lifecycle

This unit exercises lifecycle and isolation contracts with local fake runtimes only. It makes zero provider, browser, media, auth, or network calls. `mode` must be `provider-zero-fixture`, every arm must declare `runtimeKind: local-fake`, and any live mode fails before a process launches.

## Frozen group manifest

A group binds one epoch file and one task file by portable ID, canonical absolute path, and SHA-256. It contains exactly these arms: `no-skill`, `uiux-pro-max`, `hallmark`, and `omd`. Each arm binds a pairwise-disjoint canonical workspace and distinct session ID plus profile, executable, and input files by canonical absolute path and SHA-256. Equal, parent, and nested workspace relationships are rejected. `armSha256` covers the complete arm entry except the hash field itself, including arguments and the exact expected skill surface.

The controller checks every file before launch and again after every child has exited. A missing file, symlink, noncanonical path, changed byte, duplicate workspace, duplicate session, incomplete arm set, or arm-object drift rejects the group. OMD-prefixed skills are forbidden from every non-OMD arm. Subagents and ambient fallback must both be disabled.

## Init and terminal events

Each child writes newline-delimited JSON objects to stdout. JSON primitives such as `null`, arrays, malformed JSON, and unknown event objects fail closed without escaping the controller event handler. Its first accepted event must be exactly one `system/init` event binding the epoch, task, arm, profile, executable, input, session, model, tools, skills, MCP surface, subagent state, and ambient-fallback state. Set-valued surfaces may arrive in any order but may not contain duplicates. A missing, duplicate, late, or drifting init fails the group. Known allowlist-fallback warnings on stderr also fail the group.

A successful child emits exactly one `result` event after init. The result binds its session and an output relative to that arm's workspace with SHA-256. The controller rejects path escapes, symlinks, non-files, and hash mismatch, then revalidates the accepted output after the child process closes. A file changed after the result event cannot enter a completed group with its stale hash.

The provider executable runs below a controller-owned wrapper. The wrapper removes its private recovery configuration before launching the provider process and writes a nonce-bound heartbeat outside the arm workspace. This gives a replacement controller one half of the identity proof for a still-running process-group leader, without exposing the nonce or heartbeat path to the wrapped runtime. Recovery also requires a current OS identity inspection whose PID and process-group ID both equal the recorded wrapper leader. If that inspection is unavailable, the group is quarantined.

## Four-child barrier and evidence

The controller records canonical launch order and starts all four local children before awaiting completion. While a group is active, another group is rejected. Each wrapper is a distinct POSIX process-group leader. Any child failure or caller cancellation signals every remaining group, escalates from `SIGTERM` to `SIGKILL` after the configured grace period even when the direct wrapper already exited, and waits for the direct close events and escalation timers before writing `GROUP.json`. This prevents an ignoring descendant from surviving behind a cooperative direct child. The terminal journal append is attempted before the authoritative group and active-state reports are materialized; if that append fails, both reports record failure and the controller throws instead of returning completion. The provider-zero tests prove the four-child barrier, a synchronous launch failure after an earlier child starts, a real ignoring grandchild, injected event-journal failures inside both a stdout callback and the terminal transition, and an injected stdout-log failure.

`ACTIVE-GROUP.json` is an atomic restart snapshot. It binds the controller PID to the exact OS process identity observed at group start and to a separate nonce heartbeat. Recovery refuses an advancing controller heartbeat. A stale heartbeat is insufficient evidence of controller death: if the PID still exists and the current identity matches the recorded identity, recovery refuses; if either recorded or current identity is unavailable while that PID exists, recovery also refuses. A different complete identity for the reused PID permits attempt inspection to continue. Before another group starts in the same controller root, the previous state must be terminal or recovered. After an abrupt controller exit, `recover --root <root>` validates that the group root is canonical and below the controller root, each process-group ID equals its recorded wrapper PID, and each regular non-symlink heartbeat has the exact path derived from its owned attempt directory. It then probes two advancing wrapper heartbeat samples and requires a matching current OS process identity before signaling. An already-dead leader is only clear when its recorded process group is also gone. A leaderless surviving group, live PID with stale/missing heartbeat, unavailable OS identity, mismatching group, or escaped heartbeat path is quarantined or rejected without a signal. Every recovery writes a new immutable receipt under `recoveries/`; it never silently adopts an ambiguous process or reruns an arm.

Every launch has an immutable attempt directory with raw stdout/stderr and `ATTEMPT.json`, including rejected and controller-cancelled attempts. Group manifests, events, attempt logs, and reports are never overwritten. This unit has no retry policy.

`queueBlockedMs` from a child result is preserved only as `rawBrokerQueueResidenceMs`. The controller records `verifiedBlockedQueueUnionMs: 0`, `queueExclusionAdmitted: false`, and `activeBudgetCreditMs: 0`. Only a later process-state evidence unit may admit suspended queue intervals.

## Closed boundaries

This unit does not implement browser handoff, provider admission, OS read/write isolation, worker suspension proof, arbitrary filesystem-write recovery, or a transactionally replayable event journal. Event and stdout/stderr append failures now invalidate the group and trigger cleanup, but the JSONL event stream, raw logs, and active snapshot are separate files; the report preserves `journalFailures` rather than claiming cross-file atomicity. Heartbeat plus OS-identity recovery covers controller death while wrappers remain provable and quarantines ambiguous identities or surviving orphan groups. It is not evidence that an admitted provider cannot access another workspace; that requires the separate OS isolation admission.
