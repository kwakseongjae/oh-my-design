# Visual Equity Preservation — 1.9.78 Preregistration

## Trigger

The locked 1.9.77 owner blind diagnostic compared six candidates that all
passed the same 85/85 deterministic ceiling. Raw DESIGN.md was the primary
choice on 3/3 Functionality, 3/3 Usability, 2/3 Fidelity, and 3/3 Ship
Preference votes. Onboarding and locale were reversal-consistent; incident was
not. Screenshot review found a bounded missing contract: OmD can preserve
behavior and tokens while weakening an existing decision cue, reassurance
callout, active-state signal, or task-oriented section boundary.

## Frozen hypothesis

Adding one compact **visual equity ledger** before editing and one
**visual-equity closure** after editing should prevent unsupported flattening
of task-helpful existing visual decisions without freezing bad UI or relaxing
the accepted behavior, evidence, contrast, geometry, focus, or delivery
contracts.

## Allowed source delta

- `skills/omd-apply/SKILL.md`
- focused contract/distribution tests that prove the new prose is shipped
- this report's accepted findings and summary after provider-free validation

No task, starter, evaluator, score, provider, model, timeout, retry, or fallback
change is part of 1.9.78.

## Required contract

Before the first product edit, the agent records at most five existing,
task-helpful visual decisions. Each entry uses:

- `identity`
- `user_value`
- `before_evidence`
- `decision(preserve|reinforce|replace)`
- `change_authority`

Eligible visual equity includes decision hierarchy, risk/reversibility cues,
active or selected-state distinction, primary-action prominence, and spatial
boundaries that separate different user decisions. Decoration with no task
value is not protected merely because it already exists.

Replacing or weakening an entry requires at least one of:

1. the original user task,
2. an explicit DESIGN.md rule, or
3. a measured defect on the same consumer route.

“Cleaner,” “more consistent,” “more minimal,” component consolidation, generic
best practice, specialist preference, and model taste are not change authority.

After the last product edit, visual-equity closure compares the same route and
state before/after at desktop and mobile. Every changed high-salience entry
must map to its authority. Unsupported hierarchy loss, unsupported
state-signal weakening, unsupported reassurance removal, and unsupported
decision-boundary collapse must all be zero before acceptance.

The contract must explain why:

- component consolidation is not automatically simplification;
- restraint is not permission to neutralize a safe token-backed state signal;
- preserving visual equity is not preserving every old style;
- no new token or fallback value may be invented to satisfy the closure.
