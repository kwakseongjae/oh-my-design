# Hypothesis — runtime artifact closure on a spatial load plan

## Frozen question

With the model, effort, task, prompt, starter, runtime, timeout, pacing, and runtime artifact proof policy held fixed, does the exact 1.9.309 artifact-aware skill improve full carrier closure over the exact 1.9.274 conjunctive-release skill?

## Mechanism under test

Both arms receive the same fail-close runtime policy. The candidate skill explains how to materialize a locked `.omd/reflow-closure.json` before product editing and close every registered carrier and atomic row at 390px, 320px, and 200% before static proof. The control skill has only the earlier conjunctive proof contract and therefore lacks the artifact protocol needed to satisfy the shared gate.

The expected benefit is not a higher prose compliance rate. It is fewer unresolved spatial carrier and atomic-line failures while preserving the supplied bay/container/station relationships and decision hierarchy.

## Promotion boundary

Failure to create the artifact, changed inventory after editing, or incomplete manifest must fail closed rather than count as successful proof.
