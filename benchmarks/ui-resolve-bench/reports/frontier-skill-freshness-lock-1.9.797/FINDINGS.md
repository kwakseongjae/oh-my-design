# 1.9.797 frontier skill freshness lock

## Outcome

The next skill comparison now uses current official snapshots instead of
silently treating July-era arms as current products. All three included vendor
trees were checked out at detached clean commits, hashed at the exact installed
source boundary, and prepared through the benchmark sandbox without running a
third-party installer or enabling hooks.

## The important correction

Impeccable 4.0.4 is no longer fairly described by the historical
`impeccable-prompt-only` arm. Its current skill includes a local context helper,
task-specific references, a craft floor, bounded inspection, hooks, and live
iteration. The current-epoch arm therefore installs the entire 152-file skill
tree and permits its local context and playbooks. It disables hooks, live mode,
network access, and self-launched browser work because the same external
browser-harness controller must own proof for every arm.

Historical arms and reports remain immutable. The new variants have distinct
IDs, commits, and source-tree hashes, so old and new epochs cannot be aggregated
accidentally.

## Fair denominator

The fresh repair comparison includes current OmD, Anthropic Frontend Design,
Impeccable 4.0.4, and UI UX Pro Max 2.13.0. Taste Skill v2 is excluded from this
repair denominator because its declared scope does not cover the product UI
class being tested. Vercel Web Design Guidelines remains eligible only as a
review/second-pass rail, not as a same-stage implementation arm.

The first stage is deliberately a qualification run: four arms, three unseen
tasks, one fixed Luna/high trial, identical project bytes, identical task
contract, and the same externally controlled browser proof. Twelve cells can
reject a weak or unsafe arm; they cannot establish public statistical
superiority. Reliability@3 expansion happens only after Stage A, while public
Verified still requires the larger hidden-task, repeat, practitioner, and
multi-model evidence already defined by the readiness rubric.
