# Candidate-preflight-bound Reliability@3 — 1.9.725

This provider-zero experiment transfers the 1.9.723 candidate-preflight lifecycle to three fresh, cascade-effective tasks locked in 1.9.724. It is not a replay or replacement of the frozen 1.9.722 cells.

The fixed order is benthic sample transfer, conservation frame loan, then wind-tunnel model handoff. Each cell uses Codex with `gpt-5.6-luna`, high effort, a 720-second timeout, one product revision, no retry, and no replacement. The exact task trees and the clean 1.9.723 OmD skill are hash-locked before provider exposure.

Before the product edit, the model must obtain the provider-sealed source packet and validate complete candidate bytes with the same static evaluator until the candidate is green. A passed receipt must bind the candidate hash, source-contract hash, and sealed-inventory hash. The product may then be edited once with those exact bytes. Static closure must refuse to consume the closure if the final product hash differs from the latest passed receipt.

A cell passes only at 85/85 with resolved UI, one product revision, one successful and zero failed static closures, zero user handoffs, proof compliance, unchanged sealed inventory, a passed candidate-preview receipt, and exact candidate-to-final byte equality. Reliability@3 passes only at 3/3.

Inventory drift, a second product edit, a failed static closure, proof noncompliance, a missing or failed preview receipt, or a candidate/final byte mismatch freezes every unexecuted cell. An objective miss may continue to the next task only when the full lifecycle contract remains clean.

The experiment is diagnostic only. It does not enter public ranking, establish provider superiority, or promote a 2.0 release gate by itself. Provider execution is forbidden until the plan is committed, the fresh root is prepared provider-zero, and the admission audit is committed.
