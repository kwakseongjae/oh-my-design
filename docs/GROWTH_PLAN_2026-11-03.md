# 확산 계획 — 실측 데이터를 콘텐츠로 (2026-11-03)

`docs/GROWTH_PLAN_2026-10-13.md`의 P4(레퍼럴 엔진)를 구체화한다. 정체성(아카이브 + 프론트 스킬), CJK 축, D7(게시 주체는 오너 개인 계정, 초안은 Claude)은 그대로다.
수치는 공개 레포 원칙에 따라 여기 적지 않는다. 근거는 GA4 28일(11/3 조회)·GitHub·npm이고, 순위와 판단만 남긴다.

## 1. 진단

- **실사용자는 한국이다.** 참여한 사용자 대부분이 KR이다. 싱가포르 유입은 참여율이 1% 안팎이라 봇으로 본다. JP·TW·HK는 각각 수십 명 수준으로, 레퍼런스(JP·TW 각 60곳 이상)에 비해 유입이 사실상 없다. **카탈로그는 CJK인데 청중은 아직 KR뿐이다.**
- **통하는 채널.** 검색(구글 > 네이버) 다음으로 큰 레퍼러가 **Threads**다(오너 게시). 그다음 Wikidocs 책, 네이버 블로그(남이 쓴 글), padlet·Teams(수업·회사 안에서 공유), ChatGPT(AI가 추천).
- **안 통하는 것.** Threads 밖의 소셜, 영상, GitHub 레퍼러는 미미하다. 별·npm은 완만하다.
- **릴리스 효과는 하루짜리다.** 11/2(2.0.6·/hangul) 사용자가 평소의 두 배였지만 유지되지 않는다. 지속 유입은 검색·AI 인용·반복 게시에서 온다.

## 2. 논지 — "유명 제품의 실측"

일반적인 "AI 디자인 도구" 글은 퍼지지 않는다. OmD만 가진 것은 **유명 제품 UI의 실측값**이다. 349곳(11/3 운영 기준)은 hover·pressed·focus가 근거와 함께 재져 있다. "토스 버튼을 누르면 정확히 무슨 일이 일어나는가"는 디자이너·개발자가 공유하는 종류의 글이고, 소개된 회사의 디자인팀이 직접 퍼 가는 글이다.

## 3. SNS냐 블로그냐 — 둘 다, 위계를 둔다

- **원본 = 사이트의 데이터 페이지(블로그 글).** 검색·AI 인용·Wikidocs처럼 쌓이는 유입은 여기서 나온다. 2주에 1편.
- **유통 = SNS 컷.** 원본 1편에서 Threads 3~5개를 자른다. Threads는 이미 검증됐으니 **주 3회 고정 리듬**으로 시작한다(초안 Claude, 게시 오너).
- **영상·모션 = 컷 중 천장이 가장 높은 형식.** 단, 손으로 만드는 일회성이 아니라 데이터에서 자동으로 나오게 만든다(아래 4-1).

## 4. 콘텐츠 엔진

1. **상태 릴(자동 모션).** 검증 레퍼런스마다 실제 컨트롤의 rest → hover → pressed → focus를 6~10초 세로 영상(9:16)과 캐러셀 스틸로 만든다. 실측값을 화면에 얹는다(예: `#0082ff → #0068d0 · 0.185s`).
   - 재료는 이미 있다: 프로브가 상태별 크롭을 찍는다. 다만 크롭이 상태를 잃는 문제가 있어(11/3 pressed 수정과 같은 원인) 먼저 고친다.
   - 349곳이면 매주 소재가 마르지 않고, 전부 사실이다.
2. **데이터 스토리(격주 플래그십).** 예:
   - "버튼을 누르면 4px 내려가는 브랜드들"(Duolingo 3D 프레스 등).
   - "포커스 링을 직접 디자인한 곳은 몇 곳인가" — 브라우저 기본 링에 맡긴 곳이 많다는 실측. 접근성 논의를 부른다. 망신 주기 톤은 피한다.
   - "한국 앱 primary 색 지도", "CJK 은행 앱의 버튼 모양".
   - 배포처: GeekNews·Disquiet(KR), Zenn·Qiita(JP), Threads(KR·TW).
3. **브랜드 태그 루프.** 레퍼런스가 반영될 때마다 "OmD에 수록됨" 카드와 함께 그 회사 디자인팀 계정을 태그한다. 소개된 쪽이 다시 퍼 간다.
4. **700 마일스톤 런치(일회성 고품질).** "CJK UI 아틀라스": 700곳의 primary·버튼 모양을 한 화면에 모은 인터랙티브 페이지 + 60초 히어로 필름. KR·JP·TW 동시 게시.

## 5. KR 밖으로

- **TW 먼저, JP 다음.** TW는 Threads가 강한 시장이라(출처 확인 필요) KR 플레이북을 zh-TW로 옮기기 쉽다. JP는 X와 Zenn·Qiita·note — 「実測」「検証」 글이 잘 퍼지는 곳이다.
- **제품 쪽 전제: ja·zh-tw 상세 페이지.** 지금 상세 현지화는 ko만 있다. "<brand> デザインシステム", "<品牌> 設計系統" 검색에 걸리려면 `/ja/design-systems/[id]`(JP 레퍼런스)·`/zh-tw/design-systems/[id]`(TW 레퍼런스)를 ko와 같은 방식으로 만든다(본문은 영어 원문, 틀·요약만 현지화).
- **신규 레퍼런스는 계속 CJK 중심**(메모리 `feedback_new_refs_cjk_centric`). JP·TW 비중을 높여 현지 게시물의 소재를 만든다.

## 6. 실행 순서

1. 4차 묶음(CJK 22) 반영 → 2차 CJK 센서스(JP·TW 비중↑) → 700까지 5~8차.
2. 상태 릴 렌더러 + 크롭 상태 수정 → 첫 4주치 Threads 초안.
3. 첫 데이터 스토리 1편(후보: 포커스 링 실측).
4. ja·zh-tw 상세 페이지(UI라 프리뷰 GO).
5. 700 런치 패키지(아틀라스·필름·다국어 게시).
