## 1. 정체성 재정의 — "DESIGN.md 아카이브 + 프론트 스킬"

오너 지시(10/13): builder를 격하하거나 뺀다. OmD는 **DESIGN.md 아카이브와 프론트엔드 스킬을 제공하는 곳**이다.

- **주 메뉴:** Archive(디자인 시스템) / Skills / Docs. builder는 주 메뉴에서 뺀다.
- **항목 페이지:** `/design-systems/[id]`가 아카이브의 항목 페이지다. 근거 요약, DESIGN.md 복사·다운로드·Raw, 설치 명령, 에이전트 프롬프트가 여기에 모인다(IA 브랜치의 `#use`).
- **builder 처리:** 두 가지 중 하나를 고른다(결정 대기, §6 Q1).
  - (a) **완전 제거.** `/builder?ref=X`는 `/design-systems/X#use`로 308 리디렉트한다. 커스터마이즈 기능은 버린다.
  - (b) **격하.** 메뉴와 랜딩에서 빼고 noindex를 건다. 상세 페이지의 작은 "Customize" 링크로만 들어갈 수 있다.
  - 어느 쪽이든 사용자가 에이전트에 붙여 넣은 기존 `/builder?...` 링크는 계속 열려야 한다(리디렉트 또는 유지).
- **Skills 허브:** `/skills`와 스킬별 페이지를 둔다. /hangul이 첫 번째다.

## 2. 단계별 계획

### P0 — 정리와 결정 (이번 주)

1. **랜딩 처리.** 오너가 브라우저에서 검토하지 않은 채 반영됐고, getdesign.md와 닮았다는 지적이 있다. 둘 중 하나로 정리한다.
   - 이전 랜딩으로 되돌린다.
   - P1 브랜딩이 확정될 때까지 유지하되, 운영 반영 전에 프리뷰로 컨펌받는 절차를 고정한다.
2. **IA 브랜치 재작업.** `feat/ia-item-page`는 builder를 "Customize"로 이름만 바꿔 남겨 뒀다. 오너 방향과 맞지 않으므로 §1의 (a) 또는 (b)로 고친 뒤 프리뷰를 보여 주고 반영한다.
3. **계측 기준선.**
   - 주간 스냅샷을 자동화한다(현재는 수동이라 10/1~10/13 사이에 빠졌다).
   - 사이트 레퍼러를 측정할 수단을 하나 고른다. 후보는 GA4 복구, Vercel Web Analytics, 서버측 referrer 카운터다(§6 Q4).
   - 측정 가능한 유입 출처가 없으면 레퍼럴 작업의 효과를 판정할 수 없다.
4. **운영 반영 절차.** 화면이 바뀌는 변경은 **프리뷰 URL을 오너가 직접 확인한 뒤에만** main에 반영한다. 스크린샷만으로는 GO로 보지 않는다.

### P1 — CJK 브랜딩 (2주)

- **컨셉:** "CJK 화면을 제대로 만드는 DESIGN.md 아카이브".
  - 근거: 레퍼런스 521개 중 KR·JP·TW·CN이 339개(65%)이고, 많이 고른 10곳 중 9곳이 한국 서비스다.
  - 경쟁작(getdesign.md, awesome-design-md)은 영어 중심이고 출처를 보증하지 않는다.
  - OmD는 "실측 근거가 붙은 CJK 레퍼런스"와 "CJK 조판 스킬"을 함께 가진 유일한 곳이 된다.
- **산출물:** 이름 표기(OmD / oh-my-design / 오마이디자인 등), 로고, 컬러·타이포 시스템, 톤.
  - 오너가 고를 수 있게 시안 2~3개를 만든다.
  - 확정된 체계를 DESIGN.md에 반영한다(체크포인트).
  - 그 뒤 랜딩·아카이브·상세·docs를 한 체계로 다시 그린다. 지금은 랜딩만 새 디자인이고 나머지는 옛 디자인이다.
- **CJK 서체 규칙:** 사이트 자체가 CJK 조판 규칙의 시범이 돼야 한다.
  - 한국어는 Pretendard를 셀프호스트하고 `keep-all`을 쓴다.
  - 일본어·중국어는 각 언어 서체와 줄바꿈 규칙을 따른다.

### P2 — 언어 확장 (P1 확정 후, 4주)

| 순서 | 로캘 | 범위 | 근거 |
|---|---|---|---|
| 1 | ko | `/ko` 랜딩(있음), `/ko/design-systems/[id]` 상세 202곳 우선, `/ko/skills` | 레퍼런스·수요 1위. 검색 공백이 확인됐다 |
| 2 | ja | `/ja` 랜딩, 일본 레퍼런스 61곳 상세 | 레퍼런스 61곳. Zenn·Qiita 개발자 시장 |
| 3 | zh-tw | `/zh-tw` 랜딩, 대만 레퍼런스 63곳 상세 | 레퍼런스 63곳 |
| 4 | zh-cn | 보류. 레퍼런스가 13곳뿐이라 수요가 확인된 뒤에 한다 | — |

- **번역 방식:** 기계 번역이 아니라 로캘 적응이다(`omd-locale-adapter` → `omd-humanize` 검수). 레퍼런스 본문은 영어 원문을 유지하고, 페이지 틀·요약·검색 문구만 현지화한다.
- **언어 처리:** 로캘마다 `lang`, hreflang 쌍, 로캘 sitemap을 둔다.
- **검색 키워드:**
  - 한국어 "<브랜드> 디자인 시스템"
  - 일본어 "<brand> デザインシステム"
  - 대만 "<品牌> 設計系統"
- **기존 다국어 docs:** ko/ja/zh가 27개 URL인데 읽힘이 거의 없다. 로캘 랜딩·상세가 생긴 뒤 내용을 합치거나 줄인다.

### P3 — CJK 스킬 라인 (P2와 병행)

- **/hangul 출시:** 스킬, npm 패치, 페이지 순서다. 페이지는 P1 체계로 다시 만들고, 영상(Tesseract)도 새 체계에 맞춘다.
- **후속 스킬:** 일본어 조판(JLREQ 기반)과 중국어 조판(CLREQ 기반, 번체 우선).
  - /hangul처럼 "스킬 없이 vs 스킬로" 평가 수치를 만들고, 로캘별로 바이럴 콘텐츠를 낸다.
  - 원전 조사를 먼저 하고, 근거가 없는 규칙은 넣지 않는다.
- **포지션:** "CJK frontend skills" 묶음이 아카이브와 함께 OmD의 두 번째 축이 된다.

## 4. 즉시 실행 순서

1. 오너 결정 Q1~Q5를 받는다.
2. 랜딩 처리(되돌리기 또는 유지)와 IA 브랜치 재작업을 한다. 반영 전에 프리뷰로 컨펌받는다.
3. 계측 수단을 마련하고 주간 스냅샷을 자동화한다.
4. P1 브랜딩 시안 2~3개를 만든다 → 오너 선택 → DESIGN.md 반영.
5. P2 ko 상세부터 시작하고, P3 /hangul은 새 체계로 출시한다.

## 5. 성공 기준 (8주 뒤 측정)

- **검색:** "<브랜드> 디자인 시스템" 계열 KR 검색어에서 OmD 상세가 노출된다(Search Console 노출·클릭).
- **레퍼러:** 사이트 레퍼러 상위 10개 중 커뮤니티·검색 비중이 늘어난다. 기준선은 P0에서 측정한다.
- **다국어 유입:** ja·zh-tw 로캘 페이지 유입이 생긴다(0 → 측정 가능 수준).
- **사용자 수:** MAU가 10.5K에서 늘어난다. 목표치는 기준선을 측정한 뒤 정한다.

## 6. 오너 결정 필요

- **Q1** builder: (a) 완전 제거(리디렉트) 또는 (b) 격하(메뉴 제외·noindex·상세 안 작은 링크).
- **Q2** 10/1 랜딩: 되돌리기 또는 P1까지 유지.
- **Q3** CJK 브랜딩: 이름 표기·로고까지 새로 할지, 현재 이름을 유지하고 시각 체계만 새로 할지.
- **Q4** 사이트 레퍼러 계측 수단: GA4 복구 / Vercel Web Analytics / 서버측 카운터.
- **Q5** 로캘 우선순위: ko → ja → zh-tw 순서에 동의하는지.
