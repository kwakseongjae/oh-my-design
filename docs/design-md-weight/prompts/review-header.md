## 무엇을 보는가 (웨이브 22가 드러낸 실패형)

1. **A계열 값 손실** — 원본 YAML `tokens.*`와 §별 수치가 산출 DESIGN.md에 있는지. 게이트는 같은 숫자가 다른 스케일에 있으면 "보존됨"으로 오판한다(easywallet `tokens.rounded.lg:16`이 spacing의 16 때문에 통과했다). 키 경로별로 대조해라.
2. **원본 고유 사실의 소실** — 연혁·수치·고유명사("20+ years", "MRT gate" 류)가 통째로 빠졌는지.
3. **§ 제약·모션 규칙의 미착지** — 원본이 세운 규칙인데 산출 어디에도 슬롯이 없는 것.
4. **근거 없는 표면 귀속** — 원본이 세우지 않은 표면·플랫폼에 값을 귀속시킨 문장.
5. **충돌 정책 불일치** — 같은 종류의 충돌을 브랜드 안에서 다르게 처리한 자리.
6. **F2 목록 낡음** — F3가 본문을 고친 뒤 migration-log의 F1/F2 목록이 옛 상태를 가리키는지.

## 계수 규칙 (위반 시 검토 무효)
- `grep -c` 금지. `grep -o <패턴> <파일> | wc -l`을 쓰고 파일별로 적어라.
- 셸이 `no matches found`를 뱉으면 **0회가 아니라 미측정**이다. `find`로 파일 존재부터 확인해라.
- 네가 "이 문자열은 없다"고 쓸 때, **그 문장 자신이 분모에 들어간다**(E2d). 자기가 편집한 파일도 다시 grep해라 — 웨이브 22 elevenlabs가 자기보고를 grep 없이 승인해 FAIL했다.

## 출력
브랜드마다: `PASS` 또는 `FAIL <n>` + 각 결함의 (조항 / 원본 위치 / 산출 위치 / 실측). **고치지 마라 — 판정만 해라.**
마지막 줄에 `REVIEW_DONE <brand> <PASS|FAIL n>`.
