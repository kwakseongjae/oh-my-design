# 스크롤 엔진의 정답과 "수렴"이라는 진짜 적 (2026-09-05)

> 계기: 사용자가 준 X 게시물(@nateherk, 2026-09-04)이 프롬프트가 아니라 **스킬**이었다 —
> `github.com/nateherkai/scroll-craft` (MIT). 우리 `omd-aphrodite` 의 직접 경쟁 산출물이다.
> 이 문서의 수치는 **저장소 원본을 직접 받아 확인**했다(`engine/scrollcraft.js`, `references/uniqueness.md`).
> 라이선스 MIT 이지만 **코드를 가져오지 않는다** — 우리는 수치와 원리만 배우고 자작한다(replica-lab §1).

## 1. 두 줄 결론

1. **스크롤 감쇠의 정답 구간이 세 출처에서 같은 값으로 수렴했다.** 우리 실측(higgsfield 0.15 · runway 0.16),
   scroll-craft 엔진 기본값(**0.18**), 우리 r2(70점, 0.25). r4 의 0.53 만 바깥에 있다.
2. **경쟁 스킬도 우리와 똑같이 "한 가지 모양"으로 수렴했고, 그 소유자도 같은 지적을 했다.**
   진짜 적은 효과의 부족이 아니라 **수렴**이다.

## 2. 엔진 — 원본에서 확인한 규격

`engine/scrollcraft.js` 주석과 코드에서 직접 인용:

> *"Scroll only ever writes a TARGET; a standalone rAF loop walks the current time toward it at a fixed
> fraction per frame (`data-sc-lerp`, default **0.18**; **1.0 under reduced motion**, which is no smoothing
> at all). Writes are gated by a **deadband** and skipped while the decoder is still seeking."*

> *"The lerp is a mechanism, not a taste knob. … it is never read as 0: a 0 lerp is a playhead that never moves."*

구현 사실(코드): `lerp(a,b,t) = a + (b-a)*t` · 계수는 `data-sc-lerp` 로 요소별 오버라이드 · `clamp(0.02, 1)` ·
전역 기본 `0.18` · 상시 rAF 루프 하나가 페이지 전체의 단일 스크롤 값을 굴린다.

**우리 r4 와의 대조**: r4 `mountPins()` 은 스크롤 이벤트에서 위치→값을 계산하고 끝난다(측정 `scrubτ = 0`).
목표/현재의 분리가 없고, 상시 루프가 없고, 리듀스드 모션 분기도 "감쇠를 끄는" 형태가 아니다.
`docs/reviews/scroll-stiffness-diagnosis-2026-09-05.md` 가 지목한 결손 3종과 정확히 대응한다.

### 우리가 채택할 값

| 항목 | 값 | 근거 |
|---|---|---|
| 스크롤 위치 보간 계수 α | **0.14 ± 0.04** (0.10~0.18) | 우리 실측 감쇠 계열 0.15·0.16 · scroll-craft 0.18 · r2 0.25 는 약함 |
| 루프 | 상시 rAF **하나**가 전 페이지의 단일 값을 굴린다 | 섹션마다 리스너를 다는 현 구조는 정지 프레임 133 을 만든다 |
| 데드밴드 | 목표와의 차이가 임계 미만이면 쓰기 생략(루프는 유지) | 불필요한 스타일 쓰기 억제. **현재의 0.0015 양자화와는 다르다** — 그건 루프 없이 값을 끊어 계단을 만든다 |
| 리듀스드 모션 | α = **1.0** (보간 없음) | 감쇠를 끄는 것이 접근성 기본값 |
| 지터 목표 | ≤ 1.0 (현 3.08, locomotive 0.54) | 실측 |

### 클립 시간 ≠ 큐 시간
scroll-craft 는 스크럽 대상의 시간을 **핀 이동 구간이 아니라 스테이지의 가시 수명 전체**에 매핑한다.
우리 r4 는 핀 트랙 진행률에 직접 묶여 있어, 정착 이후 홀드 구간에서 **아무 일도 일어나지 않는다**(LC-56 이
"홀드에 읽을 것"을 요구하게 된 배경). r5 는 두 시계를 분리한다 — 진행(스크럽)과 체류(가시 수명).

## 3. 수렴 — 경쟁 스킬이 남긴 자백

`references/uniqueness.md` §1 "The template trap" 원문 요지:
네 개 산업(프로틴 커피 브랜드 · 퍼스널 브랜드 · 조경 설계시공 · 에이전트 관측 제품)으로 만든 네 사이트가
**모두** 고정 상단바 아래 풀블리드 스크럽으로 열고, 히어로 헤드라인을 같은 모서리에 앉히고, 핀 타입 액트에서
줄을 크로스페이드하고, 카드 레일을 같은 틸트 값으로 밀고, 같은 핀 스팬으로 닫고, **전부 13.6~13.8vh** 로 끝났다.
소유자는 "템플릿 같다"고 했고, 저자는 *"He was right, and the evidence is in the files"* 라고 적었다.

**우리 r4 는 14.27vh 다.** 같은 함정에 같은 방식으로 빠졌다는 독립 증거다.
여기에 우리 쪽 진단(`ai-default-signature-2026-09-05.md`: AI 기본값 군집 #2·#5 에 6/6 해당)을 겹치면,
**점수 정체의 원인은 "무엇을 더 넣을까"가 아니라 "왜 매번 같은 것이 나오는가"** 다.

## 4. 그래서 r5 는 무엇을 바꾸는가

1. **엔진**: 상시 rAF 단일 루프 + 목표/현재 분리 + α 0.14 + 데드밴드 + 리듀스드 모션 α=1. 자작 20~30줄.
2. **두 시계 분리**: 스크럽 진행률과 스테이지 가시 수명을 따로 둔다. 홀드가 죽지 않는다.
3. **수렴 방지 게이트(F)**: 런마다 ① 매크로구조를 이름으로 지명 ② 직전 런과 **다른 축**을 선언
   ③ "이번에 절대 안 쓸 것" 5줄(AI 기본값 군집 포함) ④ 길이·핀 수·액트 수를 직전 런과 다르게.
4. **팔레트·크롬 개편**: 니어블랙+애시드 라임과 템플릿 크롬 6종을 버린다(별도 문서 §4).
5. **LC-44(커스텀 커서) 재검토**: scroll-craft 와 Hallmark 양쪽이 "커서 팔로워는 슬롭"으로 금지한다.
   우리 규칙은 "미디어 표면에만·터치 비활성·상태 3개"로 허용 중 — **금지로 뒤집을지 판단이 필요하다.**

## 5. 경쟁 관계에 대한 메모

scroll-craft 는 **엔진을 고정하고 검증기를 붙였다**(`scripts/doctor.mjs`, `references/verify.md`).
우리도 같은 구조다(검사기 LI-1~40, 프로브 4종). 방향은 같고, 차이는 두 가지다.

- 그쪽은 **런타임 엔진 하나**를 배포한다(속성 `data-sc-*` 로 선언). 우리는 매 런 코드를 새로 쓴다 —
  그래서 r3→r4 에서 감쇠를 통째로 잃는 사고가 났다. **엔진을 자산으로 고정할지** 결정이 필요하다.
- 그쪽은 수렴을 `uniqueness.md` 라는 별도 참조로 다룬다. 우리는 게이트 E(자기 표절) 한 줄뿐이다.

두 차이 모두 우리가 흡수할 수 있고, 코드를 베끼지 않고도 가능하다.
