# 픽스처 풍부화 전략 — "정보가 빈약한 화면"의 근절

> G3 교훈 #6: 화면이 비는 이유의 절반은 데이터가 빈약해서다. 프로덕션급
> 화면은 프로덕션급 콘텐츠 밀도를 요구한다. 콘텐츠가 부족하면 생성해서 채운다.

## 1. 데이터 스키마 확장 (bench-fixture-gen v2)

현행(ONZIP v1): 상품 24(이미지 1장), 게시글 6(커버 1장). → 상세 화면이 빌 수밖에.

v2 표준:
- products: **images[] 3~5장** (hero / detail-cut / lifestyle / 소재 클로즈업),
  spec_table(소재·크기·색상·구성), option_variants(색상/사이즈 등 1~3축)
- reviews: 상품당 3~8건 — rating, 한 줄 제목, 2~3문장 본문(자연스러운 한국어
  구어), 도움돼요 수, 작성 시점(상대). 상세 페이지의 밀도와 신뢰 신호 담당.
- posts: **gallery[] 4~8장** + 본문 단락 3~5개(이미지 사이 배치용) +
  태그된 상품 핀 좌표(이미지 위 상품 태그 UI 테스트용)
- qna / 배송·교환 정책 블록(정적 텍스트) — 상세 하단 밀도.
- 홈 큐레이션: 기획전 2~3개(제목·부제·대상 상품군) — 홈 벤토/캐러셀 재료.

수량 산정 규칙: **화면 문법이 요구하는 최소 콘텐츠 수를 역산**한다.
캐러셀=슬라이드 4+, 벤토=칸 5+, 매거진 상세=이미지 4+ 단락 3+. 픽스처 스펙에
"이 과제의 레이아웃 문법 → 필요 콘텐츠 수" 표를 먼저 쓰고 생성한다.

## 2. 이미지 생성 파이프라인 v2

- 상품당 다중 컷: 동일 상품의 각도/맥락 변주는 프롬프트에 "same product as
  ..." 서술 + 시드 상품 설명 재사용으로 일관성 확보. 실패 시 해당 상품
  단일컷으로 강등(수량 기록).
- 컷 타입별 스타일 프리셋: hero(스튜디오), lifestyle(공간 연출),
  detail(클로즈업 質感), swatch(색상 변형).
- 총량 예산: 케이스당 60~120장. 생성기 자가 치유 auth + 페이싱 검증 완료
  상태이므로 배치 실행만 하면 됨.

## 3. 영상 (grok imagine — 데스크탑 제어 경로)

- 용도: 홈 히어로 앰비언트 루프(4~8초), 집들이 상세 인트로, 상품 360 유사 컷.
- 경로: grok CLI에는 video 도구가 없으므로, **브라우저 자동화(Claude in
  Chrome)로 grok.com/imagine 웹 UI를 제어**해 이미지→영상 생성 → 다운로드 →
  fixture에 mp4 배치(muted autoplay loop, poster 필수, reduced-motion 시 정지).
- 게이트: 사운드 자동재생 금지, LCP에 영상 금지(poster 우선), 파일 ≤3MB/클립.

## 4. 스크롤 내러티브 테스트

- 별도 과제 1종: 브랜드 스토리/기획전 랜딩 — 스크롤 리빌(IntersectionObserver),
  스티키 미디어+흐르는 텍스트, 섹션 스냅 여부 판단. reduced-motion 폴백 필수.
- 감사: 스크롤 시퀀스 스크린샷(0%/25%/50%/75%/100%)을 렌더 비평에 포함.

## 5. 3케이스 테스트 프로파일

| 케이스 | 도메인 | 핵심 문법 | 스트레스 포인트 |
|---|---|---|---|
| A 온집 v2 (오늘의집형) | 커머스+커뮤니티 | 벤토 홈, 카드 그리드, 매거진 상세 | 다중 이미지 상세, 상품 태그 핀, 리뷰 밀도 |
| B 이웃장터 (당근형) | 로컬 중고거래 | 밀도 높은 리스트, 채팅형 상세, 지역 필터 | 리스트 스캔성, 상태 배지(예약중/거래완료), 시간 표기 |
| C 스타일몰 (무신사형) | 패션 커머스 | 비주얼-헤비 그리드, 룩북 캐러셀, 랭킹 | 이미지 지배 레이아웃, 브랜드 위계, 세일가 표기 |

각 케이스는 fixture-gen v2로 데이터·이미지(·영상)를 먼저 채우고, 하네스가
철학→시스템→화면을 완주한 뒤 렌더 비평(G2)을 거쳐 사용자 G3로 간다.
