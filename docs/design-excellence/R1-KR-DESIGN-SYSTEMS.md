# 리서치 R1 — 한국 프로덕트 디자인 시스템의 철학→디테일 유도 사슬

목적: AI 코딩 하네스가 "철학이 담긴 디자인 시스템"을 생성하도록 만들 규범 추출.
방법: 공개 자료(공식 블로그, 개발자 문서, 컨퍼런스)를 열고 원문을 인용. 서비스 화면 복제가 아니라 **철학이 미시 결정을 유도하는 메커니즘**만 기록.
범위: 토스 / 당근 / 오늘의집 / 무신사 / 배민 / 네이버·라인
조사일: 2026-08-18

## 1. 토스 — TDS (Toss Design System)

### 1.1 철학/원칙 (원문 + URL)

**제품 원칙 (Product Principles)** — 토스가 "좋은 제품의 기준"으로 공개한 항목.

- **One thing per one page**
  - 원문: "토스의 제품 원칙 (Product Principle: PP) 중 단 한 가지 메시지에 집중하자는 뜻의 ‘One thing per one page’라는 항목이 있는데, 토스 제품이 복잡해짐에 따라 이를 충분히 고려하지 않은 경우가 잦아진 거죠."
  - 출처: https://toss.tech/article/design-motivation (2024-02-26, 오천석)

- **Easy to answer**
  - 원문: "토스에는 제품 디자인 원칙인 product principles가 있어요. 토스 제품의 winning strategy 를 담고 있고, 좋은 제품의 기준이 되는 원칙들인데요. … 오늘은 그 중 easy to answer라는 원칙을 지켜 제품을 개선한 사례를 보여드리려고 해요."
  - 조작적 정의: "3초 안에 답이 안나오면 어려운 질문이에요." / "저녁 뭐 먹을래?" vs "저녁에 피자 먹을까?"
  - 출처: https://toss.tech/article/insurance-claim-process (2022-12-14, 김재현)

- **Value first, cost later**
  - 원문: "토스의 제품 디자인 원칙 중에는 Value first, cost later라는 항목이 있어요. 비용을 말하기 전에 가치를 명확하게 전달해야한다는 내용이에요."
  - 비용 휴리스틱: "질문이 3,4개 이상이면 사용자는 지치기 시작해요." / "5초 내에 답변하기 어려운 질문이라면 사용자가 고민하게 만들어요."
  - 출처: https://toss.tech/article/value-first-cost-later (2023-03-16, 이혜인)

- **추천할 때는 제일 좋은 것 하나면 된다** (선택지 축소)
  - 원문: "사용자에게는 너무 많은 선택지보다, 최고의 선택지 하나가 더 좋을 수 있어요." / "결국 핵심은 선택지를 한 가지만 주는 것이었던 거죠."
  - 출처: https://toss.tech/article/recommend-just-one (2023-03-23, 박다롱)

**라이팅 코어밸류 5 + 프린시플 8** — 보이스(정체성)와 톤(태도)을 분리하고, 추상 가치를 문장 단위 규칙으로 내린다.

- 코어밸류: **Clear / Concise / Casual / Respect / Emotional**
  - Clear: "정확한 정보를 명확하게 전달하고, 메이커가 아닌 사용자가 이해할 수 있는 문장"
  - Concise: "사용자는 쏟아지는 정보를 모두 읽지 않아요. … 꼭 필요한 내용만 필요한만큼"
  - Casual: "금융이나 IT 업계에서 쓰던 어려운 용어와 딱딱한 뉘앙스를 쉽고 친절하게"
  - Respect: "당장의 이익을 조금 포기하더라도, 진실되고 사용자를 존중하는 커뮤니케이션"
  - Emotional: "토스와 연결되어 있다는 느낌을 받을 수 있게, 사용자가 느낄 감정에 공감"
- 프린시플: Predictable hint / Weed cutting / Remove empty sentences / Focus on key message / Easy to speak / Suggest over force / Universal words / Find hidden emotion
  - Weed cutting의 정의: "넣든 빼든 의사 전달에 영향이 없는 단어를 잡초라고 불러요."
  - 스케일 확장: "Weed cutting은 문장 안의 잡초를, Remove empty sentences는 화면 안의 잡초를, Focus on key message는 화면 간의 잡초를 없애는 것"
  - Easy to speak: "Easy to read가 아니라 speak" — 소리 내어 읽었을 때 어색하면 탈락
- 출처: https://toss.tech/article/8-writing-principles-of-toss (2022-11-15, 김자유)

**디자인 시스템 운영 철학**

- 원문: "디자인 시스템도 하나의 제품이고, 제품은 수요에 맞게 준비 되어야 합니다."
- 원문: "중요한 것은 우회로를 없애는 통제가 아니라, 우회할 이유를 줄이는 설계였어요."
- 원문: "디자인 시스템은 권장하는 규칙을 제공하되 그 규칙에서 벗어난 예외 상황도 지원 가능해야한다고 생각해요."
- API 전략: "단순하고 자주 쓰는 케이스는 Flat API / 복잡하고 변형이 잦은 케이스는 Compound API" — 둘을 함께 제공하는 하이브리드. 내부는 동일 primitive.
- 출처: https://toss.tech/article/rethinking-design-system (2026-01-08, 김민수)

**컬러 시스템 철학**

- 원문: "디자인 시스템은 변화하는 서비스 속에서도 일관성과 확장성을 지켜주는, 보이지 않는 인프라예요."
- 인지 균일: OKLCH로 같은 스케일(예: 100)의 명도를 맞춘다. 구 시스템에서 Grey 100은 1.1:1, Red 100은 1.34:1로 리스트가 얼룩덜룩했다.
- 수치 균일 다음 시각보정: "어두운 노란색 문제(The Dark Yellow Problem)" — 노란색만 다른 명도 진행.
- 다크모드: "다크모드에서는 명도대비를 더 강하게 가지도록 설계" (APCA 근거)
- 시맨틱 토큰: Fill/Weak 배경·텍스트 조합을 자동화해 브랜드 컬러를 입혀도 접근성을 유지.
- 출처: https://toss.tech/article/tds-color-system-update (2025-12-15, 윤민석/권윤)

**TDS 자기정의**

- 원문: "TDS는 Toss Design System의 약자예요. 토스 커뮤니티 전반에서 쓰는 디자인 시스템으로, 토스 제품을 구성하는 공통의 디자인 언어이자 개발자의 도구예요."
- 주장된 이점: "개발자는 커스텀 UI를 직접 만들 때보다 3~5배 빠르게 개발할 수 있어요."
- 출처: https://developers-apps-in-toss.toss.im/design/components

### 1.2 철학 → 미시 결정

| 철학 | 유도된 미시 결정 | 공개 수치/토큰 |
| --- | --- | --- |
| One thing per one page | 페이지 상단 `Top`이 한 메시지(title) + 선택적 subtitle/asset. 한 화면에 여러 CTA를 쌓지 않고 `BottomCTA`로 하단 고정 | `Top.upperGap`/`lowerGap` 기본값 **24**. `Top.TitleParagraph` 예시 size **28** |
| Easy to answer | 선택지를 사용자의 상태 질문으로 재작성 ("전문가 vs 직접" → "서류 있어?"). 전체 목록 대신 내 보험사만 | 해당 개선 후 이탈 **50% 감소**, 전체 퍼널 이탈 **60% 감소** (동일 아티클) |
| Value first, cost later | 퍼널 앞단에 더미 데이터로 결과 화면을 먼저 보여 가치를 체감 | 조회 완료율 **+67%**. 비용 휴리스틱: 질문 3–4개, 5초, 민감정보 |
| 선택지 하나 | 순위 리스트보다 1위 카드 1장. 배너 카피 "1등 카드 확인하기" | 배너 CTR **+20%p**. 1장 안이 전환 우위 |
| Concise / Weed cutting | 문장·화면·화면 간 3층 잡초 제거. 빈 공간을 채우려고 동어반복 금지 | 수치 없음 (규칙) |
| Casual / Easy to speak | 금융 한자어·문어체 금지. 한 문장 = 한 메시지, 짧은 호흡 | 수치 없음 |
| Suggest over force | 이탈 모달에서 손실 프레이밍 금지, 혜택은 뉴트럴하게 | 수치 없음 |
| 채도로 액션 위계 | Button `variant`: **fill**(고채도, 주 액션) vs **weak**(저채도·반투명, 보조). `color`: primary / dark / danger / light | size 기본값 **xlarge**. size ∈ {small, medium, large, xlarge}. display ∈ {inline, block, full} |
| 상태 가시성 | `loading` 시 3개 인디케이터가 순차 이동, **너비 불변**. pressed/disabled는 딤 레이어 + opacity CSS 변수 | `--button-pressed-opacity`, `--button-disabled-opacity-color`, `--button-loading-opacity` |
| 타이포 위계 | `Paragraph.typography`가 t/st 스케일. 굵기 regular/medium/semibold/bold | t1, st1–st3, t2, st4–st6, t3, st7, t4, st8–st9, t5, st10, t6, st11, t7, st12–st13 |
| 링크 기본색 | 밑줄 없는 링크 기본색 **blue500**. 컬러는 `adaptive.*` 시맨틱 | `var(--tds-paragraph-color, ${colors.blue500})` |
| 인지 균일 색 | 같은 스케일 번호 = 같은 인지 명도. 노랑만 예외 커브. 다크모드는 더 강한 대비 | 구 Grey100 **1.1:1**, Red100 **1.34:1**; Teal50 라이트 **1.06:1** / 다크 **1.36:1**. 다크 예시 `blue-50: rgb(28, 35, 49)`, `blue-100: rgb(33, 43, 65)`, `blue-opacity-50: rgba(71,134,235,0.11)` |
| 접근성 기본 탑재 | Button: role/disabled/aria-busy. Top: `role="heading"` + `aria-level=1/2`. 셀렉터 `aria-haspopup="listbox"` | 문서화된 기본값 |
| 유연한 확장 | Flat(자주 쓰는 조립품) + Compound(예외 조합). 내부 primitive 1벌 | `@tds/mobile/flat` vs `@tds/mobile` |

모서리·그림자·모션 커브의 **구체 수치(radius px, easing cubic-bezier)** 는 열린 TDS 공개 문서에서 확인하지 못함. **Partial.**

### 1.3 레이아웃 문법 (커머스·커뮤니티 / 와이드 데스크탑)

토스 공개 자료의 중심은 **모바일 슈퍼앱 퍼널**이지 와이드 커머스 그리드가 아니다.

- **한 화면 = 한 결정.** `Top`(큰 타이틀, size 28) → 본문 ListRow/입력 → `BottomCTA`. 와이드 데스크탑에서 벤토·멀티컬럼으로 펼치기보다, 인지 부하를 줄이려고 **세로 단일 열 + 하단 고정 CTA**를 유지하는 문법.
- **리스트가 피드.** 앱인토스 핵심 11개 중 `ListRow` / `ListHeader` / `Tab` / `Top` / `BottomCTA`가 정보 밀도의 기본 단위. 상품 카드 격자보다 **행 단위 스캔**.
- **가치 미리보기.** 조회/청구처럼 비용이 큰 플로우는 결과 화면(그래프, 또래 비교)을 더미로 먼저 보여 준 뒤 퍼널에 넣음. 커머스라면 PDP를 가리기 전에 혜택 결과를 먼저 보여주는 것과 동형.
- **선택지 축소.** 카드 추천 실험에서 10개 순위보다 1개 히어로가 이김. 와이드 화면에서도 "캐러셀로 많이 보여주기"보다 **한 장의 사회적 증거("1위", "3만명")** 가 원칙과 맞음.
- **에셋은 Lottie/스팟 일러스트.** `Top.UpperAssetContent` + `Asset.Lottie` (check-green-spot, confetti). 사진 격자보다 **한 점의 모션 피드백**.
- 와이드 웹 특화 벤토/멀티 이미지 규칙은 공개 문서에서 찾지 못함. **Partial** — 원칙상 공간을 채우지 않고 공백을 허용(Remove empty sentences: "공간이 비어보인다…는 이유로 의미 없는 문구를 쓰는 것도 피해야").

### 1.4 하네스에 이식할 규범 후보

1. **한 화면 한 메시지** → 페이지 템플릿은 `Top(title 1개, size≥28)` + 본문 1과제 + `BottomCTA` 1개(주) / weak 1개(부). 히어로에 문장 2개 이상이면 거절.
2. **대답하기 쉬운 질문** → 분기 카피는 도메인 선택이 아니라 사용자 상태 질문. 선택지 레이블은 3초 안에 답할 수 있어야 함. 전체 카탈로그 대신 "내 것/관련 것만".
3. **가치 먼저, 비용 나중** → 입력 3필드 이상 또는 민감정보 앞에는 결과 프리뷰(더미 허용)를 한 화면 넣는다.
4. **추천은 1장** → 그리드/캐러셀 기본값을 끄고, 1히어로 + 사회적 증거. 더보기는 secondary.
5. **잡초 3층** → 문장에서 의미 없는 단어 삭제 / 화면에서 동어반복 subtitle 금지 / 플로우에서 이미 아는 정보 재설명 금지.
6. **fill vs weak가 위계** → primary CTA만 fill+고채도. 나머지는 weak(반투명). danger는 파괴적 액션만.
7. **기본 버튼은 크다** → size 기본 xlarge. 금융/결정 화면에서 작은 버튼을 기본값으로 쓰지 않음.
8. **같은 스케일 = 같은 명도** → 팔레트 번호(100/200…)는 색상 간 인지 명도를 맞출 것. 노랑만 예외 커브. 다크모드는 대비를 더 강하게.
9. **로딩 너비 고정** → 버튼 로딩이 레이아웃을 밀지 않음. pressed는 별도 딤 opacity.
10. **통제 대신 우회 이유 제거** → 자주 쓰는 패턴은 Flat(props), 예외는 Compound(슬롯). 금지 규칙만 늘리지 않음.
11. **소리 내어 읽히는 카피** → Easy to speak. 한자어·긴 호흡·업계 은어 거절.
12. **공포/손실 프레이밍 금지** → Suggest over force. 이탈 방어 카피는 뉴트럴.

## 2. 당근 — SEED (Karrot Design System)

### 2.1 철학/원칙 (원문 + URL)

**자기정의**

- 원문: "SEED는 당근의 뿌리가 되는 디자인 시스템이에요. 컴포넌트, 인터랙션, 스타일을 하나의 기준으로 정의해 더 빠르고 일관된 사용자 경험을 만들 수 있게 해요."
  - 출처: https://seed-design.io/
- 원문: "SEED는 당근 제품을 위한 통합 디자인 언어로, 색·타이포·간격 같은 시각 요소부터 버튼·리스트 같은 컴포넌트, 그리고 눌렀을 때의 반응 같은 모션까지, 제품을 이루는 결정을 하나의 체계로 정리한 시스템이에요."
  - 출처: https://seed-design.io/get-started
- 원문: "디자인 시스템이란 결국 제품을 만들 때 따라오는 수많은 디자인 의사결정을, 당근에 맞는 기준으로 정리하고 반복 가능한 형태로 압축해주는 일"
  - 출발점: "당근에는 다른 IT 서비스에서 느끼기 어려운, 어딘가 인간적이고 따뜻한 인상이 있어요."
  - 출처: https://seed-design.io/updates/how-seed-evolved (2026-06-17)

**브랜드 슬로건 (시스템 브랜드)**

### 2.2 철학 → 미시 결정

| 철학 | 유도된 미시 결정 | 공개 수치/토큰 |
| --- | --- | --- |
| 로고의 둥글+엣지 | 반경 스케일 0.5 단위. 리스트 pressed-inset은 **동심 반경**(컨테이너 R − padding) | r0_5=2 … r6=24, full=9999. 예: 카드 16 − pad 6 = 내부 10 |
| 접근성 = 기본값 | 색은 값 금지, **역할 토큰**. fg 위계: neutral / muted / subtle / placeholder / disabled | `$color.fg.brand` = carrot-600(라이트) / 700(다크). `$color.bg.brand-solid` = carrot-600 / 700. `$color.stroke.focus-ring` = blue-600 |
| 같은 단계 = 같은 대비 | 톤을 단계별로 맞춤 → 서비스팀이 variant를 "같은 단계에서 톤만 바꾸면" 됨 | solid / weak / outline, pressed는 한 단계 진하게(carrot-600→700) |
| 다크모드 계층 | 배경은 더 어둡게, 앞 레이어는 상대적으로 밝게 | layer-basement: gray-200 / gray-00. layer-default: gray-00 / gray-100. layer-floating: gray-00 / gray-200 |
| 터치 확신 | pressed-scale 모션 + duration | `$timing-function.pressed-scale` = cubic-bezier(0,0,0.15,1). `$duration.pressed-scale` = **150ms** (d3). 마이크로 ≤200ms, 매크로 >200ms |
| 타이포 덜어내기 | 38→**24** 스타일. Medium(500) 추가로 위계. rem 우선 | t1=11px … t14=48px. 본문 t1–t5, 제목 t6–t10, 대형 t11–t14는 **sm 이상**. weight 400/500/700. 시스템 폰트 스택 |
| 간격의 의미화 | raw dimension + semantic | x1=4 … x16=64. **global-gutter = x4 = 16px**. component-default = x3=12. nav-to-title = x5=20. screen-bottom = x14=56. between-text = x1_5=6. between-chips = x2=8 |
| 브랜드 주황은 희소 | Brand Solid는 **한 화면 1개**. '채팅하기','단골맺기','글쓰기'처럼 **이웃 연결**에만 | High: Brand/Neutral/Critical Solid (1개). Medium: Neutral Weak (여러). Low: Outline/Ghost. Solid와 Outline을 섞지 않음. 2버튼 Dismiss는 **3:7**. 나란히 3개+ 금지 |
| 그림자 절제 | Elevation은 색·그림자·선 3수단. 그림자는 주목 요소만 | s1: 0 1 4 #00000014 / 다크 #00000080. s2: 0 2 10. s3: 0 4 16. "다크에서 잘 안 보이니 몇 안 되는 요소에만" |
| 리스트 = 피드 문법 | 행 단위 스캔. 클릭 타겟 ≤3. 행 패딩 ≥ global-gutter | Prefix/Suffix 프리셋. Highlighted로 신규 강조. 배경색 없음(부모 컨테이너가 담당) |
| 사려깊은 카피 | 존칭 최소화, 끌올 금지, 상태값 붙여쓰기, 타이틀/버튼에 마침표 없음, 20pt+ 마침표 없음 | Do/Don't 표가 규범 |
| 지역사회 | 푸시에 동네 이름 | "지금 역삼동 근처 주민들과…" |
| 실험으로 증명 | 프로필에 V3 적용 | 이웃 모아보기 **+44%**, 체류 Android **+68%** / iOS **+83%** |

### 2.3 레이아웃 문법 (커머스·커뮤니티 / 와이드 데스크탑)

SEED는 모바일 마켓+커뮤니티와 **웹 대시보드/콘텐츠**를 분리한다.

- **모바일 피드:** List(가로 행)가 기본. 상품/이웃은 썸네일 Prefix + Title + Detail(가격·동네·시간) + Suffix. 격자보다 **스캔 가능한 행**. Image Frame이 업로드 사진 담당.
- **와이드 웹 — Contents Layout:** 12컬럼. lg부터 **중앙 정렬**. max-width **1040px**가 기본. "커머스 검색 결과 등 넓은 탐색"만 **1280px**. 공간을 벤토로 채우지 않고 **읽기 폭을 잠근다**.
- **Dashboard Layout 밀도 3단:**
  - Low: 8col, gutter 24, margin 32, max 720
  - Middle(base): 12col, 24/32, max 1040
  - High: fluid full-width, margin 32, min 1040
- **Breakpoint (mobile first):** base 0–479 (gutter 16 / margin **12**) → sm 480–767 → md 768–1279 (32/24, 사이드바 노출) → lg 1280–1439 → xl 1440+.
- **Region:** Header(GNB) / Side Nav(md+) / Main / Aside. 와이드에서 상세는 새 페이지보다 **Aside 슬라이드**.
- **상품 카드가 아니라 리스트+매너온도.** `Manner Temp`가 신뢰 배지. 커머스 광택(큰 그림자, 벤토 히어로)보다 **이웃 신뢰 시그널**.
- **Brand CTA는 연결 동사.** 와이드에서도 주황 버튼을 장식용으로 뿌리지 않음.
- 공개 문서에 상품 카드 캐러셀/벤토 스펙은 없음. **Partial.** 대신 그리드 숫자(1040/1280, gutter 24, margin 32)가 와이드 문법.

### 2.4 하네스에 이식할 규범 후보

1. **당근다움 = 규칙** → 반경·아이콘 스트로크·pressed inset을 토큰으로 고정. "친근해 보이게"라는 형용사를 금지하고 r2/r4/동심 반경으로 대체.
2. **색은 역할** → hex 직접 사용 금지. `fg/bg/stroke` × `brand|neutral|positive|warning|critical|informative` × `solid|weak`. Brand는 이웃 연결 CTA 1개만.
3. **위계는 대비로** → High solid 1개 + Medium weak + Low outline. Solid+Outline 혼용 금지. 2버튼 Dismiss는 3:7.
4. **터치 피드백 필수** → 누를 수 있는 면은 150ms pressed-scale. targetSize를 스펙에 적는다.
5. **타이포 스케일 압축** → t1–t14 + 400/500/700만. 시맨틱(screenTitle, articleBody) 우선. 큰 제목(t11+)은 sm 이상.
6. **간격은 의미 토큰** → 화면 가장자리 = global-gutter 16. 화면 하단 = 56. 칩 간격 = 8. 텍스트 사이 = 6.
7. **그림자는 희소** → 기본 계층은 layer 색. shadow는 FAB 등 떠 있는 것 몇 개. 다크에서는 더 절제.
8. **리스트가 피드** → 상품/이웃 기본형은 행. 한 행 상호작용 ≤3. 패딩 ≥16.
9. **동심 반경** → 내부 R = 부모 R − padding.
10. **카피:** 존칭 최소, 축약 금지, 기능명 대신 목적("채팅으로 거래하기"), 한 문장 한 목적, 동네 이름, 버튼에 마침표 없음.
11. **와이드는 폭을 잠근다** → 콘텐츠 1040, 커머스 탐색만 1280. 빈 여백을 카드로 채우지 않음.
12. **고칠 수 있는 시스템** → 토큰 참조를 추적 가능하게. 컴포넌트는 분해 제공(제약으로 통일하지 않음).

| 철학 | 유도된 미시 결정 | 공개 수치/토큰 |
| --- | --- | --- |
| 집의 변화를 쉽게 | 3C+시공을 한 흐름. 선택 폭주를 줄이고 패키지·정찰제·책임보장으로 결정 비용 하향 | 수치 없음. 퍼널 철학 |
| 영감은 일상 | 브랜드 컬러 = 맑은 하늘/일상. 로고는 채워진 부드러운 곡선 집 | hex 미공개. **Partial** |
| 완벽 < 목표 | 원칙을 체크리스트로 씀. DS만으로 새 페이지 통일 불가 → 원칙이 보완 | 2020 원칙 다이어그램은 이미지 |
| 1%의 무언가 | 인테리어의 막막함을 위트·재미로 완화. 퇴근길/소파 맥락 | 카피 톤의 온도 차이 예시만 |
| 감각 → 규칙 | 카테고리 아이콘: **한 이미지 = 한 상품**, 정중앙, 정투영, 저대비 균일광, 화이트/alpha 배경, 브랜드 문자 제거 | 200종 / 2주. 구도 체크리스트 5항. 하나라도 NO면 폐기·재생성 |
| 작은 용처 시인성 | 다중 오브젝트 금지(작을 때 의미 붕괴). 실사 난립 대신 표준화된 사진형 아이콘을 홈 전면 | 홈 개편에서 카테고리를 1뎁스로 |
| 브랜드 목소리 일관 | 컴포넌트별 카피 가이드 + 다크패턴 금지. 시공 도메인은 사장님/고객 말투 분리 | 라이팅봇 3종 |
| 평균은 시스템, 정점은 사람 | MCP로 색·버튼·레이아웃 공통 요소를 초안에 강제. 크리틱은 사람이 서명 | 관리자 9화면 20일→5일 |
| 레이아웃이 안 무너지게 | 빌더: 필요 선택지만. 긴 텍스트·다른 이미지 비율을 규칙으로 흡수. 브랜드 컬러/타이포는 **CSS 변수** | 2컬럼(입력\|미리보기). 자유 드래그 최소화 |
| 익숙한 조작 | 이미지 8핸들(흰색 사각+파란 테두리), 비율 유지 스케일, 휠 줌, 150% 뱃지 1.2초 | 구현 스펙으로 공개된 유일한 인터랙션 수치 |

반경/그림자/타이포 스케일 표는 공식 문서에서 찾지 못함. **Partial.**

### 3.3 레이아웃 문법 (커머스·커뮤니티 / 와이드)

오늘의집은 한국 서비스 중 **사진 피드 + 상품 격자**가 본체다. 공개 글이 말하는 문법:

- **콘텐츠가 상품을 연다.** 집들이 사진 → 태그 → 상품. 와이드에서도 벤토 장식보다 **사진이 캔버스, UI는 얇은 오버레이**.
- **홈 = 카테고리 아이콘 전면.** 200종을 1뎁스에 깔려면 아이콘이 사진처럼 보여도 **단일 오브젝트·정투영·흰 배경**이어야 스캔 가능. 격자 밀도는 "시인성"이 상한.
- **화이트 캔버스 + 따뜻한 사진.** 그래픽 규칙(화이트/저대비)이 UI 크롬을 낮추고 유저 사진을 주인공으로.
- **와이드 커머스:** 검색·기획전은 넓은 탐색. 빌더 글은 피드/스토리 규격을 동시에 뽑는 SNS 빌더, 배너 빌더를 운영 — 즉 **채널별 고정 비율**이 있고, 빈 여백은 AI로 확장하지 카드로 채우지 않음.
- **3C 한 흐름.** 와이드 PDP는 리뷰/집사진/유사상품을 끊지 않고 이어 붙이는 원스톱. 리브랜딩이 명시한 것은 "파편처럼 흩어진 과정을 한 흐름으로".
- **선택 줄이기.** "넘쳐나는 선택지 속에서 취향을 찾기 어려웠던" 과거를 부정. 패키지·큐레이션이 히어로, 무한 격자는 보조.
- 데스크탑 max-width/컬럼 수는 미공개. **Partial.** 관찰 가능한 유도: 사진은 크게, 크롬은 얇게, 카테고리는 균일 아이콘 리본.

### 3.4 하네스에 이식할 규범 후보

1. **쉽게 = 결정을 줄인다** → 라이프이벤트(이사/신혼/시공)마다 원스톱 템플릿. 같은 과제를 여러 앱으로 보내지 않음.
2. **완벽보다 목표, 끝에 1%** → 먼저 과업 완료, 그다음 위트 한 점. 위트가 과업을 막으면 삭제.
3. **영감은 일상 팔레트** → 하늘빛·낮은 채도 크롬. 장식 그라데이션/드라마틱 조명 금지.
4. **사진은 주인공** → UI는 흰 캔버스. 카드 그림자로 사진을 이기지 않음.
5. **단일 오브젝트 원칙** → 썸네일/카테고리/아이콘은 피사체 1개, 정중앙, 정투영, 문자·로고 제거, 투명/흰 배경.
6. **작을수록 더 단순한 실루엣** → 다중 상품 합성 썸네일 거절.
7. **카피는 온도** → 오류도 "~아요" + 다음 행동. 다크패턴 금지. 도메인(고객/사장님/PB)별 보이스 파일.
8. **생성 전에 목표 질문** → 화면/카피 생성 시 타깃·사용자 목표·서비스 목표를 먼저 받음.
9. **Good은 시스템, Great은 서명** → 토큰·템플릿으로 60점을 보장하고, 오늘의집다움(유저 문제/이유/실행 깊이)만 사람이 올림.
10. **자유 편집 < 선택지** → 빌더형 UI는 필요한 옵션만. 레이아웃이 입력 길이에 깨지지 않게 규칙화.
11. **크리틱을 원칙으로 증류** → 팀 피드백 로그를 10원칙으로 압축해 에이전트에 넣음. 일반론("여백을 주세요") 금지.

## 4. 무신사 — MDS / MUSINSA 2.0

두 층: (A) 2023–24 플러스엑스와 만든 **MUSINSA 2.0 디자인 언어**, (B) 사내 엔지니어링 **MDS(Musinsa Design System)**. 토큰 px 표는 비공개. **Partial.**

### 4.1 철학/원칙 (원문 + URL)

**한 문장 방향**

- 원문: 실용성과 효율성에 기반한 5원칙이 **“최소한의 디자인으로 최대한의 기능을 구현한다”** 로 수렴.
- 내부 지향: "패셔너블한 플랫폼보단 **일상에 밀착된, 실용적인 플랫폼**"
- 출처: https://brunch.co.kr/@plusx/130 (2025-07-21, 플러스엑스 이혜빈·윤예진·이정민)

**5가지 디자인 원칙 (원문 목록)**

1. 기본 요소를 명확한 기준에 따라 사용합니다.
2. 모듈화된 컴포넌트로 다양한 상황과 언어에 대응합니다.
3. 상품과 콘텐츠를 다양하게 보여줄 수 있는 포맷을 디자인합니다.
4. 실용적이고 일관성 있는 컴포넌트 제작합니다.
5. 단순한 요소들을 활용하여 정교한 화면 구조 구축합니다.

**지향 4가지 (문제 진단 후)**

- 일관적인 디자인 시스템 / 기본적인 사용 방식 / 호환성 높은 컴포넌트 / 체계적인 서비스 일원화
- 문제: 지면마다 검·파랑이 위계 없이 혼재. PC와 모바일이 별도 운영.

**무신사스러움 = Gray / Back to Basic**

- 원문: "여러 브랜드가 공존하는 플랫폼은 어떻게 자기만의 색깔을 보여줄 수 있을까요?"
- 해답: 오프라인 **무신사 스탠다드** 매장의 금속·대리석·유리·우드 → 공간을 감싼 **그레이를 대표 컬러**. "중립적인 컬러로 입점 브랜드를 포용하고 정제"
- Back to Basic: 기본 형태, 텍스트 가시성, 정보 위계를 한눈에.

**Z축 계층**

- "그레이 컬러의 배경 위에 화이트 컬러의 컴포넌트가 모듈로 조합"
- Z축이 주목도와 인지 피로를 조절. 복잡한 콘텐츠를 쉽게 인식.

**MDS 엔지니어링 (사내)**

- 은탄환 없음. 유지보수성을 핵심으로 **Headless UI**. Atomic + Compound + Radix. Molecule 이상에서 Slot / SlotProps / Render Props 투트랙.
- SVG에 `vector-effect` 자동 주입, ts-morph로 아이콘 대량 수정.

### 4.2 철학 → 미시 결정

| 철학 | 유도된 미시 결정 | 공개 수치/토큰 |
| --- | --- | --- |
| 최소 디자인, 최대 기능 | 장식 컬러·독자 언어 금지. 기본 요소를 기준대로만 | 구체 px 없음 |
| 플랫폼은 회색, 브랜드는 상품 | UI 크롬 = Gray. 키컬러로 검/파랑을 남발하지 않음. 입점 브랜드 사진이 색을 담당 | "검은색과 파란색이 키컬러처럼… 위계 없이"가 개선 대상 |

### 4.3 레이아웃 문법 (커머스·커뮤니티 / 와이드)

무신사는 **에디토리얼 패션 피드 + 상품 격자**가 본체. 2.0이 명시한 문법:

- **상품이 주인공, UI는 전시장.** 스탠다드 매장처럼 회색 공간에 흰 모듈. 와이드 데스크탑도 벤토로 크롬을 키우지 않고 **그레이 필드 위 흰 카드 그리드**.
- **포맷의 다양성 = 상품/콘텐츠를 보여주는 틀의 다양성** (원칙 3). 한 가지 카드가 아니라 리스트·카드·스냅·후기 포맷을 모듈로 갈아끼움.
- **스냅과 후기는 붙이지 않음.** 와이드 PDP에서도 코디 영감(스냅)과 구매 정보(후기)를 한 캐러셀로 섞지 말 것. 공통 영역만 연결.
- **게이트웨이.** 뷰티/부티크/슈즈 등 버티컬은 팝업 관문 + 관별 액센트. 와이드 GNB에 모든 관을 동등하게 깔아 색이 싸우게 하지 않음.
- **PC↔모바일 일원화.** 별도 컴포넌트 세트를 두지 않음. 와이드는 같은 모듈의 밀도 변화.
- **커뮤니티가 커머스의 꽃.** 스냅 태그가 상품으로 바로. 콘텐츠 소비율 = 일관 컴포넌트.
- max-width/컬럼/radius 수치는 공개 문서에 없음. **Partial.** 유도: 공간을 회색으로 비우고, 흰 모듈로만 채운다.

### 4.4 하네스에 이식할 규범 후보

1. **최소 디자인, 최대 기능** → 크롬은 회색 스케일. 브랜드 액센트는 상품·전문관 게이트에만.
2. **플랫폼은 중립, 입점 브랜드가 색** → UI가 패션 사진과 싸우면 실패.
3. **Gray 필드 + White 모듈 + Z축** → 배경을 회색으로 깔고 카드를 흰색으로 띄움. 그림자보다 면 대비.
4. **기본 형태, 높은 텍스트 대비** → 실험적 라디우스/장식 타이포 금지. 위계는 크기·굵기.
5. **모듈로 지면을 조립** → 상품 리스트 / 콘텐츠 카드 / 스냅 / 후기를 슬롯 조합.
6. **목적 다른 콘텐츠는 분리** → 영감(스냅)과 스펙(후기)을 한 그리드에 섞지 않음.
7. **버티컬은 게이트 + 관 색** → 현재 위치를 색으로. 전관 무지개 크롬 금지.
8. **PC/모바일 한 시스템** → 와이드는 새 언어가 아니라 같은 모듈의 밀도.
9. **Headless + Compound** → 스타일 변형이 행동을 깨지 않게. MDS와 토스의 Flat/Compound가 동형.

### 5.3 레이아웃 문법 (커머스·커뮤니티 / 와이드)

- **앱(B2C):** Style 2.0 이후 캐릭터·장식 리본을 걷어낸 **음식 사진 + 얇은 민트 크롬**. 와이드 웹도 같은 논리 — 가게/메뉴가 주인공, UI는 볼드한 타이포와 민트 CTA.
- **사장님(B2B) 와이드:** 카드 모듈이 본문. 디바이스·폼 수에 따라 카드가 재배치. 대시보드를 벤토로 꾸미지 않고 **같은 카드 문법의 밀도 변화**.
- **강조 충돌 금지.** 한 카드에 세일/뱃지/민트를 동시에 켜지 않음. 워크숍에서 명문화한 규칙.
- **조회 vs 편집.** 읽기 화면과 폼 화면의 시각 언어를 나눔. 와이드 어드민에서 편집 밀도를 높이되 조회 카드와 섞지 않음.
- **커머스 피드(배민스토어/쇼핑):** 공개 토큰 없음. 유도는 앱과 동일 — 장식 제거, 상품 사진, 민트 한 점.
- 컬럼/max-width 미공개. **Partial.**

### 5.4 하네스에 이식할 규범 후보

1. **쉽고 명확하고 위트있게** → 카피에만 위트. UI 크롬에 캐릭터/스티커를 올리지 않음.
2. **볼드 & 심플** → 제목은 블록형 굵은 산세리프. 속공간을 열어 작은 화면 가독.
3. **액센트 1색 + 기능별 명도** → 브랜드색을 버튼/배경/텍스트에 같은 hex로 쓰지 말고 역할별 명도 스케일.
4. **장식 관성 삭제** → "예전부터 있던 마스코트"는 기능이 아니면 제거.
5. **같은 종류의 기능 = 같은 동작** → 수정은 항상 같은 패턴(다이얼로그 vs 페이지를 도메인마다 바꾸지 않음).
6. **정보는 카드, 레이아웃은 자동** → 모바일 1열을 그리고 와이드는 카드 수·폼 수로 재배치.
7. **조회와 편집을 면으로 구분** → 읽기 카드와 입력 폼의 배경/보더가 달라야 함.
8. **강조가 겹치면 하나 남긴다** → 세일+신규+브랜드를 한 썸네일에 쌓지 않음.
9. **Edge는 격리** → 예외 케이스가 기본 레이아웃을 깨지 않게 별도 슬롯.
10. **날것의 목소리** → 브랜드 카피를 매끈한 대행사 톤으로 포장하지 않음. 못생긴/대담한 한 점을 허용하되 앱 본문 가독은 타협하지 않음.

| 유니버설 테마 | **브랜드 헤더(자유) + 뉴트럴 보디(그리드)**. 보디는 색이 도드라지지 않음 | 웹 그리드 가이드 존재, px 미공개 |
| 인터랙션 일관 | Lottie/JSON, iOS·Android 동일 값, 코드 스니펫 | OS 간 체감 동일 |

반경/간격 스케일 표는 LDS 공개 사이트 본문이 JS라 추출 실패. **Partial.**

### 6.3 레이아웃 문법 (커머스·커뮤니티 / 와이드)

- **네이버 검색(와이드 포함):** 스마트블록을 세로로 쌓는 **컬렉션 피드**. 와이드에서도 벤토로 해체하지 않고, 블록 내부 템플릿만 바꾼다(이미지 그리드 vs 텍스트 스니펫). 쇼핑 블록은 상품 격자가 블록 안에 들어감 — 페이지 전체가 쇼핑몰이 아님.
- **라운드 + 균일 그리드.** 검색창·카드·썸네일이 같은 곡률 언어. 와이드 여백은 그리드 정렬로 삼키지, 장식 패널로 채우지 않음.
- **정답 다음 피드.** 와이드 결과 하단이 탐색의 시작. 페이지 번호 대신 연속 스크롤.
- **LINE 메신저:** 심플 대화가 본체. 플렉스 메시지로 미디어+버튼 조합. 와이드(PC LINE)도 같은 기본 컴포넌트.
- **LDSG 패밀리(커머스/핀테크):** 헤더만 브랜드 색, 본문은 뉴트럴 그리드. 와이드 웹에서 서비스 BI가 본문까지 물들이지 않음.
- **네이버 쇼핑/플레이스:** SDS 규칙상 이미지가 결정 정보면 그리드, 스펙이 결정이면 텍스트. 패션 PDP와 금융 안내를 같은 스니펫으로 찍지 말 것.

### 6.4 하네스에 이식할 규범 후보

1. **정답 다음에 탐색** → 완료 화면 아래에 관련 피드를 붙인다. 1·2·3 페이지네이션 기본값 금지.
2. **주제 = 템플릿** → 이미지가 선택을 좌우하면 그리드/큰 미디어. 절차·조건이 좌우하면 텍스트 스니펫 우선.
3. **모두 라운드, 한 그리드** → 검색창·카드·썸네일 곡률을 통일. 임의 직각/타원 혼용 금지.
4. **토큰→블록 레시피** → 화면을 통째로 그리지 말고 모듈 조합. 모듈이 레시피.
5. **신뢰 = 적은 색 + 강제** → 브랜드 그린 + 제한 프라이머리. 프로모만 무지개. 토큰 밖 hex는 빌드 경고.
6. **중의 없는 문장** → LINE 보이스. 버튼/툴팁은 한 가지로만 읽히게.
7. **컴포넌트와 UX 가이드는 한 쌍** → 가이드 없는 컴포넌트 배포 금지.
8. **메신저형 vs 패밀리형** → 코어 제품은 타이트, 확장 서비스는 6속성만 잠그고 테마.
9. **헤더는 브랜드, 보디는 뉴트럴** → 와이드에서 본문까지 브랜드색을 깔지 않음.
10. **국가/언어가 타이포를 가른다** → 한 폰트 스택을 전 로케일에 강제하지 않음.
11. **그래픽은 밝고 보편** → 특정 문화 제스처·연령 배제 얼굴 금지. 비율 가이드.
