# 패치 10 설계 초안 — 철학 유도 사슬 (Philosophy Derivation Chain)

> G3 교훈 #2: 디테일의 부재는 철학의 부재다. 미시 결정(모서리·상태·정렬·밀도)이
> 철학에서 유도되지 않으면 컴포넌트는 "대충 AI 생성"으로 보인다.
> 목표: 디자이너·프론트엔드가 DESIGN.md를 읽고 "왜 이 값인가"에 답을 찾는 것.

## 유도 사슬 (하네스 작업 순서 재설계)

```
브리프+도메인+데이터
  → [1] PHILOSOPHY  한 문장 입장(stance) + 원칙 3개
                    각 원칙은 반드시 "무엇을 얻기 위해 무엇을 희생하는가" 포함
  → [2] DERIVATION  원칙 → 결정 표: 각 원칙이 강제하는 미시 결정
                    (모서리·그림자·색 밀도·타이포 위계·모션 커브·정보 밀도·
                     레이아웃 문법 후보)  ※ 근거 없는 결정 금지
  → [3] TOKENS      결정 표 → 토큰 값 (결정 ID를 토큰 주석으로 역참조)
  → [4] COMPONENT SPECS  컴포넌트별 명세서 (코드 전에 문서로):
                    상태 매트릭스 · 기하(높이/패딩/히트타깃) · 광학 정렬 ·
                    아이콘 규격 · 커스텀 리스트박스 등 합성 컴포넌트 패턴
  → [5] LAYOUT GRAMMAR  페이지별 문법 선언 + 콘텐츠 수 역산
                    (부족하면 데이터·에셋 추가 생성/요청이 먼저)
  → [6] BUILD       페이지는 [3][4][5]를 소비만 한다
  → [7] RENDER CRITIQUE  실제 스크린샷 기반 비평(슬롭 게이트 전수 스윕) → 수정
  → [8] DESIGN.md   [1][2]의 철학·유도 근거가 Core v2 experience/governance에
                    실려 "왜"에 답하는 문서가 된다
```

## 예시 (온집이라면)

- 철학: "물건보다 물건이 놓인 삶을 먼저 보여준다 — 속도를 희생하고 맥락을 얻는다"
- 원칙 P1 "맥락 우선" → 결정: 상품 카드는 lifestyle 컷 우선, hero 컷은 상세에서;
  카드 비율 4:3(공간이 보이는 비율); 홈은 벤토(집들이+상품 혼합)
- 원칙 P2 "차분한 신뢰" → 결정: 모서리 12px 단일값(부드럽되 장난스럽지 않게),
  그림자 1단(멀리 안 뜸), 악센트는 행동에만, 모션 200ms ease-out 단일 커브
- 원칙 P3 "정보는 밀도 있게, 감정은 여백 있게" → 결정: 상세 스펙/리뷰는 컴팩트
  행(밀도 8px 리듬), 미디어 섹션은 섹션 공기 4rem

각 결정은 D-번호를 갖고 토큰/컴포넌트 주석에서 역참조된다:
`--radius-card: 12px; /* D-P2-1 */`

## 리서치 반영 지점 (R1/R2 수렴 후 확정)

- [2]의 결정 카테고리 표준 목록 ← R1(한국 시스템들이 실제로 유도하는 축)
- [4]의 컴포넌트별 프로덕션 명세 체크리스트 ← R2(HIG/M3/Polaris/Radix)
- [5]의 문법 카탈로그와 선택 규칙(뷰포트×콘텐츠 양×종류) ← R2
- 커스텀 리스트박스 정본 패턴(APG combobox) ← R2

## 구현 형태

- SKILL.md의 작업 순서 절 교체 + `references/derivation-chain.md`(신규,
  결정 카테고리 표준 + 예시) + `references/component-specs.md`(신규,
  컴포넌트별 프로덕션 명세) + slop-gates GS7 추가(근거 없는 미시 결정 금지:
  토큰에 D-참조 없는 값이 있으면 실패)
- Core v2 스키마는 불변 — 철학·유도는 experience 섹션과 provenance
  decisions(D-번호)로 수용 가능. 컨트롤러 변경 불필요 예상.
