# smooth-scrub-engine — 스크롤에 상태를 준다

**층**: 스크롤 · **크기**: ~1.4KB gz (JS 60줄) · **라이선스**: MIT (자작) · **의존성 0**

## 언제 쓰나
스크럽·핀 연출이 "딱딱하다"는 지적을 받을 때. 그리고 정착(LC-48) 이후 홀드 구간이 죽을 때.

## 원리
스크롤은 **목표값만** 쓰고, 상시 rAF 루프 하나가 현재값을 목표로 프레임당 고정 비율 α 만큼 걸어간다.

```
cur += (target - cur) * α
```

이 한 줄이 없으면 스크롤 이벤트가 값이 되고, 휠의 이산 단계가 그대로 화면의 계단이 된다.

**두 시계를 나눈다.** 진행률 `--p`(핀 트랙에서 얼마나 왔나)와 가시 수명 `--v`(스테이지가 화면에 얼마나 머무나)는
다른 시계다. 하나로 묶으면 정착 후 홀드에서 아무 일도 일어나지 않는다. `--e` 는 정착 대역 `k` 로 나눈 뒤
이징한 진행률이며, **이징은 보간 이후 값에 건다**(순서가 바뀌면 감쇠가 이징에 먹힌다).

## 근거 수치 (2026-09-05 실측)
| 출처 | α |
|---|---|
| higgsfield (framer-motion) | 0.15 |
| runway (GSAP ScrollSmoother) | 0.16 |
| scroll-craft 엔진 기본값 | 0.18 |
| 우리 r2 (70점, GSAP scrub) | 0.25 |
| **우리 r4 (65점, 감쇠 없음)** | **0.53** ← 유일하게 대역 바깥 |

기본값 **0.14**. `data-sc-lerp` 로 요소별 조정(0.02~1). 리듀스드 모션에서는 **1**(보간 없음).

## 검증 (`demo.html`, 1440×900 헤드리스)
1500px 을 한 프레임에 점프시키고 `--e` 를 프레임마다 읽었다.

| α | 프레임별 값 | 99% 도달 |
|---|---|---|
| **0.14** | 0.863 → 0.963 → 0.995 → 1.000 | **4프레임** |
| 0.53 | 1 → 1 → 1 | 1프레임(스냅) |
| 1 (리듀스드 모션) | 1 → 1 → 1 | 1프레임 |

## 금기
- **양자화 임계로 값을 끊지 마라.** r4 의 `Math.abs(v-last) > 0.0015` 는 루프 없이 값을 띄엄띄엄 갱신해
  계단을 하나 더 만들었다. 데드밴드는 *루프를 유지한 채* 쓰기만 생략하는 것이고, 목표에 도달하면 스냅한다.
- α 를 0 으로 두지 마라 — 영영 도달하지 않는다. 0.02 하한을 코드가 강제한다.
- 섹션마다 스크롤 리스너를 달지 마라. **루프는 하나**다.
- 스무스 스크롤(문서 전체를 transform 으로 미는 것)과 혼동하지 마라. 이 엔진은 **값**을 감쇠할 뿐
  페이지 스크롤은 네이티브로 둔다(접근성·스크롤바·키보드 유지). 페이지까지 부드럽게 하려면 별도 판단이 필요하다.

## 변수
`--p` 진행률(0~1) · `--e` 정착 이징된 진행률 · `--v` 스테이지 가시 수명(0~1).
속성: `data-sc-k` 정착 지점(기본 0.55) · `data-sc-lerp` 보간 계수(기본 0.14).
