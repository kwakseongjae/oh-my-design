# drift-collage — 살아 있음과 흔들림을 가르는 것

| | |
|---|---|
| 계열 | 유휴(idle) · 배경 |
| CSS-only | ✅ 예 — JS 0줄 |
| 인라인 크기 | CSS 34줄 / 약 1.3KB |
| 다크/라이트 | 둘 다 — `--fx-drift-veil` 를 배경색으로 **반드시 교체** |

## 핵심 — 위상이 어긋나야 살아 있다
타일 7장에 같은 애니메이션을 걸면 한 덩어리가 통째로 흔들린다. 그건 살아 있는 게 아니라 **떨리는** 것이다.
타일마다 셋을 다르게 준다:
- `--ax` 진폭(8~18px) · `--ar` 회전(±1~2.2deg)
- `--dx-dur` / `--dy-dur` 주기 — **서로소에 가깝게**(17s/23s, 29s/37s). 정수배면 몇 바퀴 뒤 다시 동기화돼 덩어리로 보인다.
- `--ph` 음수 지연 — 처음부터 각자 다른 위치에서 시작한다. 0 이면 페이지 진입 순간 전원이 같은 지점에 있다.

## 왜 `translate` / `rotate` 개별 속성인가
`transform` 하나에 두 애니메이션을 걸면 뒤의 것이 앞의 것을 **덮는다**. CSS 개별 변환 속성
(`translate` · `rotate` · `scale`)은 각각 독립 애니메이션을 가질 수 있어, X 표류와 회전의 **주기를 다르게** 줄 수 있다.
주기가 다른 두 운동이 겹쳐야 궤적이 반복으로 안 읽힌다. 이 효과의 핵심 트릭이다.

## 금기
- **진폭 20px 초과 금지.** 배경이 전경을 방해하기 시작한다. 히어로 카피가 위에 있으면 14px 이하.
- 주기 12초 미만 금지. 빠른 드리프트는 "떠 있음"이 아니라 "불안"이다.
- veil(가장자리 그라디언트) 없이 쓰지 않는다. 없으면 잘린 사각형 콜라주로 보인다. 라이트 모드에서 veil 색 교체는 **필수**.
- 타일 9장 초과 금지 — 레이어 예산. `aurora-mesh` + `film-grain` 과 겹쳐 쓰면 배경 레이어 2겹 규칙을 넘긴다. 셋 중 둘까지.
- 전경 텍스트에 `pointer-events:none` 을 빠뜨리면 선택이 막힌다.

## 성능 조건
- 합성만 한다(translate/rotate). 페인트 0, 레이아웃 0.
- 타일 7장 = 레이어 7장. `will-change` 는 타일에만.
- 화면 밖으로 스크롤돼도 CSS 애니메이션은 계속 돈다. 긴 페이지라면 `IntersectionObserver` 로 `animation-play-state: paused` 를 토글한다(JS 6줄).

## 모바일 / 리듀스드 모션
- `prefers-reduced-motion` → `animation: none`. **정지한 콜라주도 구도로 성립**하므로 숨기지 않는다.
- 모바일에서는 타일 수를 4장으로 줄이고 바깥쪽 3장을 `display:none` 하는 편이 낫다(작은 화면에서 7장은 죽이다).

## 이미지 슬롯
`.fx-drift__ph` → `<img>`. Higgsgen: 히어로에 7장(장르가 골고루 섞이게).

## 파라미터
