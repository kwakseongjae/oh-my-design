# spotlight-pointer — 포인터를 따라오는 스포트라이트

| | |
|---|---|
| 계열 | 커서 · 빛 |
| CSS-only | 아니오 — JS 22줄 (좌표 전달만) |
| 인라인 크기 | CSS 12줄 + JS 22줄 / 약 1.4KB |
| 다크/라이트 | 둘 다 — 다크는 흰색 알파 .16, 라이트는 **브랜드 색 알파 .10~.12**. 라이트에서 흰 광원은 보이지 않는다 |
| 라이선스 | 이 구현은 oh-my-design 자작, MIT |
| 난이도 | 하 |

## 무엇인가
포인터 위치를 `--fx-spot-x/y` 로만 넘기고, 실제 그리기는 CSS `radial-gradient` 가 한다.
JS 는 좌표 계산과 in/out 판정만 하고 스타일 계산을 하지 않는다.

## 왜 이 구조인가
카드마다 `mousemove` 리스너를 다는 흔한 구현은 카드 12장이면 리스너 12개 + 프레임당 12번의 레이아웃 조회다.
여기서는 window 리스너 1개 + `requestAnimationFrame` 으로 프레임당 1회 배치 갱신한다.

## 언제 쓰나
- 카드 그리드에서 "지금 어디를 보고 있는지" 시선 위치를 은근히 표시할 때
- 어두운 히어로에서 마우스가 있다는 사실 자체를 피드백할 때
- 표/리스트의 행 강조 대체 (배경색을 바꾸는 것보다 부드럽다)

## 금기
- **크기를 200px 미만으로 두지 않는다.** 손전등처럼 보이면 콘텐츠보다 효과가 먼저 읽힌다.
- 알파 0.25 초과 → 즉시 싸구려. 다크에서 .12~.18, 라이트에서 .08~.12.
- 무지개색/네온 광원은 게임 런처 신호다. 흰색 또는 브랜드 색 1개.
- 스포트라이트 안에서만 텍스트가 읽히는 설계 금지 (터치 기기에서 영영 못 읽는다).

## 접근성 / 폴백
- `@media (hover:none)` 에서 CSS 가 비활성, JS 는 `matchMedia('(hover:hover)')` 로 마운트 자체를 건너뛴다.
- 효과가 없어도 카드는 완전히 읽혀야 한다 (progressive enhancement).

## 파라미터
`--fx-spot-size`(광원 지름), `--fx-spot-color`, `--fx-spot-fade`

## 출처 / 계보
포인터 추종 스포트라이트는 2023~2025 React 이펙트 라이브러리들이 "Spotlight / Glare card" 이름으로 대중화한 어휘다.
여기 코드는 그 코드를 옮긴 것이 아니라 동일 기법을 vanilla 로 재작성하고 리스너 수를 O(1) 로 줄인 것.
