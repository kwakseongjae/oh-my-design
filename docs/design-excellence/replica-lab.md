# 레플리카 랩 — 레퍼런스를 단일 HTML 로 다시 지어 배우는 절차 (v1, 2026-09-05)

> 발단: Higgsgen r4 65점. 사용자: "레퍼런스 사이트들의 css나 전체 html들을 가져와서 그걸 직접 재현해보는
> 과정을 경험하면서 작업하면 어떨까 … 단순히 리서치에서 멈추지 말고, 단일 HTML로 해당 사이트를 모방하면서
> 효과와 에셋 배치, 구도 등을 학습하고 그걸 레퍼런스로서 사용해서 다음 랩들을 진행할 수 있게."
> 읽는 순서: 코퍼스(`reference-corpus/`) → 레플리카(`replicas/`) → 랩(`higgsgen/`, 그 다음 브리프들).

## 0. 왜 하는가

계측은 "무엇이 다른가"를 알려 주지만 "어떻게 만드는가"는 알려 주지 않는다.
r1~r4 는 규칙을 더하며 올라왔고, 규칙으로는 **질감**(스크롤의 감쇠, 화면이 살아 있는 느낌)이 안 잡혔다.
질감은 **다시 지어 봐야** 손에 남는다. 레플리카는 산출물이 아니라 **학습 장치**이고, 그 부산물(효과 스니펫·
구도 격자·타이밍 수치)이 다음 랩의 레퍼런스가 된다.

## 1. 절대 규칙 — 무엇을 가져오고 무엇을 가져오지 않는가

| 가져온다 (학습 대상) | 가져오지 않는다 (법·품질 양쪽) |
|---|---|
| 수치: 이징 곡선, duration, lerp 계수, 스크럽 지연, 주기·진폭, 스태거 간격 | 그들의 CSS·JS 원문 (한 줄도 붙여넣지 않는다) |
| 구조: 섹션 순서·높이(vh)·그리드·거터·정렬 축 | 그들의 이미지·영상·폰트·아이콘·로고·3D 에셋 |
| 구도: 미디어 비율·화면 점유율·텍스트와 이미지의 관계·여백 방향 | 그들의 카피(문장) — 자리표시자는 우리 문장으로 |
| 기법: 어떤 층이 무엇을 담당하는가, 무엇이 무입력으로 움직이는가 | 브랜드 색·워드마크·상표 |

레플리카는 **우리 에셋**(higgsgen 61장, 자작 SVG/캔버스)과 **우리 코드**로만 만든다.
결과물은 "저 사이트처럼 **움직이고 배치되는**" 페이지이지, 저 사이트의 복제가 아니다.
각 `replica.html` 하단에 `Study replica — original: <url> · assets and code are our own` 고지를 넣는다.
공개 배포하지 않는다(레포 내부 학습 자산).

## 2. 디렉터리

```
test-v2/content-runs/aphrodite/
  reference-corpus/<id>/     # 원본 캡처 (읽기 전용, 학습용)
  replicas/<id>/
    replica.html             # 단독 HTML, 렌더 시 네트워크 0
    notes.md                 # 학습 노트 (아래 §4)
    fidelity.json            # 원본 vs 레플리카 프로브 비교
    screenshots/             # 1440·390, 원본과 나란히
```

## 3. 충실도 — 눈이 아니라 프로브로 잰다

같은 도구로 원본과 레플리카를 재고 차이를 기록한다. 통과선은 지표별로 다르다.

| 축 | 도구 | 지표 | 통과선 |
|---|---|---|---|
| 스크롤 질감 | `scroll-feel.mjs` | 스무스 τ(ms) · 스크럽 lerp α · catch-up 프레임 · 속도 결합 속성 · 지터 | τ·α 는 원본의 **±25%**, 속도 결합은 유무 일치 |
| 자율 모션 | `ambient-motion.mjs` | 화면당 픽셀변화 %(0.6/1.5/3.0s) · 변화 그리드 셀 수 · 최강 요소 주기·진폭 | 픽셀변화 원본의 **±30%**, 주기 대역 일치 |
| 크기·구도 | `scale-probe.mjs` | 폴드 커버리지 · 지배도 · 화면당 요소 수 · 최대 서체 | 커버리지·지배도 원본의 **±20%** |
| 마감 | `landing-integrity.mjs` | LI-1~40 | 레플리카는 **면제**(원본이 우리 규칙을 안 지킬 수 있다) — 다만 차이를 노트에 적는다 |

**레플리카가 우리 규칙을 어기면 그것도 발견이다.** 규칙이 틀렸는지, 원본이 예외인지 노트에서 판정한다.

## 4. 학습 노트 규격 (`notes.md`, 한국어)

1. **한 줄 요약** — 이 사이트가 잘하는 단 하나.
2. **섹션 해부표** — 섹션 · 높이(vh) · 주 미디어 비율·점유율 · 텍스트 관계(겹침/나란히/관통) · 층(스크롤/유휴/호버/진입) · 액센트 사건.
3. **효과 목록** — 관찰된 동작 · 코퍼스 근거(파일·선택자·프로퍼티) · 추정 구현 · 우리 재구현 방법 · 크기(KB).
4. **타이밍 표** — duration · easing · delay · stagger · 주기 · 진폭 (실측값).
5. **에셋 역할표** — 몇 장이 어디에 어떤 비율로, 무엇을 증명하려고 쓰였는가. 우리 61장 중 무엇으로 대체했는가.
6. **재현 실패 목록** — 못 따라간 것과 이유(WebGL·유료 라이브러리·독점 에셋·시간).
7. **다음 랩으로 가져갈 것** — fx-library 후보, LC/LI 규칙 후보, 스토리보드 패턴. **여기가 이 문서의 존재 이유다.**

## 5. 절차

1. 코퍼스에서 대상 선정(다음 랩이 필요한 질감을 가진 사이트).
2. 원본을 프로브 3종으로 재고 `fidelity.json` 의 `original` 을 채운다.
3. 구조를 먼저 세운다(섹션·그리드·점유율) → 정지 상태에서 구도가 닮았는지 스크린샷 대조.
4. 그 위에 모션을 얹는다(스크롤 → 유휴 → 진입 → 호버 순, 층 예산은 우리 규칙대로).
5. 레플리카를 같은 프로브로 재고 `replica` 를 채운다 → 통과선 밖이면 수치를 고친다.
6. `notes.md` §7 을 쓰고, 거기서 나온 스니펫을 `fx-library/` 에, 규칙 후보를 코덱스에 올린다.

## 6. 다음 랩과의 관계

- 랩(브리프 실행)은 레플리카를 **레퍼런스로 인용**한다: "S3 의 스크럽 감쇠는 `replicas/<id>` 의 α=0.11 을 따른다".
- 스토리보드 게이트에 열을 추가하지 않는다 — 대신 각 효과의 **출처를 레플리카 번호로** 적게 한다.
- 레플리카는 버전을 올리지 않는다. 원본이 바뀌면 새 캡처 + 새 레플리카(`<id>-2`).
