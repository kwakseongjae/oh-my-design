# /hangul 바이럴 게시물 (2026-11-05)

오너가 영상을 찍어 Threads에 올리고, 근거는 댓글 타래로 잇는다. 이 문서는 구성, 촬영 대본, 글 초안, 이미지 목록을 담는다. 수치는 `docs/research/2026-10-25-hangul-report/`(로컬, 미커밋)의 3차 평가에서 가져왔다. 트래픽 수치는 이 문서에 적지 않는다.

## 1. 참고한 형식: 모델·제품 출시 타래

Anthropic과 Google(DeepMind)이 새 모델이나 제품을 낼 때 X·Threads에 올리는 글은 거의 같은 뼈대를 쓴다.

| 자리 | 출시 타래에서 하는 일 | 우리 적용 |
|---|---|---|
| 본문 | 이름과 주장 한 줄, 영상 하나. 링크는 넣지 않는다 | 실제로 일어난 일 하나(지어낸 정책 3개) + 오너가 찍은 영상 |
| 댓글 1 | 가장 강한 시연 하나를 이미지·클립으로 | 전자결재 문구 비교 카드(실제 평가 결과물) |
| 댓글 2 | 벤치마크 그래프 한 장, 비교 기준을 같이 | 지어낸 사실 5.40 → 2.65, 20/20 카드 |
| 댓글 3 | 다른 쓰임새 시연 | 예시 화면 카드(같은 화면, 다른 한국어) |
| 댓글 4 | 한계·안전 언급(Anthropic이 자주 넣음) | 평가의 한계를 한 문단으로 |
| 마지막 | "지금 쓸 수 있다" + 시작 방법 한 줄 + 링크 | 설치 명령 한 줄 + `/go/` 링크 |

원칙은 세 가지다.
- 댓글 하나에 주장 하나, 이미지 하나.
- 링크는 맨 마지막 댓글에만 둔다. 본문에 링크가 있으면 노출이 줄고, 읽는 사람이 댓글을 타고 내려오며 근거를 보게 하는 것이 이 형식의 핵심이다.
- 숫자는 비교 기준과 조건을 함께 보여 준다. 25점 만점 총점(21.75 → 22.55)은 차이가 작아 앞세우지 않는다.

## 3. 영상 촬영 대본 (30~40초, 세로 9:16)

**권장: 같은 요청을 두 번 실제로 돌려 찍기.** 진짜 결과물이라 가장 설득력이 있다.

준비
- 빈 폴더 두 개. A에는 아무것도 설치하지 않는다. B에는 `npx skills add kwakseongjae/oh-my-design --skill hangul`만 설치한다.
- 두 폴더 모두 사용자 설정·CLAUDE.md가 섞이지 않게 한다.
- 요청문(두 폴더에 똑같이, 스킬 이름은 부르지 않는다. 20/20 수치가 이 조건이다):
  > 사내 전자결재 앱의 화면 문구를 ko.json으로 써 줘. 결재 요청 확인 창, 부재 중 대결 지정, 반려 완료 알림, 결재 기한 초과 알림이 필요해.
- 결과는 매번 달라진다. 두세 번 돌려 보고 실제로 나온 것을 그대로 쓴다. 고치거나 연출하지 않는다.

| 시간 | 화면 | 자막 |
|---|---|---|
| 0~3초 | A의 결과가 올라오는 터미널 | AI한테 한국어 화면 문구를 맡겼어요 |
| 3~14초 | A 결과를 확대, 문제 줄에 동그라미 | 요청에 없던 정책 / 해요체 사이 합쇼체 / 하는 일이 안 보이는 버튼 |
| 14~26초 | B에서 같은 요청, 결과 | 같은 요청, /hangul 설치만 했어요 |
| 26~34초 | A와 B 나란히 | 요청한 사실만, 말투 하나로 |
| 34~38초 | 끝 화면 | 설치 한 줄 · 링크는 댓글에 |

**대안: 페이지 녹화.** 휴대폰으로 `oh-my-design.kr/ko/hangul`을 열고 "스킬 없이 ↔ /hangul" 전환을 누르는 장면. 이 경우 본문과 자막에서 "예시 화면"이라고 밝힌다.
