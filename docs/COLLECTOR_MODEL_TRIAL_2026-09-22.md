# 수집 단계에 어느 모델을 쓸 것인가 — 진행 중인 실측 (2026-09-22)

오너 요청: 계속하는 작업에 하나씩 적용해보면서 **수집에 적합한 모델을 토큰 효율까지 보고**
고르기. 이 문서는 한 번에 끝내는 보고서가 아니라 **회차를 쌓는 기록**이다.

## 0. 먼저 — 무엇을 위임할 수 있는가

수집은 한 덩어리가 아니다. 네 단계고, **위임 가능성이 전혀 다르다.**

| 단계 | 판단 | 오판의 대가 | 위임 |
|---|---|---|---|
| ① 스카우팅 | 낮음 | **후보 하나 놓침** | **가능** |
| ② 심층 프로브 | 중간 (순서가 결과를 바꾼다) | 틀린 상태값 | 조건부 |
| ③ 분리 판정 | **높음** | **틀린 레퍼런스** | **불가** |
| ④ 저작 | 높음 | 틀린 레퍼런스 | 불가 |

③을 위임하지 않는 근거는 추측이 아니라 **하루치 기록**이다. 오늘 카탈로그를 구한 여섯 건이
전부 원값을 직접 본 결과였다:

```
#005fcc가 DeepSeek가 아니라 크롬 기본값        ← `auto` 한 글자로 갈렸다
Chatwork CTA로 잰 것이 Marketo 폼 버튼
컨트롤 [0]의 mousedown이 [1]의 focus를 오염
자동 포커스된 입력이 "상태 없는 컨트롤"로 보임
#645b4a를 믿기까지 세 번 확인
JAL 최다 렌더 본문색 oklch(0.145 0 0)이 shadcn 기본값
```

요약 보고로는 **하나도 못 잡는다.** 그래서 이 실험의 대상은 **①**이다.

## 1. 회차 1 — 스카우팅 (JP 웨이브 3, 후보 12)

### 설계

세 팔이 **바이트 동일한 입력**(md5 동일한 후보 목록 3부)에 **동일한 스크립트**
(`web/scripts/scout-candidates.mjs`)를 돌린다. 스크립트는 **숫자만 내고 판정하지 않는다** —
판정이 곧 측정 대상이기 때문이다.

| 팔 | 모델 | 지시 |
|---|---|---|
| A | haiku | 전체(함정 체크리스트 5개 포함) |
| B | sonnet | 전체(동일) |
| C | sonnet | **간결**(체크리스트 없음) |
| 대조군 | opus (본 세션) | — |

B와 C를 나눈 이유: 품질을 지탱하는 게 **모델인지 체크리스트인지** 분리하기 위해서다.
이게 안 갈리면 "어느 모델"이라는 질문 자체가 잘못 놓인 것이다.

### 정답지 (대조군이 직접 실행 + 모호한 네임스페이스 4곳 추가 확인)

```

                                    → JAL과 같은 "칠하는 대상별" 4가족 구조
        zenn       own=129 ctrl=5   --c-* 가 자체(--c-button-share-hover-bg 같은 컴포넌트 단위)
        qiita      own=127 ctrl=8   --color-*110 + --advent-*(어드벤트 캘린더, 명백히 자기 것)
        crowdworks own≈179 ctrl=13  **196이 아니다 — --fa-* 17개는 Font Awesome**
                                    --z-* 91(초세밀 z-index) · --aicw-* 56(브랜드) ·
                                    --paragraph-* 16(font 단축 속성 통째로 토큰화)
얇음    coconala   own=119 ctrl=3   램프는 자기 것이나 fw=183(Tailwind) 우세, 컨트롤 3
        hatena     own=48  ctrl=0   진짜지만 **컴포넌트 0**
REJECT  ana 4 · lycorp 3 · cyberagent 0 · paidy 0 · wealthnavi 0 · m3 0
```

**채점 포인트 3개** — 숫자만 읽으면 못 잡고, 이름을 봐야 잡히는 것들:

1. **crowdworks의 `own=196`은 부풀려져 있다.** `--fa-*`는 Font Awesome이다.
   스크립트의 프레임워크 목록에 `fa`가 없어서 자체로 셌다. **도구가 놓친 것을
   읽는 쪽이 잡아야 한다.**
2. **lycorp·cyberagent는 토큰이 0~3인데 자체 서체가 있다**(LINESeedJP, CA Sans).
   그냥 기각이 아니라 **기록할 값어치가 있는 기각**이다.
3. **hatena는 ctrl=0** — 등재는 되지만 토큰 전용(huawei·douyin·smartbank과 같은 길).

### 결과

세 팔 모두 **핵심 VIABLE 3건(newspicks · zenn · qiita)을 정확히** 집었다. 거기서는 안 갈린다.
갈린 건 **도구가 놓친 것을 읽는 쪽이 잡느냐**다.

| 채점 항목 | haiku + 체크리스트 | sonnet + 체크리스트 | sonnet + 간결 |
|---|---|---|---|
| VIABLE 3건 | ✅ 3/3 | ✅ 3/3 | ✅ 3/3 |
| **crowdworks `--fa-*`가 Font Awesome** | ❌ 못 봄 | ✅ 짚음 | ✅ 짚음 |
| crowdworks 결론(=viable) | ❌ 기각 | ⚠️ **flag**(보존) | ❌ 기각 |
| lycorp 자체 서체 | ❌ | ✅ 언급 | ✅ **+ 다음 수까지** |
| hatena ctrl=0 | ❌ (locale로 오인) | ✅ | ✅ |
| 엉뚱한 규칙 인용 | ❌ m3를 locale로 | — | — |
| 잘못된 단서 | — | — | ⚠️ ana "차단" |

**haiku는 체크리스트를 받고도 셋 다 놓쳤다.** 그리고 특유의 실패가 있다 — `lang`이 비면
**substantive 이유 대신 locale 규칙을 집는다**(m3는 `own=0`이 이유인데 "wrong locale"로,
hatena는 `ctrl=0`이 이유인데 "locale detection failed"로 적었다). 규칙 목록을 **패턴으로
소비하고 데이터로 검증하지 않는다.**

**체크리스트는 품질을 지탱하지 못했다.** sonnet은 체크리스트가 없어도 같은 함정을 잡았고,
haiku는 있어도 못 잡았다. 이 작업에서 **좋은 지시가 약한 모델을 구제하지 못한다.**

#### sonnet-terse의 잘못된 단서 — 반증했다

> "ana는 JAL처럼 헤드리스 차단일 수 있으니 Aside로 재시도하라(JAL은 로컬 0, Aside 416)"

Aside로 열어봤다: **토큰 4개로 동일**(`--color-booking-primary` 등), 컨트롤 29개 정상.
**차단이 아니라 진짜로 토큰이 적다.**

**구별점을 놓쳤다**: JAL은 페이지가 **아예 안 열렸다**(navigation error). ana는 로컬에서도
`200 · ctrl=32 · 2,810자`였다. **차단된 페이지는 컨트롤 32개를 주지 않는다.** 자기 데이터에
반증이 들어 있었는데 최근 사례에 끌려갔다.

다만 **flag였지 reject가 아니었고, Aside 호출 한 번으로 반증됐다.** 싸게 틀리는 건 flag의
올바른 성질이다 — 기각했다면 후보를 잃었을 것이다.

#### 보고서 크기(= 내 컨텍스트 비용)와 시간

| | 보고서 | 벽시계 |
|---|---|---|
| haiku | ~950자 | ~6분 |
| sonnet + 체크리스트 | ~1,500자 | ~7.5분 |
| sonnet + 간결 | ~1,800자 | ~7분 |

**시간은 거의 같다** — 스크립트가 병목이라 모델이 아니라 브라우저가 시간을 쓴다.
보고서 크기는 sonnet이 크지만 **그 차이가 곧 잡아낸 함정**이다. 950자짜리 haiku 보고서는
싸지만, 그걸 믿었으면 **crowdworks를 잃고 hatena를 엉뚱한 이유로 보류**했을 것이다.

**한 가지 덧붙일 것**: 스크립트의 프레임워크 목록에 `fa`가 없어서 `--fa-*` 17개를 자체로

안 보이게 된다.** 목록은 고치되, 위임 판정의 기준은 "숫자를 읽었나"가 아니라
**"이름을 봤나"로 남긴다.**

## 2. 토큰 회계를 어떻게 셀 것인가

서브에이전트의 **내부 토큰은 내 컨텍스트에 안 들어온다.** 들어오는 건 **최종 보고서**뿐이다.
그래서 두 가지를 따로 센다:

- **내 컨텍스트 비용** = 보고서 길이. 위임하면 모델과 무관하게 줄어든다.
- **총 비용** = 내부 토큰 + 보고서. 모델에 따라 갈린다.

그리고 **틀린 보고의 비용은 토큰이 아니다** — 잘못 등재된 레퍼런스이거나, 놓친 후보다.
그래서 이 표의 마지막 칸은 항상 **정확도**여야 한다.

## 3. 회차 2 — 심층 프로브(②)를 sonnet에 위임 (zenn)

**설계**: 실제 작업은 위험에 두지 않는다. newspicks(가장 강한 후보)는 **내가** 재고,
zenn을 sonnet에 맡긴 뒤 **내가 독립 재측정**해서 대조했다.

### 결과 — **②도 위임할 수 있다. 단, 헤드라인 주장은 검증하고 쓴다.**

보고가 정확했다. 산술까지 맞았다(`#000000d1`→`rgba(0,0,0,.82)`,
`99rem`→`1584px`, `#8f9faa`→`rgb(143,159,170)`).

**함정을 스스로 처리했다:**

| 상황 | 대응 |
|---|---|
| `styleSheets[].cssRules`가 0을 반환(CDN이 CORS로 막힘) | `getComputedStyle`로 전환. **스타일시트 텍스트로 접근했으면 "토큰 없음"이라 보고했을 사이트에서 129개를 찾았다** |
| `--text "#fff"`가 `<body>`를 잡음(**내가 오늘 만든 도구의 함정**) | `--height 40`으로 고정 |
| `outline: none`을 브랜드 부재로 볼 것인가 | **`auto`가 아님을 rest와 대조해 확인** — §2.5 규칙을 정확히 적용 |
| "못 쟀음"과 "변화 없음" | 분리해서 보고. "all 4 states measured, nothing unmeasured"라고 명시 |

**추가로 잡은 것**: zenn 자신의 오타 `--c-button-danger-forcus-border`(sic),
`-rgb` 채널 삼중항이 하나뿐이라는 것, Inter가 `--font-latin-hero`에만 묶여 있고 일본어는
OS 스택으로 떨어진다는 것, census n=2227이 절단이 아니라 **페이지 전체 요소 수**라는 것.

**UNCERTAIN 절이 정직했다**: 다크 모드 미측정(헤더에 토글이 있다), 나머지 5개 버튼 변형은
홈에 안 뜬다 — 셋 다 실제 한계이고 내가 그대로 레퍼런스 한계에 옮겨 적었다.

### 그런데 검증이 결론을 바꿨다

보고: *"primary 버튼은 authored focus 링이 없다(`outline-style: none`)."* — 맞다.

하지만 "링이 없다"에는 **무해한 읽기**(브라우저 기본이 원래 없었다)와 **심각한 읽기**
(작성자가 껐다)가 있고, 보고만으로는 안 갈린다. **진짜 Tab 키를 눌러** 봤더니 Zenn 로고
링크에 `outline: rgb(0, 95, 204) auto 1px`가 뜬다 — **크롬 기본값이 이 페이지에 살아 있다.**

즉 **버튼 컴포넌트가 그걸 끄고**, secondary만 box-shadow로 대체하고 primary는 대체물이 없다.
판독이 소견이 됐다. **위임된 실행은 이 확인을 할 수 없었다** — 지시에 없던 검사였기 때문이다.
