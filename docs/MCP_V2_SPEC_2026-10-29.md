# MCP v2 명세 — 수집한 레퍼런스 데이터를 근거와 함께 제공하는 커넥터

작성 2026-10-29 · 상태: **초안, 오너 결정 대기(§10)** · 관련: `docs/WORKER_PLAN_2026-10-29.md` §6·§8

## 0. 요약

AI 에이전트(Claude, Cursor, Codex 등)가 대화 안에서 oh-my-design 카탈로그(530개, verified 308개)를 찾고, 토큰·컴포넌트·상태·서사를 **근거와 검증 상태가 붙은 채로** 가져가게 하는 읽기 전용 원격 커넥터입니다.

- **주는 것:** 우리가 수집·검증한 데이터만 제공합니다(오너 결정 10/29). 정본 DESIGN.md, `reference.json`의 토큰·컴포넌트·claim·출처, 검증 상태와 날짜, 레지스트리 메타, 상세 페이지 주소입니다.
- **주지 않는 것:**
  - 임의 URL 분석·캡처: 캡처 도구는 내부 수집 파이프라인 전용입니다.
  - 생성·변형·쓰기: 커스터마이즈는 10/13에 제거했습니다.
  - 로그인과 개인화.
- **v1과 다른 점:**
  - 문서 전체 대신 토큰·상태 단위로 줍니다.
  - 값마다 출처가 붙습니다.
  - 모르는 값은 비워 두고 `absent`로 알립니다.
  - verified를 먼저 보여 줍니다.
  - 한글 이름으로 검색할 수 있습니다.
- **호스팅:** v1처럼 같은 Vercel 앱의 `/api/mcp`에서 Streamable HTTP, 무상태로 운영합니다. 데이터가 빌드 때 고정되므로 비용이 거의 들지 않습니다.

## 1. 왜 지금인가

- **채널:**
  - 성장 계획(10/13)이 AI 인용 채널로 MCP 커넥터를 다시 적어 두었습니다.
  - 상세 페이지에는 이미 봇·AI 요청이 한 달 8.9천 건 들어옵니다(`docs/REDESIGN_DECISIONS_2026-10-01.md`).
  - llms.txt를 가장 많이 읽는 것도 Claude Code입니다.
- **해자:** 지금 다른 도구는 사용자가 디자인 시스템을 직접 가져와야 합니다. 이름 붙은 브랜드 카탈로그를 측정 근거와 함께 대화 안에 넣어 주는 곳이 우리 자리입니다.
- **선행 조건 충족:** Core v2 전환(7/14) 때 v1을 내린 이유는 데이터 형태가 바뀌어서였습니다. 이제 `reference.json`(format 3.0.0)에 claim 단위 근거가 있어서, 값마다 출처를 붙여 줄 수 있습니다.

## 2. v1에서 가져올 것과 바꿀 것

v1은 2026-06-18 출시, 07-14 퇴역했습니다(`d4bb3ace`). `/api/mcp`는 지금 410을 돌려줍니다.

| | v1 | v2 |
|---|---|---|
| 도구 | `list_references`, `search_by_vibe`, `get_design_md` | §5의 6개 |
| 단위 | 문서 전체 | 문서·섹션·토큰 그룹·컴포넌트 |
| 근거 | 결과마다 상세 페이지 링크 | 값마다 claim 경로와 출처(URL, 측정 방식, 날짜) |
| 품질 표시 | 없음 | `verified_v2` / `partial` / `legacy`와 검증일, 다음 재검증일 |
| 모르는 값 | 문서에 있던 대로 | 필드를 빼고 `absent` 목록으로 알림 |
| 검색 | 키워드 → bge-m3 의미 검색 | 같은 방식에 한글 이름(`displayName`)과 verified 우선 정렬 추가 |
| 운영 | Origin 허용 목록, IP당 60회/60초, 개인정보·약관 페이지, 질의 원문 미기록 | 그대로 가져옴 |

- **정리할 것:**
  - `web/scripts/build-embeddings.mjs`는 v1 소비처(`catalog.ts`)가 지워진 뒤에도 Vercel 빌드마다 돌고 있습니다. v2 의미 검색에서 다시 쓰거나, 쓰지 않기로 하면 빌드에서 뺍니다.
  - `/privacy`에는 "Retired Claude connector (MCP)" 절이 남아 있어서 v2 출시 때 고쳐 씁니다.

## 4. 데이터 계약

### 4.1 모든 응답에 붙는 것

```json
{
  "catalog": { "version": "2.0.5", "reference_ast": "cc593833f856", "generated": "2026-10-29" },
  "notice": "Descriptions of public product surfaces for design reference. Not affiliated with or endorsed by the companies named."
}
```

- `reference_ast`는 `build-reference-ast`의 카탈로그 해시입니다. 같은 값이면 같은 답을 돌려줍니다.
- `notice`는 상표·추천 오해를 막습니다. 토스 BSD-3 건과 같은 원칙입니다.

### 4.2 레퍼런스 요약 객체

```json
{
  "id": "sixt",
  "name": "SIXT",
  "display_name_ko": null,
  "country": "DE",
  "category": "automotive",
  "homepage": "https://www.sixt.de/",
  "status": "verified_v2",
  "verified_at": "2026-10-29",
  "next_reverify_at": "2027-04-27",
  "urls": {
    "page": "https://oh-my-design.kr/design-systems/sixt",
    "page_ko": "https://oh-my-design.kr/ko/design-systems/sixt",
    "raw": "https://oh-my-design.kr/sixt/design.md"
  }
}
```

- `display_name_ko`는 레지스트리의 `displayName`이 한글일 때만 채웁니다. 음역은 만들지 않습니다(AGENTS.md 한국어 페이지 규칙).
- `page_ko`는 `hasKoDetail()`(`web/src/lib/i18n/ko-detail.ts`)이 참일 때만 넣습니다. 라우트·사이트맵과 같은 판정을 씁니다.

### 4.3 근거가 붙은 값

```json
{
  "path": "colors.brand-orange",
  "value": "#ff5000",
  "evidence": {
    "method": "computed-style",
    "surface": { "id": "home", "url": "https://www.sixt.de/" },
    "source": { "id": "home-live", "kind": "product-surface", "url": "https://www.sixt.de/" },
    "captured": "2026-10-29"
  }
}
```

`reference.json`의 `verification_v2.claims[path]`를 `sources`·`surfaces`와 이어 붙인 것입니다. claim이 없는 값은 `evidence: null`이 아니라 `"evidence": { "status": "unsourced" }`로 표시합니다. verified 레퍼런스는 게이트상 이런 값이 없습니다.

### 4.4 규칙

1. **모르는 값은 비웁니다.** 레퍼런스에 없는 필드는 응답에서 뺍니다. `null`로 채우거나 비슷한 값으로 바꾸지 않습니다. 요청한 그룹이나 상태가 없으면 `absent: ["spacing", "components.search.pressed"]`로 알려, 에이전트가 빈칸을 지어내지 않게 합니다.
2. **상태가 데이터와 같이 다닙니다.**
   - verified가 아닌 레퍼런스의 토큰·컴포넌트에는 `"trust": "unverified"`와 이유 코드(`reason_codes`)를 붙입니다.
   - 검색은 기본적으로 verified를 먼저 정렬합니다.
3. **서체 근거 등급을 그대로 줍니다.** 공식 제품 사용 / 라이브 로드 / 공식 배포 자산 / 선언만 / 미확인. 대체 서체는 측정 근거가 있는 것만, `"label": "substitute — not the brand face"`와 측정값을 붙여 줍니다(G3). 대체 서체를 브랜드 서체처럼 내보내지 않습니다.
4. **정본 바이트를 보존합니다.** `get_design_md` 전체 응답은 `/<id>/design.md`가 서빙하는 정본과 같은 바이트입니다(raw 라우트가 덧붙이는 꼬리말은 빼고). 섹션 응답은 v3 제목 단위로 정확히 잘라 줍니다.
5. **결과마다 인용 주소를 줍니다.** 상세 페이지 주소(`urls.page`)는 모든 결과에 들어갑니다.
6. **판단하지 않습니다.** 비교 도구는 측정값을 나란히 놓을 뿐 점수나 추천을 매기지 않습니다.

## 5. 도구 (v2.0)

모든 도구에 `annotations: { readOnlyHint: true, idempotentHint: true, openWorldHint: false }`를 붙입니다. 응답은 `structuredContent`(+`outputSchema`)와, 호환용 같은 내용의 JSON 텍스트로 보냅니다.

| 도구 | 입력 | 출력 |
|---|---|---|
| `search_references` | `query?` (언어 무관 텍스트), `country?[]`, `category?[]`, `status?` (`verified` 기본 우선, `any`), `limit?` (≤20, 기본 8) | 요약 객체 목록 + `match` (어느 필드가 맞았는지) + `score` |
| `get_reference` | `id` | 요약 + 섹션 목차(v3 제목, 글자 수) + 개수(토큰 그룹별, 측정된 상태가 있는 컴포넌트 수) + 출처 목록 |
| `get_design_md` | `id`, `sections?[]` (v3 제목: Overview, Colors, Typography, Layout, Elevation & Depth, Motion & Easing, Components, Do's and Don'ts, Voice & Tone, Agent Prompt Guide, Governance) | 마크다운. 전체는 정본 바이트, 부분은 제목 단위 |
| `get_tokens` | `id`, `groups?[]` (`colors`, `typography`, `rounded`, `spacing`, `shadow`, `motion`) | 그룹별 §4.3 값 목록, `absent`, 서체 근거 등급 |
| `get_component_states` | `id`, `component?` | 컴포넌트별 type, 쉬는 상태 값, **측정된** hover/pressed/focus만, `not_measured` 목록, 근거 |
| `compare_references` | `ids` (2~4), `aspects?[]` (`colors`, `typography`, `radius`, `components`, `motion`) | 측정값을 나란히 놓은 표. 없는 값은 `absent`로 표시 |

- **잘못된 id:** 비슷한 이름으로 바꿔 답하지 않습니다. `unknown_reference` 오류와 함께 `search_references`를 쓰라는 안내를 돌려줍니다(`omd-reference-query`의 "unknown brand 거부"와 같은 원칙).
- **검색:**
  - 키워드 검색 대상은 id, 이름, 한글 이름, 국가, 분야, Overview 첫 문단입니다.
  - 임베딩(bge-m3)이 있으면 의미 검색 점수를 섞습니다. 없으면 키워드만 씁니다.
  - "토스", "toss", "calm blue fintech" 모두 toss를 찾아야 합니다.
- **v2.0에서 뺀 것:**
  - CSS 변수·Tailwind 내보내기: 값을 바꾸지 않는 변환이지만 이름 규칙을 정해야 해서 Phase 2로 미룹니다.
  - MCP resources·prompts: 원격 커넥터는 도구만으로 충분합니다.

## 6. 전송·운영

- **엔드포인트:** `https://oh-my-design.kr/api/mcp`. Streamable HTTP, 무상태, Node 런타임입니다. v1 설정을 가진 클라이언트는 410 대신 바로 v2를 받습니다(§10 D1).
- **구현:** 공식 `@modelcontextprotocol/sdk`의 Streamable HTTP 서버 또는 `mcp-handler`를 씁니다. 지금 `web/package.json`에는 둘 다 없고 `zod` 4만 있습니다. 둘 중 하나를 고르고 버전을 고정합니다.
- **데이터 로딩:**
  - 빌드 때 생성된 데이터를 함수 번들에 넣습니다: `registry.generated.ts`, `reference-quality.generated.ts`, `references/<id>/reference.json`, `DESIGN.md`.
  - 런타임에 파일 시스템을 훑지 않습니다. raw 라우트(`web/src/app/r/[id]/route.ts`)와 같은 읽기 방식을 씁니다.
- **보안:**
  - 인증은 없습니다. 공개 데이터이고 읽기 전용입니다.
  - Origin 허용 목록을 둡니다(MCP 사양의 DNS rebinding 대응, v1과 동일).
  - IP당 60회/60초 제한을 Redis로 걸고, Redis 장애 시에는 열어 둡니다.
  - 응답 크기 상한은 256KB로 둡니다(가장 큰 DESIGN.md도 그 아래입니다).
- **개인정보:**
  - 질의 원문, IP, 계정을 기록하지 않습니다.
  - 도구별·레퍼런스별 호출 수만 KV에 집계합니다(`omd:mcp:v2:*`).
  - `/privacy`·`/privacy/ko`의 커넥터 절을 고쳐 씁니다.
- **비용:**
  - Vercel Hobby 함수 호출 비용만 듭니다.
  - 임베딩은 빌드 때 한 번(카탈로그 전체 약 $0.005), 검색 질의마다 한 번(bge-m3, $0.01/백만 토큰)입니다. 키가 없으면 키워드로 떨어집니다.

## 7. 측정

- **Phase 0(지금 바로):** 410 핸들러에 KV 카운터 한 줄을 넣어, 퇴역한 커넥터로 들어오는 요청 수를 셉니다(WORKER_PLAN §6의 수요 확인). 응답은 그대로 410입니다.
- **출시 뒤 주간 지표:**
  - 도구별 호출 수
  - 서로 다른 레퍼런스 수
  - verified 비중
  - 오류율(`unknown_reference` 포함)
  - p95 지연
- **보지 않는 것:** 질의 원문, 사용자 식별.
- `scripts/growth/snapshot.mjs`에 MCP 카운터를 더합니다.

## 8. 검증

- **계약 테스트**(`web/src/app/api/mcp/route.test.ts`를 v2로 교체). 표본 레퍼런스 3개를 씁니다: verified 한국(toss), verified 유럽(sixt), legacy 하나.
  - `get_design_md` 전체가 정본과 같은 바이트인지.
  - 응답에 `null`로 채운 필드가 없고, 빠진 값은 `absent`에 있는지.
  - verified 레퍼런스의 모든 토큰 값에 근거가 있는지.
  - 측정 안 된 상태가 `not_measured`로만 나오는지.
  - "토스"로 toss를 찾는지.
  - 없는 id가 오류로 끝나는지(근사 금지).
  - 61번째 호출이 429인지.
  - 낯선 Origin이 403인지.
- **수동 확인:** MCP Inspector, Claude.ai 사용자 커넥터 추가 시험(오너), Claude Code `claude mcp add --transport http`.
- **게이트:** 개수 문구는 `REFERENCE_COUNT` 상수를 씁니다. 코드에 숫자를 박지 않아 `check-counts`가 계속 맞습니다.
