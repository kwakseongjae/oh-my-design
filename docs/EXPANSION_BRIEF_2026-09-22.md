# 확충 작업 계획 (2026-09-22)

`EXPANSION_PLAN_2026-09-20`의 1~4단계는 끝났고 5단계도 사실상 끝났다. 이 문서는 **6단계부터
실제로 무엇을 어떤 순서로 하는가**이고, 어제·오늘 측정으로 바뀐 것을 반영한다.

## 1. 출발점

```
441 = KR 203 · US 109 · TW 63 · JP 44 · UK 12 · CN 5 · IT 2 · FR 2 · DE 1
목표 700  →  +259
등급: verified 144 · partial 184 · legacy 113
```

§C.3의 정직한 상한은 **630~710**이고 700은 그 안이다. 어제 어휘 재조사는 이 밴드를
**낮추지 않았다** — CN `+30`을 "과소평가"로 판정했다(텐센트만 브랜드북 14권).

## 3. 오늘 측정이 계획을 바꾼 두 가지

### (a) 기존 카탈로그의 깊이 상한은 낮다 — 예산을 확충으로

```
공식 디자인 시스템(ds.url) 선언 비율:  verified 65/141 = 46%  vs  미검증 21/297 = 7%
표면 스윕 2종(DNS 1,782 프로브 + GitHub org 77개) 결과 도달 가능: 약 9건
```

카탈로그는 디자인 시스템을 운영하는 회사를 **이미 다 걷어갔다.** 남은 297건은 consumer-tech
88·fintech 43·ecommerce 30 — 애초에 발행하지 않는 브랜드다. **표면 없는 브랜드의 `partial`은
틀린 상태가 아니다.**

### (b) 무엇이 verified를 결정하는가 — **내가 틀렸던 가설을 정정한다**

어제 나는 "제품 시스템과 마케팅을 섞으면 verified에 못 간다"고 적었다. **데이터로 확인하니
틀렸다.**

| | 도메인 | 등급 |
|---|---|---|
| krds | 마케팅만 | **verified** |
| smarthr | 디자인시스템만 | **verified** |
| pixiv · serendie | **둘 다** | **verified** |
| cybozu | 마케팅만 | partial |
| asana · sendbird | **둘 다** | partial |

**도메인 수는 등급을 예측하지 못한다.** 실제 예측자는 하나다 —
**선언한 인터랙티브 컴포넌트 전부에 관측된 상태가 있는가.**

- serendie: 컴포넌트 **1개** 선언(1/1/1) → verified
- asana: 12개 선언, 2개가 상태 없음 → partial
- sendbird: 13개 선언, 3개가 상태 없음 → partial

> **확충 규칙**: 컴포넌트를 **적게** 선언하라는 뜻이 아니다. **상태를 측정하지 못한
> 컴포넌트를 선언하지 말라**는 뜻이다. 측정한 만큼만 선언하면 verified로 간다.

## 4. 시장별 배분

| 시장 | 현재 | §C.3 여력 | 재조사 보정 | 이번 배분 |
|---|---|---|---|---|
| **CN** | **5** | +30 | **과소평가** — 텐센트 브랜드북 14권, 하이얼·화웨이·샤오미가 추정 밖 | **+30 (1순위)** |
| **JP** | 44 | 115~160 | 제품 여력 불변, 아이덴티티 +7 | +40 (2순위) |
| **TW** | 63 | **신규 0 권장** | 제품 기준 0 유지, 아이덴티티 13 | **신규 0** |
| **KR** | 203 (46%) | 47~80 | — | **보류** — 편중부터 해소 |
| 기타(US/EU) | 126 | — | — | 기회편성 |

**CN이 1순위인 이유**: 5건뿐이라 공백이 가장 크고, **proof gate가 어제 열렸으며**
(`REGIONAL_PROOF_COUNTRIES`에 CN 추가), 라이브러리/브랜드 판정 규칙(넌센스 경로 대조군)이
바로 CN을 위해 쓰였다. 게이트 밖에서 5→35로 키우면 되돌릴 수 없다 — **게이트가 먼저 선 지금이
정확한 타이밍**이다.

**CN의 함정 두 가지는 이미 문서화돼 있다**: ① 후보 10건을 전부 기각한 전력(TDesign·Arco·Semi·
Vant는 **라이브러리**다) ② `bytedance.com/arco`가 200을 주지만 넌센스 경로도 **바이트 단위로
같은** 6,667자를 준다. **대조군 없이 200을 신뢰하지 않는다.**

## 5. 작업 방식

`scripts/wave-run.mjs` — **웨이브당 5브랜드**(16-wide는 레이트리밋). 브랜드마다
워커 → 게이트 → F3 → 기계검사 → 검토 → (개정 → 재실측) 체인을 독립 실행한다. 층 단위 직렬은
웨이브 44에서 사고를 냈다(같은 브랜드에 검토·개정 동시 투입).

**브랜드당 선정 체크리스트** (오늘 얻은 것을 반영):

1. **라이브러리인가 브랜드인가** — 그 이름의 제품/플랫폼 페이지를 회사 도메인에서 열되
   **넌센스 경로 대조군을 같이** 연다(`AGENTS.md` 하드룰).
2. **측정 가능한 표면이 있는가** — `index.json`(스토리북)은 catch-all이 흉내낼 수 없어 확정적.
   토큰 사이트는 **자기 네임스페이스** 커스텀 프로퍼티인지 본다(Tailwind `--tw-*` 355개는
   그 사이트가 아니라 프레임워크다).
3. **상태를 잴 수 있는 컴포넌트가 몇 개인가** — 그 수만큼만 선언한다(§3b).
4. **CN/JP/TW/KR이면** 브랜드 소유 지역 Tier-1 **2개 이상**(proof gate).
5. **역할 이름을 렌더러 어휘에 맞춘다** — 본문색은 `foreground`여야 한다.
   `selectForeground`가 받는 건 `foreground`·`heading`·`ink`·`body`뿐이고, `text`로 지으면
   상세 페이지의 foreground 슬롯이 **빈 채로 렌더된다**. (pixiv·weibo·ctrip에서 세 번 반복한
   실수. `src/lib/references/normalize.ts`의 셀렉터가 정답지다.)
6. **CREATE 절차**: `data/reference-fingerprints.json` + **삼중 미러**(`.claude/data`·`.codex/data`) ·
   `design-md/<id>/` · `packages/mcp/data/references/<id>/` · 티어 카운트 3개 surface.

**계측기 규율**(오늘 6건의 오류에서): 라이트/다크 섞임 → `getComputedStyle(:root)` ·
값 역인덱스 금지, 이름으로 조회 · 스토리북 0×0 로더 버튼 · 래퍼 div · 라이브 앵커 press는
클릭이라 네비게이션 억제 필요 · 쿠키 배너는 브랜드 컴포넌트가 아니다(수락하지 말고 숨긴다).

## 6. 권장 순서

1. **CN 웨이브 1 (5건)** — 후보 선정부터. 기각 10건을 다시 열지 말고 §5 체크리스트로 새로 판정.
   **5건으로 파이프라인이 CN에서 도는지 먼저 증명**한다(Serendie가 JP에서 한 역할).
2. **CN 웨이브 2~6 (25건)** — 1이 통과하면 규모를 올린다.
3. **JP +40** — 제품 레퍼런스 여력이 가장 크다(115~160).
4. **재평가** — 441+70 = 511 시점에서 상한과 배분을 다시 잰다. 700은 목표지 예언이 아니다.
