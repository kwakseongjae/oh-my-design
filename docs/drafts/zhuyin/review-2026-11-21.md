## Read by the model

What the reading found:
- Each rule says no more than its quotes, keeps the source's hedges ("in most cases", 通常, 原則上, 建議), and names whose rule it is. No rule contradicts a quote it carries.
- Where a translation guide and the authority's handbook differ, the file says so in the rule itself instead of choosing silently: the dash (ZW-30), the width of parentheses (ZW-31), the colon and question mark (TW-25), the ellipsis (TW-29), chapter-title brackets (TW-27, settled to the handbook's 〈〉).
- Every spacing or width claim that rests only on the Microsoft extract is marked "not confirmed against page bytes" and has no check (ZW-13 half-width, ZW-14, ZW-35). That matches the gate.
- The typography rules (ZW-43 to ZW-54) quote the current CLREQ, name the region each sentence names, and leave out the two candidates for which CLREQ names no region.

Remarks from the model's own knowledge of the language. These have no source, are not rules, and are here so that a later reader knows where to look first:
- ZW-01 (您 in product UI) rests on two translation guides. Taiwan products written natively are not uniform on 您 and 你; the check is FYI, which fits.
- ZW-10 (正在… over …中): strings such as 載入中 and 處理中 are everywhere in interfaces written in Taiwan. Microsoft itself says the trailing form "could be used". A project that already writes …中 should probably keep it; this reads more like a house choice than a default.
- ZW-09 and ZW-07: ordinary Taiwan prose uses 被 and 它 freely (see the checker run below). Microsoft's rule is about avoidable passives and about generic persons, which a pattern cannot tell apart.
- ZW-08: 患有 is the normal clinical wording (患有糖尿病). Microsoft's advice is about pity language for disability; on medical copy this check will be noise.
- ZW-34 already says that Taiwan-native text read for the research does not always put a space between Han and Latin text. Keep it FYI.
- ZW-40: the Executive Yuan writes 新臺幣 with 臺; the locale data writes 新台幣. Both are in the rule; a product for government use would follow the former.

## The checker on text written in Taiwan (2026-11-22)

The pages of the sources that were written in Taiwan (Mozilla's zh-TW guide and marketing guide, the WordPress zh-TW guide, L10N-TW, two MODA pages, four TIPO pages; 675 lines with Han text, taken from the cached page bytes) were run through `scripts/lang/zhuyin-copy-check.mjs`. 44 findings, all FYI:

| check | hits | what they are |
|---|---:|---|
| ZW-34 | 25 | digits written against Han with no space, almost all on one MODA page (3項, 有1). The rule already says native text does not always space. |
| ZW-09 (被) | 10 | the guides' own prose: Mozilla's and L10N-TW's sentences use 被. |
| ZW-07 (它) | 6 | the guides' own prose: L10N-TW and Mozilla's marketing guide write 它. |
| ZW-21 | 1 | Mozilla's own wrong example, 互聯網. Correct hit. |
| ZW-01 | 1 | Mozilla's sentence that says when 你 is allowed. |
| ZW-04 | 1 | a WordPress sentence that begins with 輸入. |

So one hit in the 44 is the form a source calls wrong. The bare 被 and 它 patterns fire on the writing of the very guides the skill cites, for rules that only Microsoft states. Before the skill ships, either these two checks go (the rule stays as a writing rule with no check) or they are narrowed to the frames Microsoft quotes (會自動被…, a generic 它 after a noun). This is a proposal; the checker has not been changed.
