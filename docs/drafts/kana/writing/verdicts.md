# /kana writing — second-reader verdicts on rules.md (UW-01 … UW-57)

Checked 2026-11-21 against `rules.md` and `sources.json` in this directory. Region for every rule: Japan; every cited page is a Japanese-language source written for Japan, so no rule is "wrong region".

## How this check was done, and its limit

- All 23 URLs in the source-key table opened (HTTP 200), and so did the Pepabo tech-blog post quoted in UW-52. No source was unreachable.
- I had the same kind of tool as the researcher: a fetch that passes the page through an extraction model. No shell, no page source. This is therefore **not an independent byte-level check**.
- To keep the extractor from echoing the rule back, passages were pulled blind: it was asked what a section says about a topic, with the neighbouring sentences, and was not shown the rule's quote. A control question with an invented sentence came back "NO". The rule file's quotes were then compared by script with the text returned; the only quote that is not verbatim is the first one in UW-19 (two more differ only in list formatting, noted in their rows).
- Code points below were read with `codePointAt` from the strings the extractor returned. As a calibration, on both Mozilla pages the glyphs returned beside the labels U+301C, U+FF5E, U+2013, U+2014 and U+2015 are exactly those code points, and full-width and half-width forms came back distinct wherever a page names the width in words (全角「！」「？」 = U+FF01/U+FF1F; 半角「!?」 = U+0021 U+003F; DADS 「＊（全角アスタリスク）」 = U+FF0A). That is good evidence the pipeline keeps widths, but it is still an extractor's output. UW-42, UW-43 and UW-47 are judged on that evidence plus the pages' own words (全角, 半角, 記号が全角); if that is not accepted as a code-point check, treat their width claims as unverified. A native reader should look at the pages for UW-36, UW-42, UW-43, UW-45 and UW-47.
- **Criterion.** "supported": every quote is on its page and the page says what the rule's title, test and Strength line claim, for Japan. "weaker than stated": the quotes are real, but the title, the count or the test claims more than the page does (a dropped 原則 or なるべく, a guide counted that does not state the rule, a "disagreement" between things that are not two rules). Notes inside a "supported" row are context, not objections.
- Sources that rules.md brings in by JW id (KB, JTF, KG, YN, GK and earlier SmartHR reads) were not reopened; a verdict here covers only the pages cited by key in this round.
- One citation has no URL: UW-15 cites `SH-btn`, which is in neither the source-key table nor sources.json. The heading it quotes is on SH-app.
- OPTiM: the post has three bare lists (UXライティング, 13 items; マイクロコピー, 13 items; 用語集, 6 items). Every OPTiM heading quoted in rules.md is in one of them, with no body, as rules.md says.
