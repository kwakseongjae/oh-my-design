# 실행 계획 (2026-09-17 측정 기준)

## 전제 — 오늘 측정이 목표를 부정한다

오너 1순위는 "440 리뉴얼을 빨리". 오늘 잰 숫자로는 **그 목표가 그대로는 달성 불가능하다.**

| | |
|---|---:|
| `verification_v2` 없는 레퍼런스 | 299 |
| 필요한 클레임 경로 | **35,447** |
| 그중 증거 번들이 없는 레퍼런스 | 278 |
| `prose-derived` 111개의 색 근거율 | **43%** |
| 선언 색이 컴포넌트·본문에서 재사용되는 비율 | **100%** |

마지막 줄이 결정적이다. 값 하나를 고치려면 그 값을 쓰는 컴포넌트와 문장을 함께 고쳐야
한다 — 오늘 세 번의 기계적 대량 편집이 전부 여기서 실패했다. **299건 승격은 도구로
가속되지 않는다. 저술이다.**

그래서 목표를 바꾼다: **"440개를 verified로"가 아니라 "수요가 있는 곳은 깊게, 나머지는
정직하게".**

## 원칙 셋

1. **깊이는 수요를 따라간다.** 단, 근거를 정확히 말한다.

   **확실한 것(음성)**: 승격은 퍼널을 움직이지 않는다. 7월에 140개를 verified로 만들었고
   전환은 따라오지 않았다.

   **확실하지 않은 것(양성)**: "컴포넌트 ≥5 → 전환 0.499, <5 → 0.386"은 **연관이지
   인과가 아니다.** `docs/OMD_EXECUTION_DESIGN_2026-09-17.md:32`가 이미 한 번 정정했고
   (*"Association, not causation … do not re-inflate it"*), 이 계획의 초안이 그걸 다시
   부풀렸다. 교란이 명백하다 — 컴포넌트가 많은 레퍼런스는 사람이 시간을 많이 쓴
   레퍼런스이기도 하다.

   **재검증 불가**: 그 분석은 "수요 상위 140개" 구간에서 나왔는데, 커밋된
   `data/reference-demand.json`은 **440개 중 20개만** 담는다(원자료는 gitignore).
   지금 다시 계산할 수 없다.

   그래서 컴포넌트 수는 **인과가 입증된 목표가 아니라 우리가 개선할 수 있는 관측 가능한
   대리 지표**로 다룬다. 이 격하는 투입 시간을 정하는 데 영향을 준다.
2. **고칠 수 없는 것은 감춘다가 아니라 표시한다.** 261건 모션·111건 팔레트를 다시 쓰는 대신
   **소비자에게 불확실성을 보여준다.** 탐지기는 이미 있다.
3. **유입을 막는다.** `prose-derived` 111개는 측정 없이 저술했기 때문에 생겼다. 새 레퍼런스가
   같은 방식으로 들어오면 1000개 확충은 약한 레퍼런스 560개를 더하는 일이 된다.

## 트랙 1 — 수요가 측정된 20개 심화 (최우선)

**"상위 30"은 존재하지 않는다.** 수요 데이터는 20개뿐이고 그중 상위 10이 83%다.
오늘 10개를 끝냈으므로 **남은 것은 10개**다.

**무엇을 — 하나만 고른다: 상태값.** 초안은 "상태값 + 컴포넌트 복원"이라고 썼는데
**둘은 다른 작업**이다. 상태값은 *기존* 컴포넌트에 hover/pressed/focus를 더하고,
컴포넌트 복원은 번들의 평균 49개에서 출하된 2.9개로 좁혀진 간극을 되돌리는 일이다.

1주차는 **상태값**을 한다. 절차가 오늘 4건으로 검증됐고 단가가 실측됐기 때문이다.
컴포넌트 복원은 더 큰 레버일 수 있으나 **경로가 아직 검증되지 않았다** — 오늘 측정으로
번들의 상태 델타 중 문서화된 컴포넌트에 귀속되는 것은 7.2%뿐이었다. 1주차 이후
한 건으로 단가를 재고 결정한다.

**prose-derived 교차 확인 완료**: 수요 20개 중 `prose-derived`는 **0개**다. 그래서 트랙 1이
"근거 43%짜리 팔레트 위에 상태값을 쌓는" 문제는 발생하지 않는다.

절차(레퍼런스당 15~25분, 오늘 4건으로 실측):
```
닫힌 탭/iframe을 연다 → 정본 예제를 잡는다 → authored CSS 커스텀 프로퍼티를 읽는다
→ 크기 변형을 대조한다 → 상태값만 추가한다 → 별도 표면·출처로 기록한다
```

**완료 기준**: 수요 20개 각각이 상태값을 갖거나, **갖지 못하는 사유가 기록**돼 있다.
**진척 지표**: `component_state_prose_only` 143 → 약 138.
**분량**: 10건 × 20분 ≈ **3.5시간**. 단, 오늘 10건 중 **5건이 브랜드 발행 방식 때문에
막혔고, 막혔다는 것을 판정하는 데도 15~25분이 들었다.** 남은 10건도 절반은 사유 기록으로
끝날 것으로 본다 — 그것도 완료다.

**정직한 기대치**: 이 3.5시간이 움직이는 지표는 `component_state_prose_only` 143 → ~138
하나다. 티어는 안 움직인다. 위 원칙 1의 격하를 감안하면 **이것이 큰 투자가 아니라는 점이
오히려 장점**이다 — 인과가 불확실한 목표에 7시간이 아니라 3.5시간을 쓴다.

## 트랙 2 — 불확실성을 제품에 노출 (트랙 1과 병렬)

**무엇을**: 261건 모션·111건 팔레트를 다시 쓰지 않는다. 대신 `/reference/[id]`와 `/builder`가
**근거 없는 값을 근거 없다고 표시**하게 한다.

근거: 탐지기가 이미 레퍼런스별로 판정을 낸다(`motion_value_unsourced`,
색 근거율). 문서 372건을 다시 쓰는 것과 UI 한 곳을 고치는 것의 비용 차이가 두 자릿수다.

**완료 기준**: 소비자가 "이 모션 값은 관측되지 않았다"를 문서를 읽지 않고 안다.

**분량 — 추정하지 않는다.** 초안은 "1~2일"이라고 썼는데 렌더러를 한 번도 열어보지 않고
쓴 숫자다. 1일차에 **스코핑부터** 한다. 형태가 자명하지 않기 때문이다 — AGENTS.md는
*"Never ... adding `Partial`/warning chrome in place of its content. Omit only the
unresolved field"*를 못박는다. 즉 배너가 아니라 **필드 단위**여야 하고, 근거 없는 값
5개짜리 모션 표를 빈 행으로 둘지, 접을지, 통째로 뺄지가 제품 결정이다.

**오너 결정 필요**: 이 작업은 카탈로그를 **눈에 띄게 나빠 보이게** 만든다. 그게 사실을
반영하는 것이지만, 그 트레이드오프를 받아들일지는 내가 결론 낼 일이 아니다.
