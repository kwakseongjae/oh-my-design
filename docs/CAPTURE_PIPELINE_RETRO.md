## 2. 개별 버그가 아니라 **구조 문제** 다섯

### P1. 측정기가 "웹은 이렇게 생겼다"는 가정 위에 서 있다

12건 중 8건이 **사이트 구조 가정 위반**이다. 시맨틱 헤더가 있다, 히어로는 `<img>`다,
이미지는 뷰포트 안에 들어온다, 배경은 CSS에 있다 — 전부 틀렸다.

수백 개로 늘리면 새 브랜드마다 새 가정이 깨진다. **가정을 없앨 수는 없으므로,
깨졌을 때 조용하지 않게 만들어야 한다.**

### P2. 결측이 데이터처럼 보인다

`sampled: 0`, `chrome: null`은 스키마상 정상 값이다. 애플이 0장인 채로 "증거 기반"이라
불릴 뻔했다. **부재와 실패가 구분되지 않는다.**

지금은 `notes.buttonCandidatesAboveFold: 0` 같은 사유를 일부만 붙였다. 전 필드로
확장해야 한다.

### P3. 검증이 전부 사후·수동이었다

12건 전부 **내가 출력을 눈으로 보고** 찾았다. 그중 2건(#7, #10)은 **카탈로그 DESIGN.md와
어긋나서** 잡혔다 — 즉 독립 소스와의 대조가 유일하게 작동한 자동 검증인데,
그게 자동화돼 있지 않다.

### P4. 채널이 둘인데 수정이 한쪽에만 들어간다

투명색 가드를 Aside에만 넣고 Playwright에 안 넣어서 같은 버그를 두 번 고쳤다.
지금은 `analysis.mjs`로 분석은 공유하지만 **수집기 로직이 여전히 두 벌**이다.

### P5. 모바일이 사실상 없다

390 스크린샷은 찍지만 `mobile`에 `chrome`만 들어간다. **imagery·motion·구도가 데스크탑
전용**이다. 사용자가 명시한 "모바일에 대해서도" 요건을 지금 구조로는 못 받는다.

## 3. 파이프라인 제안

### 3.1 캡처 자기진단 (P1·P2)

수집기가 **깔때기 카운트를 evidence에 남긴다.**

```json
"imagery": {
  "funnel": { "found": 34, "sizeOk": 16, "centreInFrame": 12, "srcOk": 12,
              "framed": 9, "cropped": 9, "analysed": 9 },
  "sampled": 9
}
```

이러면 `sampled: 0`이 **어느 단계에서 죽었는지** 파일만 봐도 안다. 애플·피그마·토스를
각각 30분씩 추적한 작업이 한 줄 읽기로 바뀐다.

**게이트**: 어느 단계에서 90% 이상 탈락하면 `CAPTURE_SUSPECT`를 세우고 사람 확인 전까지
그 브랜드를 하류로 넘기지 않는다.

### 3.2 독립 소스 교차검증 (P3)

카탈로그 `web/references/<id>/DESIGN.md`에 이미 색·타이포가 있다. 캡처 직후 자동 대조:

| 필드 | 카탈로그 | 캡처 | 판정 |
|---|---|---|---|
| canvas | `#ffffff` | `#fdfdfd` | ✅ ΔE 낮음 |
| primary | `#000000` | `#5ccca8` | ❌ **불일치 — 수집 오류 의심** |

이 표가 자동으로 나왔으면 #10을 즉시 잡았다. 카탈로그가 없는 신규 브랜드는 대조 대상이
없으므로 `NO_CROSS_CHECK`로 표시하고 사람 확인 우선순위를 올린다.

### 3.3 수집기 적합성 스위트 (P1·P4)

사이트 원형(archetype)별 고정 픽스처를 만들고, 수집기 변경은 이걸 통과해야 배포된다.

| 원형 | 대표 | 무엇을 검증 |
|---|---|---|
| 캐러셀 커머스 | musinsa | 화면 밖 슬라이드 제외 |
| 풀블리드 히어로 | apple | 뷰포트보다 큰 이미지 포착 |
| 영상 히어로 | toss | video·canvas 수집 |
| 비시맨틱 마크업 | coupang | 기하 헤더 검출 |
| 반응형 srcset | figma | 스크롤 후 재식별 |
| 텍스트 포털 | naver | 이미지 0이 정상 판정 |
| 다크 대응 | karrot | colorScheme 고정 |

**픽스처는 라이브 사이트가 아니라 저장된 HTML+자산이어야 한다** — 라이브는 매일 바뀌어
회귀 테스트가 안 된다. 지금 저장소(`~/.omd/evidence-store/`)에 원본이 있으니 그걸로
재생 가능한 픽스처를 만들 수 있다.

### 3.4 채널을 어댑터로 (P4)

수집 로직을 한 벌로 만들고 채널은 세 함수만 제공한다.

```
interface Channel {
  goto(url), evaluate(fn), screenshot() → Buffer, setViewport(w,h)
}
```

지금 `capture-media-evidence.mjs`와 `capture-via-aside.mjs`가 **각자 수집 JS를 들고 있다.**
이걸 하나로 합치면 #8 같은 재발이 구조적으로 불가능해진다.

**채널 사다리**: Playwright(기본, 통제 가능) → Aside(거절 사이트) → 수동(챌린지 표시 시
브랜드 제외). 거절 판정 기준을 코드로: HTTP 403 / 큰 이미지 0 / "Access Denied" 타이틀.

### 3.5 모바일을 1급으로 (P5)

`viewport`를 축으로 올린다. evidence가 뷰포트별 블록을 갖는다.

```
evidence.surfaces = {
  "desktop-1440": { chrome, imagery, motion },
  "mobile-390":   { chrome, imagery, motion }
}
```

모바일이 중요한 이유가 측정에도 있다 — **한국 커머스는 모바일이 정본이고 데스크탑이
파생**인 경우가 많다. 데스크탑만 재면 브랜드의 실제 디자인 언어를 놓친다.

### 3.6 레퍼런스 탐색 자동화 (신규)

이번엔 URL을 손으로 골라 curl로 찔러봤다. 수백 개엔 안 맞는다.

```
후보 수집 → 표면 분류 → 도달성 판정 → 대상 화면 선정 → 캡처
```

- **표면 분류**: 랜딩 / 제품 / 기업 / 문서. 기업 표면으로 제품 토큰을 채우면 규칙 위반이라
  이 분류가 게이트다.
- **도달성**: 403·챌린지·로그인 벽을 코드로 판정하고 채널 사다리로 라우팅
- **대상 화면 선정 근거를 기록**: 왜 이 URL인가. 지금은 계획 문서에 산문으로만 있다

### 3.7 비용·시간 계측 (신규)

지금 evidence에 소요 시간이 없다. 수백 개로 확장하려면 브랜드당 캡처 비용을 알아야
웨이브 크기를 정한다. `durationMs`를 단계별로 남긴다.

## 4. 프로세스 문제

### 4.1 스캐폴딩이 산출물보다 앞서 자랐다

이번 세션에 **생성 이미지 0장, arm 실행 0회**다. 측정기·루브릭·거버넌스는 필요했지만,
루브릭을 216런 본실험 기준으로 완성하려다 파일럿을 못 열었다.

**교훈**: 파일럿을 게이트 뒤가 아니라 **게이트 앞**에 둔다. 실물이 무엇이 부족한지
알려주는 속도가 문서보다 빠르다.

### 4.2 검토가 실제로 값을 만들었다 — 유지할 것

3자 교차검증(sol·grok·opus5)이 잡은 것:
- 루브릭이 omd 자기 형식을 채점표로 쓰던 것
- 회피 규칙이 실험을 성립 불가로 만들던 것
- 이징 보일러플레이트의 **출처가 우리 규격 템플릿**이라는 것
- 기준선 없이는 점수 해석이 불가능하다는 것

이 넷은 혼자서는 못 찾았을 것이다. **검토 비용은 정당했다.**

### 4.3 워커 토큰이 파이프라인의 단일 장애점

sol 토큰 소진으로 작업이 멈췄다. 평가자 3종 중 하나가 죽으면 실험 자체가 못 연다.
**대체 경로를 미리 정하거나, 최소 가동 구성을 정의해야 한다.**

## 6. 구현 상태 (2026-08-23)

회고가 문서로만 남으면 다음 라운드에 같은 12건이 다시 난다. 아래는 **코드로 닫힌 것**과
아직 안 닫힌 것.

| 순위 | 항목 | 상태 | 어디에 |
|---|---|---|---|
| 1 | 캡처 자기진단(깔때기) | **닫힘** | `collectors.mjs` 깔때기 + `attritionOf` |
| 2 | 카탈로그 교차검증 | **닫힘** | `cross-check.mjs`, 파이프라인 단계로 편입 |
| 3 | 수집기 단일화 | **닫힘** | `collectors.mjs` 한 벌을 두 채널이 사용 |
| 4 | 적합성 픽스처 스위트 | **닫힘** | `conformance.mjs` + `fixtures/` 9종, 9/9 |
| 5 | 모바일 축 승격 | **부분** | Playwright는 두 서피스. Aside는 창 크기 제어 불가 |
| 6 | 탐색 자동화 | **닫힘** | `discover-targets.mjs`, `targets.json`에 선정 근거 |
| 7 | 비용 계측 | **닫힘** | 단계별 `durationMs` + 실행 리포트의 브랜드당 중앙값 |

### 6.1 픽스처를 스위트가 아니라 **게이트**로 둔 이유

`pipeline.mjs`는 `conformance.mjs`가 빨간불이면 **캡처를 시작하지 않는다.**

이번 라운드의 12건 중 10건은 숫자를 눈으로 보다가 찾았다. 고장 난 수집기가 내는 증거는
정상 증거와 생김새가 같기 때문이다. 스위트를 "기억나면 돌리는 것"으로 두면 그 성질이
그대로 남는다. `--skip-gate`는 있지만 **우회 사실이 실행 리포트에 기록**된다.

### 6.2 픽스처가 즉시 잡은 것

스위트를 처음 돌리자마자 두 건이 빨간불이었고, 둘 다 회고 시점엔 몰랐던 결함이다.

- `<video>`가 `src`도 `currentSrc`도 못 내면(`<source>` 자식으로 재생하거나 아직
  로드 전) **통째로 탈락**했다. 토스 히어로가 video라서 열거 대상을 넓혔던 그 수정이,
  URL 없는 video 앞에서 무효였다.
- 감쇠 게이트가 정상 커머스 그리드에서 오탐했다. 썸네일 수백 장을 걸러내는 건 필터가
  일하는 것이지 표본을 잃는 게 아니다. `found → sizeOk` 구간을 비율 게이트에서 뺐다.

### 6.3 태그 기반 재식별 — 5번을 실제로 열어준 수정

모바일을 1급으로 올리자 배민 폰 레이아웃이 9장 중 8장을 `kept → framed`에서 잃었다.
원인은 크기 하한이 아니라 **문서 좌표의 드리프트**였다. 위쪽이 lazy-load되면 아래
모든 y가 밀리고, 390px 화면에선 그 이동량이 훨씬 크다.

열거 시점에 `data-omd-cap`을 붙이고 그걸로 되찾는다. 태그가 사라진 경우(스크롤 시
재렌더)에만 기하로 폴백하고, 그때도 **문서 y는 쓰지 않는다.** 수정 후 배민 모바일
9장, 감쇠 없음.
