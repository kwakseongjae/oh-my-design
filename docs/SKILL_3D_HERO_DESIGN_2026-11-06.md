## 1. 결론: 스킬 하나, `omd-3d-hero`(가칭)

요청은 둘이었지만 하나로 묶기를 권한다.

| 오너 요청 | 이 설계에서 | 이유 |
|---|---|---|
| Blender풍 배경을 만들어 주는 스킬 | `omd-3d-hero`의 본업. DESIGN.md 토큰으로 조명이 있는 공간·추상 장면을 만들고, "Blender로 렌더한 듯한" 마감(부드러운 그림자, AO, 톤 매핑, 얕은 피사계 심도, 그레인)을 입힌다 | 비어 있는 자리다. taste-skill 2.5(11/05)가 3D를 넣었지만 제품 렌더뿐이고, 브랜드 토큰 근거와 한국어 헤드라인이 없다 |
| three.js 스킬 | 별도 API 팩을 만들지 않는다. three.js는 `omd-3d-hero` 안의 실행 수단이다 | three.js API 레퍼런스는 cloudai-x 팩(설치 190K)과 threejs.org의 `llms.txt`가 이미 덮는다. 사람들이 스킬에서 얻으려는 것은 API가 아니라 연출과 검증이다 |

## 2. 무엇을 하나

입력은 프로젝트 `DESIGN.md`와 브리프 한 줄(헤드라인 + 보조 문구), 출력은 첫 화면 히어로 하나다.

1. **토큰을 읽는다(지어내지 않는다).** 색·표면·깊이(그림자, 반경)·모션 토큰에서 재질 색, 조명 색온도, 배경 톤을 끌어온다. `omd-shader-hero`의 `tokens.mjs`처럼 토큰이 없으면 멈춘다. 근거 없는 색을 채우지 않는다.
2. **장면 유형 셋 중 하나를 고른다.** 공간(빛이 드는 방·창·벽면), 추상 오브젝트(브랜드 형태를 단순화한 덩어리), 지형·자연(물·안개·언덕). 제품 렌더는 하지 않는다(taste 영역).
3. **정지 컷이 먼저다.** 같은 장면의 정지 컷을 포스터로 굽는다. 첫 페인트, WebGL 없음, 모션 줄이기, 폰에서는 이 컷만 나온다. 실시간 장면은 데스크톱에서 천천히 움직이는 정도로만, 끄면 포스터로 돌아간다.
   - 포스터 굽기 경로: 브라우저 경로 추적(three-gpu-pathtracer, 적합성 미검증) → 사용자가 Blender 채널을 가지고 있으면 그쪽으로.
4. **헤드라인은 잰다.** `omd-shader-hero`의 knockout 방식으로 한글 헤드라인과 보조 문구 대비를 장면의 최악 프레임에서 잰다(4.5:1 / 큰 글자 3:1). 한글 조판은 `hangul` 규칙(keep-all, 자간, 행간)을 따른다.
5. **실제 GPU에서 검증한다.** shader-hero `verify.mjs`의 네 경로(정상, WebGL 없음, 모션 줄이기, 모바일)를 그대로 쓰고, 프레임 예산과 번들 크기를 기록한다.

## 3. 재사용과 함께 고칠 것

- 재사용: `skills/omd-shader-hero/scripts/tokens.mjs`(토큰 → 잉크·대비), `verify.mjs`(실제 렌더 증명), 포스터 대체·모션 줄이기 규칙, /hangul 페이지의 three.js 3D 아이콘 작업 경험.
- 함께 고칠 것: `agents/omd-asset-curator.md`가 아직 1.5.0에서 지운 3D 서브에이전트로 보낸다고 적혀 있다(3행). 이 스킬과 `omd:media` 채널로 바꾼다.
- 설계 전에 읽을 것: taste-skill 2.5의 `make-posters.mjs`·`assets/objects/product-render` 흐름. 겹치지 않게 범위를 자른다.

## 4. 성공 기준

3D 스킬은 설치 상한이 낮다(MengTo 3D 이펙트가 행마다 1.6~1.8K, 24시간 보드 600위 안에 3D 스킬 0). 그래서 설치 수가 아니라 아래로 판단한다.

- 검증된 레퍼런스 3곳(예: 토스, 당근, 배민 — 장면 유형이 서로 다른 셋)의 DESIGN.md로 만든 데모 3개가 네 경로 검증을 통과한다.
- 그 데모로 Threads 1편(계획표 #6, 11/28)을 낸다.
