## 2. 작업 분해 — 140개는 두 종류다

번들 140개를 전부 열어 `interactions` 배열 길이를 셌다(실측, 번들 누락 0건):

> ## ⚠️ 정정 2 (2026-09-16, 최종) — 상태값은 번들에 **있다**
>
> 앞선 정정(바로 아래)이 틀렸다. 두 번 조사했고 두 번째가 맞다.
>
> **1차 판단**: `interactions[]`와 `components[].states`를 보고 "번들에 상태값이 없다"고 결론.
> 그 두 곳이 이름만 담는 것은 사실이다.
>
> **실제**: `captureStates()`(`capture-reference-evidence.ts:193-245`)가 hover·pressed·focus를
> **적용한 채 computed style을 찍어** `surfaces[].elements[]`에
> `<selector>::state-<name>` 원소로 넣는다. 177개 번들 중 **86개**에 그런 원소가
> **4,748개** 있다 (pressed 2,226 · hover 1,565 · focus 957).
>
> 즉 **하네스는 멀쩡했다.** 집계 단계가 값을 이름으로 접었을 뿐이다.
> 예: `tossbank` 버튼 hover가 `#4e5968 → #3182f6`(실측 토스 블루)로 남아 있다.
>
> **도구 추가**: `npm run state-values -- <id>` (`web/scripts/extract-state-values.mjs`).
> `components[].representative.selector`로 base와 `::state-*` 원소를 조인해 스타일 diff를
> 제안으로 낸다. 파일은 쓰지 않는다 — 번들은 `type`과 셀렉터만 알고 `tds-button` 같은
> 토큰 이름은 모르므로 매칭은 사람이 확인한다.
>
> **커버리지**: 상태 delta 보유 **67개 레퍼런스 / 560개 상태**.
> 상태값이 필요한 164건 중 **41건이 번들 조인으로 해결**되고,
> 56건은 번들은 있으나 delta가 없으며, 67건은 번들이 없다.
>
> 따라서 하네스 수정은 **선행 조건이 아니다.** 41건을 지금 채울 수 있고,
> 나머지는 조사(공개 DS) 또는 재캡쳐가 필요하다.

> ## ⚠️ 정정 1 (2026-09-16) — 아래 R/C 구분은 틀렸다
>
> **번들에는 상태별 스타일 값이 없다.** 177개 전량을 재확인한 결과:
>
> - `interactions[]` 레코드 **237개**, 키는 `kind` `surfaceId` `triggerSelector`
>   `targetSelectors` `states` 다섯 개뿐 — **색상값 0개**
> - `components[].states`는 **2,298개 전부 문자열**, 객체 0개
> - `components[].representative.style`은 **정지 상태 하나**뿐
>
> 즉 캡쳐 하네스는 *"이 컴포넌트에 hover/pressed 상태가 있다"*는 **이름만** 기록하고
> *"그 상태에서 어떻게 보이는가"*는 기록하지 않는다. 이는 산문 `states:`와
> 정보량이 동일하다 — 지금 advisory가 불충분하다고 표시하는 바로 그것이다.
>
> 따라서 **"R형 55개는 브라우저 실행 없이 재투영만 하면 된다"는 전제가 성립하지 않는다.**
> 140개 전부가 캡쳐를 새로 돌려야 하고, 그 캡쳐는 **각 상태를 적용한 채 computed style을
> 찍도록 하네스를 고친 뒤**에야 의미가 있다.
>
> 그리고 이것이 **오히려 좋은 소식이기도 하다**: 기존 산문은 증거를 버린 결과가 아니라
> *값이 없다는 사실을 정직하게 기록한 것*이었다. 125개 풀 컴포넌트 중 22개는
> *"no state value is inferred"*처럼 미관측을 명시한다. 버려진 94%라는 앞선 진단은
> 컴포넌트 **개수**에는 해당하지만 상태 **값**에는 해당하지 않는다.
>
> **선행 작업이 하나 생겼다**: `web/scripts/capture-reference-evidence.ts`가 상태 적용 중
> computed style을 스냅샷하고 `states`를 값 객체로 방출하도록 고치는 것. 그 전에는
> 상태값 복구가 조사(1차 출처 확인)로만 가능하다.

## 2b. 🔴 마감과 게이트가 정면으로 충돌한다 — 오너 결정 필요

**만료 복구는 현재 스킬 게이트가 금지하는 작업이다.** 착수 전에 확인해야 한다.

기존 재검증 경로를 따라가면 이렇게 끝난다 (`artifacts/reverify/runs/*/packet.md` 실물 확인):

```
3. Execute the semantic task: `/omd:add-reference <id> --mode update`
6. Update only `web/references/<id>/DESIGN.md` and `.verification.md`
```

그런데 그 스킬은 `CORE_V2_CATALOG_WRITE_BLOCKED` 상태다:

> *"Do not write or update `web/references/<id>/DESIGN.md`, frontmatter tokens,
> generated counts, or mirrors."* — 해제는 Core v2 이관 5조건이 **함께** 떨어질 때만.
> 스킬 문서는 *"all of them, with no one-off exception and no plausible fallback"*이라고 못박는다.

### 우회로가 없다는 것도 확인했다

만료를 피하는 유일한 비-쓰기 경로가 있는지 봤다. 없다.

- `reference-quality.mjs:196-198` — claim이 참조하는 소스를 순회하며 **하나라도** TTL을 넘기면
  `source_expired`로 verified를 막는다. 소스 하나가 만료되면 끝이다.
- 140개 **전부**가 `product-surface`(90일) 소스를 갖는다. 135개가 `official-doc`(180일)·
  `license`/`brand-asset`(365일)도 함께 갖지만, **긴 TTL이 짧은 TTL을 구제하지 못한다.**
- 따라서 TTL 재분류조차 claim의 근거 소스를 바꿔 쓰는 **파일 쓰기**이고, 게이트 대상이다.

**결론: `web/references/`를 쓰지 않고 만료를 피할 방법은 없다.**

### 오너가 고를 것

| | 선택지 | 대가 |
|---|---|---|
| **A** | 만료 복구에 한해 게이트를 **좁게 연다** — 기존 ref의 증거 갱신·컴포넌트 복원만 허용, 신규 레거시 파일 생성은 계속 금지 | 게이트가 막으려던 "레거시 바이트 증가"가 일부 발생. 다만 신규 파일이 아니라 **기존 파일 갱신**이다 |
| **B** | 만료를 받아들이고 Core v2 이관 후 순차 복구 | 10/12에 카탈로그가 0 verified로 읽힌다. 복구까지 몇 주 |
| **C** | 23일 안에 Core v2 이관 완주 후 Core 경로로 복구 | **불가능.** 사람 판단 약 440건이 남아 있다 |

권고는 **A**다. 게이트의 명시된 목적은 *"creating another legacy file"* 방지인데,
만료 복구는 새 파일을 만들지 않고 이미 있는 140개의 **버려진 증거를 되돌리는 일**이다.
다만 게이트 문구가 예외를 명시적으로 배제하므로 **에이전트가 스스로 판단해 열 수 없다.**
오너가 열어야 한다.

A를 고르면 함께 정할 것: 허용 범위(증거 갱신 + 컴포넌트 복원만인지), 적용 대상(140개 한정인지),
해제 종료 시점(만료 대응 완료 시 자동 재잠금인지).

## 5. 순서가 이렇게 된 이유

로드맵 §2는 "1000 확충은 440 리뉴얼의 하드 의존"이라고 적었다. 맞다. 그런데 그 위에 하나가 더 있다.

```
만료 대응 (D-23)
   ↓ 같은 파일을 만진다
트랙 A · 440 Core v2 리뉴얼
   ↓ 게이트 5조건
트랙 C · CJK 확충
```

**440 리뉴얼을 먼저 해도 만료는 온다.** 반대로 만료 대응을 먼저 하면
그 과정에서 140개의 컴포넌트·상호작용 증거가 정본에 들어가고, 그건 Core v2 이관의
`components-states` 섹션 — 측정된 **10배 격차**로 가장 얇은 바로 그 섹션 — 의 입력이 된다.

즉 만료 대응은 440 리뉴얼과 경쟁하지 않는다. **선행 투자다.**
