## 1. 반영되지 않은 것 · 반영했다고 적혀 있으나 안 된 것

### 1.1 실행 포인터가 옛 번호를 유지한다 (치명)

단계표는 T3-2 = 루브릭 동결, T3-3 = 무신사 왕복이다 (75–76행).
승인 후 지시인 **다음 행동**은 여전히 이렇게 적는다.

> T3-1 유도 규칙 → T3-2 무신사 1건 왕복. 9개를 캡처해두고… (297–298행)

병행 다이어그램도 옛 순서다: `캡처 → 유도규칙 → 무신사 왕복 → 9개 확장` (291행).
T3-0이 없고, T3-2가 왕복이다. 이 세 곳이 한 문서 안에서 서로 다른 실험을 지시한다.

검토 A·B가 독립적으로 요구한 “루브릭 먼저”는 표에만 있고, 착수 문장에는 없다.

### 1.2 T3-1 템플릿이 T3-0·T3-6을 정면으로 뒤집는다 (치명, 반영 주장과 불일치)

T3-0 #3: `luminanceGradient`로 개명, key-light 지시 승격 금지 (94행).
T3-1 템플릿: `조명: evidence.imagery.aggregate.lightDirections 최빈값` (105행).

T3-0 #4: figure-ground 실패는 알고리즘 미분리, 엣지투엣지는 별도 근거 (95행).
T3-6: 그 해석을 증거팩에 넣지 않는다 (135–136행).
README §3도 같은 완화를 이미 했다 (README 62–64행).
그런데 T3-1은 이렇게 남긴다.

> subjectCenter 슬롯은 비운 채로 나가고, 대신 "엣지투엣지 크롭"이 근거가 된다. (111–112행)

헤더의 “검토 A/B 반영”과 T3-0 표는 이 문장을 고친 것처럼 읽히지만, 유도 규칙의
실제 슬롯은 이전 실패(근거 없는 구도 문장)를 그대로 재생산한다.

코드도 아직 그 해석을 쓴다. `analysis.mjs:155` 실패 reason은
`no figure-ground separation (edge-to-edge composition)` 이고,
무신사 `evidence.json` 표본 reason이 그 문자열이다.

### 1.3 원본 보존은 계획이 선언하고 README가 부정한다

검토 A의 핵심이었다. 계획 225–233행은 README §6의 “다시 캡처하면 된다”를
틀렸다고 적는다. 그런데 README 128–131행은 그 문장을 **그대로** 둔다.

gitignore(`test-v2/.gitignore:6`)라 커밋되지 않고, git-밖 불변 저장소 경로·
보존 책임자는 계획에 없다. 저장소가 없으면 선언만 있고 감사 경로는 없다.

manifest 필드(URL·시각·viewport·locale·로그인) 중 locale·로그인은 무신사

## 2. 개정이 만든 새 문제

1. **단계표 / 다음 행동 / 병행 다이어그램 3중 분기.** 번호 재매핑 후 실행 문장을
   안 고친 부산물이다. 승인되면 다음 에이전트는 다음 행동을 따른다.
2. **T3-0 #4의 증거 인용이 이미 거짓이다.** 같은 개정에서 README §3을 고쳤다.
   실행자가 README만 보면 #4를 끝난 일로 건너뛰고, `analysis.mjs:155`의
   해석 문자열은 남는다.
3. **“이미 끝난 것”이 T3-0을 부정한다.** 64–66행: “광고를 브랜드 색으로 오인하던
   결함 제거.” T3-0 #1과 무신사 `chrome.primaryButton = #5ccca8`(라벨 `""`)가
   그 결함이 제거되지 않았음을 보여 준다.
4. **T2 표가 깨졌다.** 200–206행: 헤더가 두 번이고 그 사이에 편집 메모가 있다.
5. **T1-5가 T1-4 분기를 무시한다.** 184행: “신규 1건 + 기존 3건을 **새 규격으로**.”
   T1-4가 v2 보강으로 끝나면 “새 규격” 왕복은 성립하지 않는다.
6. **무신사 재캡처가 단계가 아니다.** 표는 재캡처를 요구하고 T3-3은 왕복을 요구한다.
   사이 단계가 없으면 파일럿은 잘못된 표면의 JSON으로 루브릭을 검증한다.

## 4. 조건

각 조건은 해당 단계 전에 문서 또는 산출물에서 기계적으로 확인한다.

**C1. 실행 포인터 정합** (T3-1 이전, T3-0과 병행 가능)
계획 291행 다이어그램, 297–299행 다음 행동, 220–221행 캔바 문장, 200–206행 T2 표를
단계표(73–80행, 207–212행)와 같은 번호·같은 분모로 맞춘다.
검증: `T3-2`가 “무신사 왕복”으로 검색되지 않는다. `T3의 10개`가 없다.

**C2. T3-1 템플릿이 T3-0·T3-6과 모순하지 않는다** (T3-1 이전)
112행의 엣지투엣지 대체 근거를 삭제한다. `lightDirections`를 조명 슬롯에 쓰지 않는다.
빈 슬롯은 문장 삭제뿐이다.
검증: `RULES.md`와 계획 T3-1 블록에 `엣지투엣지`·`조명:.*lightDirections`가 없다.

**C3. README를 정본 정책에 맞춘다** (새 캡처 이전)
§6 재캡처 문장을 저장소 정책으로 교체. §9를 “잔여 7 + 무신사 재캡처”로.
§5 주 버튼을 유효 크로메로 제시하지 않음. §1·§2 용어를 T3-0에 맞춤.
검증: README에 `다시 캡처하면 된다`, `나머지 9개`가 없다.

**C4. 불변 저장소 한 줄 + 기존 PNG 입고** (새 캡처 이전)
계획에 경로(git 밖)·보존 주체를 한 줄로 박고, 현재 musinsa/coupang PNG SHA를
`manifest.json`에 넣는다.
검증: manifest의 SHA가 로컬 파일 SHA와 같고, README §6이 그 경로를 가리킨다.

**C5. 무신사 재캡처를 T3-0 이후·T3-3 이전 단계로 번호 부여** (T3-3 이전)
검증: 표의 URL과 새 `evidence.json` `source.finalUrl`이 같은 표면이다.
현 `/recommend?gf=A` JSON으로 T3-3을 돌리지 않는다.

**C6. T3-2 동결 전에 넣을 필드를 계획에 박는다** (T3-2 동결 이전)
필수: 축 가중치, 평가자 수·일치도, 동률/결측/abandon, 통과 임계, 브랜드당 반복,
4변형 선택 규칙, verify.json vs 인간 충돌 시 승자, 레인 A 턴·시간·재시도,
hallmark 질문 허용 여부, 시맨틱 아트디렉션을 넣을지 **명시적 포함 또는 제외**.
검증: `90-comparison/RUBRIC.md`에 위 필드가 빈칸 없이 있고, grok 반박을 통과한
