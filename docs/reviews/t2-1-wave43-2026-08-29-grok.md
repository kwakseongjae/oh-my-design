## 결함 성격이 바뀌었다 — 발명형 0, 소실형만 남았다

웨이브 43의 7건은 **전부 A1 계열(원본 고유 사실·제약의 소실)**이다. 웨이브 40~42에 섞여 있던
D2a 재수록·D1 플랫폼 발명·B1 sibling 승격 같은 **발명형이 0건**이다.

| 브랜드 | 결함 |
|---|---|
| lovable | 원본 고유 경계 구 소실 |
| maicoin | §11 서사 절단 · 시스템 산스 제약 · §15 모션 제약 · §5 레이아웃 제약 |
| mailchimp | §11 서사 연결문 · §15 easing Use 페어링 |

해석: 예방 층 강화(웨이브 42에서 hubspot형 D2를 F3 → 워커로 승격, 그 전의 발명 금지 조항들)가
**「만들어내는 결함」을 억제**했고, 남은 것은 **「빠뜨리는 결함」**이다.

이 구분이 다음 개선 방향을 정한다. 소실형은 금지 조항으로 막히지 않는다 — 워커가 원본을 다
옮기지 못하는 문제이므로 **제출 전 자가 대조 절차**를 강화해야 한다. 웨이브 44 워커 프롬프트에
§별 원본 문자열 전수 대조를 넣어 효과를 잰다.

표본이 한 웨이브라 단정은 이르다. 브랜드 난이도 차이일 수 있으므로 44~45에서 유지되는지 본다.

## 오케스트레이터가 잡은 것 — F3 무실행 2건

maicoin·mailchimp의 F3가 읽는 단계에서 잘려 `audit-log.md`가 생성되지 않았는데, **기계 검사
3종(게이트 PASS · 1:1 OK · use 100%)은 전부 통과했다.** 그 검사들은 F3 전 상태에서도 성립한다.
`audit-log.md` 부재를 확인하지 않았으면 F3를 건너뛴 브랜드를 검토로 넘겼을 것이다.

단계별 완료 증거를 고정한다:

| 단계 | 완료 증거 |
|---|---|
| 이관 | `DESIGN.md` 존재 + 게이트 |
| F3 | `audit-log.md`의 `AUDIT_DONE fixes=N` |
| 개정 | **지목 문자열의 파일별 실측** |
| 검토 | `REVIEW_DONE <brand> <verdict>` |

기계 검사(게이트·1:1·use)는 **어느 단계의 완료 증거도 아니다** — 단계와 무관하게 성립할 수 있는
무결성 조건이다.
