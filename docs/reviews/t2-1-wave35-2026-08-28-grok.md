## 새 결함형 — 표면 간 측정 이전 (intercom)

원본 `:268` **한 줄**이 세 표면을 각각 다르게 기록한다:

```
Hero Primary `#000` 6px / 42px / 12×16 / 16px·400 (intercom.com Cream 캔버스)
             `#fff` 6px (fin.ai 다크 캔버스)
Compact Primary `#111111` 4px / 40px / 0×14
```

괄호가 `42px / 12×16 / 16px·400`을 **intercom.com으로 한정**하고, fin.ai에는 `#fff` 6px만
세우며, Compact에는 서체 칸이 아예 없다. 산출은 셋을 섞었다 — intercom.com 전용 서체를
Compact `:232`에, intercom.com의 padding·height·font를 fin.ai `:332`에 귀속했고,
Layout `:376`은 그것을 `the source footer records`라고 썼다.

**이 형태가 기존 검사를 통과하는 이유**: 모든 값이 원본에 실재한다. 값 grep도, 키 경로
대조도, sibling 대조도 통과한다. 잡히는 지점은 **어느 표면에 귀속됐는가**뿐이다.
동반 결함인 `40-42px`(원본 0 / sibling 2 / 산출 2)가 아니었다면 이 건은 더 늦게 발견됐을
것이다 — sibling 값 승격이 표면 혼합의 **증상**으로 함께 나타났다.

개정 후: `40-42px` dest 0, 세 표면 값 분리, 461→460행, 35=35 유지, gate PASS.
