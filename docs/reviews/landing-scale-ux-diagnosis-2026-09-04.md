# r3 가 70 → 60 으로 떨어진 이유 — 규칙 쪽 원인 진단 (2026-09-04)

> 사용자 지적(r3, 17:40): "사용자의 UX적인 관점을 충분히 반영하지 못했다. 이미지를 소극적인 사이즈로 쓰는 것, 매번 호버를 해야 펼쳐지고 돌아오는 애니메이션, 화려함 속에 숨어 있는 간결함과 시원시원함이 반영되지 않았다."

## 1. 한 줄 결론

**r3 는 우리 규칙을 전부 지켰고, 그 규칙이 틀렸다.** 검사기는 개수를 재고(LI-24~26), 게이트는 호버 관문을 요구하며(C8), 섹션당 3층을 허용한다(C1+C8). 세 규칙이 합쳐지면 "작은 것 많이 + 호버해야 보임 + 겹친 효과"가 최적해가 된다. 그게 r3 다.

## 3. 왜 이렇게 됐나 — 피드백 번역의 누적 편향

- r0→r1: "이미지를 그냥 쓴 느낌" → 이미지가 **행동**하는 섹션(동사) ⇒ 좋았다(30→60).
- 밀도 진단(09-03): 휑함 → **절대 바닥**(개수) ⇒ 좋았다(빈 화면 0).
- r1→r2: 효과 부족 → 스크롤 안무 + 라이브러리 ⇒ 좋았다(60→70).
- r2→r3: "스크롤 없이도 살아 있는 것·호버 팟" → **층을 하나 더** ⇒ 나빠졌다(70→60).

매 라운드 규칙을 **더했다.** 더할수록 화면당 요소와 층이 늘고, 큰 것 하나가 설 자리가 줄었다. 사용자가 말한 "화려함 속의 간결함"은 층의 합이 아니라 **큰 스케일 × 적은 요소**다. 다음 라운드는 규칙을 더하는 게 아니라 **상한과 크기 바닥을 넣고 호버 관문을 빼는** 라운드여야 한다.

## 5. 규칙 후보 (리서치 4레인 합성 후 확정)

- **크기 바닥**: 폴드 최대 미디어 ≥ N% 뷰포트, 본문 화면 중 최대 미디어 ≥50% 인 화면 비율 ≥ M — LI-34 후보.
- **호버 관문 금지**: 호버 없이 보이지 않는 콘텐츠 0. 호버는 강화(≤ 2% 리프트·감속·정지)만. 열림은 클릭/탭으로 **지속**, 자동 순환은 장식층에만 — LC-49 / LI-35 후보. C8 개정.
