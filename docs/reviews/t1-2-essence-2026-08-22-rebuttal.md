### 2. 정수가 정말 정수인가

T1-2 정의는 “이게 없으면 DESIGN.md가 아니다”(`docs/OMD_3TRACK_PLAN.md` 205행)다. 현행 실패 닫힘은 Core v2 Portable Core다.

`spec/design-md-core-v2.md` 205–230행, 581행이 요구하는 것은 세 덩어리다.

- Experience: 제품/표면 범위 + 일차 과업 1개
- Foundations: 실행 가능한 값/규칙 **또는** 명시적 제약 **1개**
- Governance: 권위, 적용 우선순위, unknown=absent, 변경 규칙

컴포넌트 본문 충만, 브랜드 연혁, 페르소나, 에이전트 프롬프트는 그 표에 **없다**. 112–115행은 문서 전체 600–1,800단어, exhaustive matrix는 그래프. 136–138행은 특성 3–5개·금지는 SHOULD, 연혁·페르소나는 권위가 있을 때만.

이 테스트에 섹션 전체를 넣으면:

- **통과하는 조각**: §1의 범위·과업·방향, §2·§3의 알려진 역할/값, §7의 적용 경계, §9의 unknown/우선순위.
- **§1 전체 8.58%**: 아님. nintendo §1(63–80행)은 §2·§3·§6을 다시 쓴 분위기 에세이다.
- **§4 전체 10.04%**: 아님. 판정 21행 스스로 “요약만 본문, matrix는 그래프”. 독립 파일에 컴포넌트 계약이 필요한 것과 10% 섹션이 정수인 것은 다르다.
- **§6**: 아님. 판정 23행 “별도 장문 섹션일 필요는 없어도 내용은 foundations에” — 그건 필드 잔류다. 같은 문장을 §14에는 위임으로 썼다(31행).
- **§11 전체 5.52%**: 아님. 규격 138행은 연혁을 조건부 SHOULD로 둔다. nintendo §11(357–363행)의 1889 화투 회사 연혁은 Portable Core MUST가 아니다.

§13만 필드 입자를 허용하고 §1·§4·§11은 섹션 정수로 둔 것은 같은 문서 안에서 입자가 갈린 것이다.

### 3. 위임 착지점이 실재하나

스키마에 칸이 있는 것, 440개가 그 칸을 쓰는 것, 칸이 그 내용을 담는 것은 다르다.

**§9.** `skills/omd-apply/SKILL.md` 133–160행은 프로젝트 DESIGN.md를 통째로 읽는다. 브랜드별 Agent Prompt 슬롯이 없다. 그래프 `governance`(스키마 336–344행)는 `priority` / `unknown_policy` / `change_policy` / `decisions`뿐이고 `additionalProperties: false`다. 프롬프트 필드가 없다.

카탈로그 §9는 범용 스킬이 아니다. nintendo 308–334행은 브랜드 적용 규칙(적색 단일 액션, 지역 서체). toss 306–311행은 Tossface 비승격, 미등재 컴포넌트=확장. 이걸 `omd-apply`로 보내면 **유실**이다. 빌더 매퍼는 이미 `agent prompt` → `governance`다(`web/src/lib/builder/design-md-core-export.ts` 186–188행). 착지는 스킬 파일이 아니라 **같은 DESIGN.md의 governance**다. 판정 60행 “별도 범용 prompt 파일을 새로 만들 이유는 없다”는 브랜드 예시를 **삭제**하겠다는 뜻이다.

**§14.** 받을 칸은 있다. 스키마 `components_states.components[].states`와 `components[].interaction.state_applicability`(246–267, 217–244행). `src/cli/book.ts` 207–223행이 후자를 읽는다.

다만 판정 61행 `` `interaction.state_applicability` ``는 그래프 루트에 없다. 올바른 경로는 `components_states.components[].interaction.state_applicability`다.

인스턴스는 카탈로그에 없다. Core v2 일치 **0/440**(조사 124행). 판정 57행 “저장소에도 graph.json이 존재한다”는 호스트 프로젝트 파일 하나다. 지금 440개에서 독립 §14를 지우고 그래프로만 보내면 마이그레이션 전 **유실**이다. 규격 205–212행은 사이드카 없이 “선언된 컴포넌트와 상태를 만들 수 있어야” 한다. “짧은 요약만 §4와 함께”(61행)는 그 MUST보다 얇다.

### 4. 이징 권고의 부작용

무출처 **커브** 삭제(선택지 1)는 조사 부록 140–178행과 맞다. 미리보기 CSS는 깨지지 않는다. `generate-css.ts`와 레퍼런스 AST(`schema.ts` 57–69행)는 motion 키를 읽지 않고, `omd book` 마크다운 폴백은 §15 표를 파싱하지 않는다.

깨지는 쪽은 **계약 문장과 재주입**이다.

1. `omd-apply`는 DESIGN.md 전체를 읽고 모션 요청을 트리거한다(SKILL.md 24, 137, 191–198행). 값이 있으면 브랜드 사실로 적용한다. 지우면 지어내지 말라는 경로로 간다 — 의도된 교정.
2. 빌더 export 기본값은 philosophy layer ON → §10–§15 유지. 사용자가 받는 텍스트에서 218/440의 `ease-exit`가 빠진다.
3. `spec/omd-v0.1.md` 261–262행과 playground `MOTION_RULES`(`web/src/lib/playground/rules/motion.ts` 45–50행)가 **같은** `cubic-bezier(0.4, 0, 1, 1)`로 §15를 다시 쓴다. 카탈로그만 지우고 라이터를 안 고치면 부록이 재적재된다.
4. `skills/omd-feel/reference.md` 47–50행은 Material decelerate/accelerate를 규칙으로 둔다. 판정 51행이 경고한 역승격 구멍이 이미 열려 있다.

duration·signature를 커브와 같이 지우라는 권고(32·38행)는 T1-1이 지지하지 않는다.

### 개정 항목

1. 정수를 Portable Core MUST 필드/그룹으로 다시 쓴다. §1·§4·§6·§11 섹션 정수를 철회한다.
2. 완비율·무게를 정수 증거 칸에서 뺀다. §15 삭제는 잰 **커브**로 좁힌다. 60.41%를 정수 질량처럼 읽지 않는다.
3. §9 브랜드 규칙은 본문 `governance`/`experience`에 남긴다. 440개 예시를 `omd-apply`로 보낸다고 쓰지 않는다. 삭제이면 삭제라고 적는다.
4. §14 경로를 `components_states.components[].interaction.state_applicability`로 고친다. 본문 잔류는 Core v2 §4.4를 만족해야 한다. 카탈로그 0그래프에서 “지금 그래프로 보낸다”를 실행 지시로 쓰지 않는다.
5. 선택지 1은 무출처 커브에 한정한다. v0.1 템플릿, playground `MOTION_RULES`, `omd-feel`이 같은 문자열을 재주입하지 못하게 같이 적는다.

§15 커브 의심, 완전일치 0.51%로 커브 반복을 가리지 말 것, 가상 persona를 sidecar로 승격하지 말 것은 유지한다.

VERDICT: REVISE
