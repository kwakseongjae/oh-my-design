# 밀도를 고쳤는데도 왜 와우가 없는가 — 마감(craft) 격차 계측

> 사용자 지적(2026-09-03): "이전보다 나아지긴 했는데 전혀 와우한 경험은 없다. 영상이랑 이미지, 화면적인 미감이나 완성도가 너무 떨어진다."
> 앞선 진단 [`landing-density-diagnosis-2026-09-03.md`]는 **양**을 고쳤다(미디어 5→28개, 빈 화면 7→0).
> 이 문서는 남은 **질**의 격차를 잰다.

## 1. 한 줄 결론

**우리 최고 산출물은 OS 기본 폰트로, 그림자·블러·마스크·블렌드·3D·클립패스가 전부 0인 평면 색 블록이다.**
양을 채워도 낱개의 질이 그대로면 와우가 생기지 않는다. 코덱스 LC-1~36은 기하·리듬·배치를 다루고
**마감(재질·깊이·타이포 마감·모션 정교함)에 대한 규칙이 하나도 없다.**

## 3. 원인

### 3.1 폰트 규칙이 아예 없다

`skills/omd-landing/SKILL.md`와 `landing-craft-codex.md` 어디에도 **서체를 어떻게 조달하라는 지시가 없다.**
브랜드 DESIGN.md의 `tokens.typography.family.ui`가 로드 불가면 「unknown = absent」 규칙에 따라 시스템 폰트로 떨어지고,
그 상태가 그대로 최종 산출이 된다. 생성기 잘못이 아니라 **파이프라인에 조달 경로가 없는 것**이다.

### 3.2 "외부 요청 금지"를 폰트 금지로 오해할 여지

랜딩 산출은 단독 HTML이고 외부 라이브러리·네트워크 요청이 금지다. 그래서 웹폰트를 아예 포기했다.
그러나 **생성 시점에 폰트를 받아 base64로 인라인하면 렌더 시 외부 요청은 0건이다.** 이 경로가 문서화되지 않았다.

### 3.3 재질·깊이·모션에 대한 규칙 부재

코덱스는 "무엇을 어디에 놓는가"까지만 규정한다. 그 위에 얹는 층 — 그레인, 비네트, 글로우, 유리, 마스크 리빌,
스크롤 연동 애니메이션, 스태거 — 은 규칙도 검사도 없어서 생성기가 시도할 이유가 없다.

## 4. 확보한 능력 — 가변 폰트 인라인 (검증 완료)

레포 머신에서 실측했다.

| 항목 | 결과 |
|---|---|
| 소스 | `@fontsource-variable/*` 의 latin woff2 (jsDelivr) |
| 파일 크기 | Fraunces 65KB · Bricolage Grotesque 75KB |
| base64 인라인 후 HTML | **87KB** |
| 적용 여부 | `document.fonts.check` true, 폴백 대비 폭 차이 확인 |
| **옵티컬 사이즈 축** | `opsz 9` 383.1px vs `opsz 144` 307.5px → **작동** |
| **굵기 축** | `wght 300` 315.2px vs `wght 900` 372.9px → **작동** |
| 렌더 시 외부 요청 | **0건** |
| 도구 | `pyftsubset`·`fonttools` 설치돼 있어 더 줄일 수도 있다 |

주의: Google Fonts `css2` API 는 UA에 따라 **정적 인스턴스**를 준다 — 그걸 받으면 가변 축이 죽는다.
가변이 필요하면 `@fontsource-variable` 파일을 직접 받아야 한다(위 실측이 그 차이를 보여 준다).
라이선스는 OFL 계열만 쓴다(임베딩 허용).
