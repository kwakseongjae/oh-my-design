## 상정 1 — T1-4 구조 편차

**판정: APPROVE_WITH_CONDITIONS**

계획의 「골든 3건을 도구로 재생산해 수동본과 diff 0」은 버린다. 정본은 **워커(판단) + 게이트(강제) + 규칙집(누적)** 이다.

이유는  intact하다. 마이그레이션은 권위 한정·가상 페르소나·증거 종류를 읽는 일이라 결정론 파서는 의미 반전을 재생산한다. 골든 3건이 기계 PASS + sol FAIL 3/3이었고, 미접촉 notion이 다시 기계 PASS + sol FAIL이었다. 그 FAIL이 규칙집 v2와 게이트 2종(B1 `focus-visible-promotion`, D1 `alien-negative-claim`)으로 누적된 루프는 설계대로 돌았다.

이번 세션에서 확인한 것:

| 검사 | 결과 |
|---|---|
| 게이트 musinsa / karrot / 29cm / notion | PASS 4/4 |
| `inspectDesignMd` `portable_core` + `[FILL IN]` 0 | true / 0, 4/4 |
| 합성 구본 (focus-visible 행에 hex + `storefront … were not captured`) | `MIGRATION_BLOCKED` — `focus-visible-promotion`, `alien-negative-claim` |
| 레퍼런스 수 | `web/references/*/DESIGN.md` = 440 |

구본 원파일은 트리에 없다. 차단 주장은 합성 재현으로 받았다. 이벤트 기록이 아니라 이 재현이 남아야 한다.

### 조건 (다음 grok 재심 없이, 웨이브 1 투입 전)

1. 계획 T1-4 행을 워커+게이트+규칙집으로 고쳐라. 실행 포인터가 diff 0을 가리키면 승인 직후 이전 실패를 다시 만든다.
2. 게이트 주석이 D2(가상 인구통계)를 기계화했다고 쓰지 마라. `gate()`에 그 검사가 없다. 기계화 목록은 코드와 같아야 한다: outputs · token-loss/invention · fill-in · states-preserved · na-inversion · coverage-claim(부정 인식) · focus-visible-promotion · alien-negative-claim · tool-prompt. 기계화되지 않은 조항은 A3·A4·B2·B3·C2·C4·D2·E2.
3. 게이트에 `inspectDesignMd` `portable_core: true`와 신규 `[FILL IN]` 0을 넣어라. 지금 로그에만 있고 `gate()`에 없다.
4. 워커 프롬프트의 규칙집 버전은 파일 헤더에서 읽어라. `v2` 하드코딩 금지.
5. 기계화 결함의 음성 픽스처를 남겨라 (최소 B1·D1·na-inversion). 게이트를 고칠 때마다 골든 3 + 승인 notion은 PASS, 음성 픽스처는 BLOCK.

T1-4 단계는 위 5항을 반영하면 닫힌다. 골든 3 + notion 승인본을 카탈로그에 넣지 마라.

## 상정 2 — T2-1 개시와 표본율

**판정: APPROVE_WITH_CONDITIONS**

상정 1의 조건 5항을 반영한 뒤에 연다. 웨이브는 **5개 id, 웨이브 내부만 병렬**. 다음 웨이브 워커는 이전 웨이브의 게이트 전수 + sol 표본이 끝난 뒤에만 시작한다. 웨이브를 파이프라인하면 FAIL → 규칙집 누적 → 소급 재실행이 공회전한다. 규모 읽기: 436 잔여(골든 3 + notion 제외) ≈ 88웨이브 × ~8분 ≈ 12시간. sol은 전수하지 않는다.

제안한 표본율은 아래 수정과 함께 받는다.

| 항목 | 결정 |
|---|---|
| 첫 3웨이브(15건) | 웨이브당 sol 2건 (40%) |
| 이후 | FAIL 0 **그리고** 그 6표본이 위험 프로파일 3종 이상일 때만 웨이브당 1건 (20%). 프로파일: (a) 토큰 밀도 스토어프론트 (b) 서사·§13 페르소나 (c) 결측·`[FILL IN]`·§9 고유값. 동질 15건이면 하향 금지 |
| sol FAIL | 다음 웨이브 정지. 그 웨이브 전수 재검토. 규칙집 누적. 표본율 40% 복귀 |
| 신규 계층이 기계화 가능 | 이전 웨이브 통과분 **게이트 소급** |
| 신규 계층이 기계화 불가 (C2·A3·A4·B2·D2 류) | 게이트만 다시 돌리지 마라. 이전 웨이브에 당시 표본율로 **sol 소급 재표본** |
| 게이트 FAIL | 즉시 개정 1회. 재실패면 그 id는 `MIGRATION_BLOCKED`, 통과 집합에 넣지 않음. 한 웨이브에서 재실패 ≥2/5면 웨이브 정지, 워커/규칙집을 먼저 본다 |
| 표본 선정 | 워커가 고르지 않는다. sol 레인은 sol이다. 워커와 같은 grok가 자기 산출을 표본 검토하지 않는다 |
| 산출 위치 | `docs/design-md-weight/migrated/<id>/` 만 |
| 카탈로그 | `web/references` 교체·quality manifest·count-sync는 T2-1 전체 완료 + **별도 최종 승인** 전 금지 |
| T2-3 | 닫힘. 이 승인은 신규 160을 열지 않는다 |
| 스킵 | musinsa, karrot, 29cm, notion |
| 웨이브 원장 | 각 웨이브에 id, 규칙집 버전, 게이트 판정, `portable_core`, sol 표본 id·판정을 남겨라 |
| Proof | 기존 freshness·source·claim ledger는 provenance에 남긴다. 원 계획의 「Proof 게이트 보존」 |

하향 뒤에도 sol FAIL이 나면 40%로 복귀한 채 그 다음 3웨이브를 다시 채운 뒤에만 재하향한다.
