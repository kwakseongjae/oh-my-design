# A5 copy-loss 게이트의 라틴 사각 — 코퍼스 44%가 무보호

**작성** 2026-08-26 · opus5 (오케스트레이터) · **발단** flex 이관 워커 보고

## 발단

flex 워커가 이관을 마치며 적었다: 원본 `DESIGN.md`에 비라틴 런이 **0개**라
`copy-loss` 게이트가 바늘을 하나도 만들지 않았고, **본문을 전부 의역해도 PASS가
나왔을 것**이다. 워커는 손으로 라틴 인용문 133개를 뽑아 42개 미생존을 찾았고 22개를
고쳤다. freee 워커도 같은 일을 했다(라틴 104개 추출, 0개 누락).

즉 두 워커가 게이트가 못 보는 자리를 각자 손으로 메웠다. 그건 다행이지만 **그 자리가
얼마나 넓은지는 아무도 재지 않았다.**

## 이 사각은 설계된 것이다

`migrate-reference.mjs`의 주석이 이미 이유를 적어 두었다. 바늘을 **연속 비라틴 런
4자 이상**으로 좁힌 것은 의도적 절충이다:

> 전체 인용문을 바늘로 쓰는 방식은 시도했다가 되돌렸다. legacy 파일은 카피만큼이나
> 설명을 인용한다(`Top utility nav (로그인 / 관심 / 최근)`). 전체 인용문 바늘은
> 발행된 적 없는 산문을 손실로 보고했고, 정작 그 안의 라벨은 살아 있었다.
> 늑대야 외치는 차단 게이트는 우회당하고, 그게 이 게이트가 막으려는 E3 실패 양식이다.

절충 자체는 옳다. 문제는 **절충의 대가가 얼마인지 숫자로 없었다**는 것이다.

## 실측

바늘 추출 로직을 그대로 코퍼스에 돌렸다 (같은 `QUOTED_COPY` 7형태, 같은 비라틴 4자 하한):

| | 수 |
|---|---|
| 레퍼런스 전체 | 440 |
| **바늘 0개 — A5 기계 무보호** | **195 (44%)** |
| 바늘 1개 이상 | 245 (중앙값 9, 최대 111) |

이관 완료본 125개로 좁히면:

| | 수 |
|---|---|
| 이관 완료 | 125 |
| **그중 무보호 상태로 통과** | **66** |

무보호 이관본에는 `apple` · `adobe` · `airbnb` · `claude` · `asana` · `airtable` ·
`aws-cloudscape` · `bbc` · `cashapp` 처럼 **영문 UI 카피가 브랜드 자산의 전부인**
레퍼런스가 몰려 있다. 카피가 곧 브랜드인 쪽이 정확히 무보호인 셈이다.

## 무엇이 문제인가

A5는 "발행 문자열은 바이트로 옮긴다"는 조항이다. 게이트가 있는 45%에서는 기계가 이를
강제하고, 없는 44%에서는 **워커의 성실성만이 강제한다.** 그런데 A5 조항 자체가 생긴
계기가 바로 워커가 성실하지 않았던 사건이다 — 웨이브 19에서 datadog이 검증 카피 6종을
의역하고(`SEE THE PLATFORM` → "inspect the platform") dcard가 번체 포럼명 9종을 영문
의역으로 갈아치웠다. 그 두 건은 **비라틴이라서** 나중에 기계로 잡혔다.

라틴 전용 원본에서 같은 일이 일어났다면 지금도 모른다.

## 게이트를 넓히면 되는가 — 아니다

전체 인용문 바늘은 이미 시도되고 되돌려졌다. 되돌린 이유(설명 산문의 오탐 →
차단 게이트 우회 → E3)는 지금도 유효하다. 라틴 인용문에는 비라틴 런 같은
"우연일 수 없다"는 성질이 없어서, 정밀도를 되찾을 값싼 신호가 없다.

현실적인 방향 셋:

1. **워커 절차로 승격.** 지금 flex·freee 워커가 자발적으로 한 것(라틴 인용문 전수
   추출 → 생존 대조 → 미생존 처분)을 **무보호 브랜드에서 필수 단계로** 규칙집에 적는다.
   기계가 못 하면 절차가 하되, 절차가 있다는 사실이 문서에 남아야 한다.
2. **무보호 여부를 게이트가 스스로 보고.** `copy-loss`가 바늘 0개일 때 조용히 PASS하지
   말고 `copy-loss: 바늘 0 — 이 브랜드에서 A5는 기계 검사되지 않았다`를 **출력에
   남긴다.** 통과와 미검사가 같은 화면으로 보이는 게 지금의 실제 위험이다.
3. **소급 감사 66건.** 이미 이관된 무보호 66건에 라틴 전수 대조를 돌린다. R2 개선
   트랙에 넣는다.

2번이 제일 싸고 즉효다 — 통과와 미검사를 구별하는 것만으로 워커가 자기 상황을 안다.

## 상태

**2번 구현됨** (2026-08-26). `gateTexts`에 `problems`와 별개인 `unchecked` 채널을 뒀다.
바늘이 0개면 게이트가 조용히 PASS하지 않고 이렇게 답한다:

    { "brand": "apple", "verdict": "PASS", "problems": [],
      "unchecked": [ { "check": "copy-loss",
        "detail": "원본에 비라틴 런이 없어 바늘이 0개다 — 이 브랜드에서 A5는
                   기계 검사되지 않았다. 발행 라틴 문자열을 손으로 전수 대조하라." } ] }

`verdict`는 건드리지 않는다. 미검사는 결함이 아니므로 차단하면 안 되고, 다만 **보이지
않으면 안 된다.** 자기검사에 두 케이스를 넣었다 — 라틴 전용 원본은 반드시 보고하고,
비라틴이 있으면 보고하지 않는다. 12/12 통과. 실측 확인: `apple`·`flex`는 보고,
`flo`(한국어 카피 7종)는 미보고.
