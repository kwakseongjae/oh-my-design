# 스크롤이 딱딱한 이유 — 코드 수준 원인 (2026-09-05)

> 사용자 채점(r4 65/100): "절제된 느낌은 괜찮았는데, 스크롤 기반의 움직임이 딱딱하다는 느낌과
> 무언가 누르지 않으면 애니메이션 되지 않는다는 느낌이 아쉬웠어."
> 대상: `test-v2/content-runs/aphrodite/higgsgen/runs/template-r4.html` `mountPins()` (600~625행).

## 1. 한 줄 결론

**r4 의 스크럽은 상태가 없다.** 스크롤 이벤트마다 위치를 읽어 값을 계산하고 끝난다 —
전 프레임 값을 향해 따라가는 항이 없고, 속도 항이 없고, 스크롤이 멈추면 그 프레임에 모든 것이 정지한다.
물리적으로 **위치의 함수**이지 **시간의 함수**가 아니다. 이것이 손끝에서 "딱딱하다"로 읽힌다.

## 2. 코드가 하는 일 (실제 구현)

```js
function tick() {
  var p = -el.getBoundingClientRect().top / travel;   // 스크롤 위치 → 진행률
  var e = clamp(p, 0, 1) / k;                          // 정착 대역(LC-48)
  var v = cubic ? 1 - Math.pow(1 - e, 3) : e;          // 이징을 '위치'에 적용
  if (Math.abs(v - last) > 0.0015) el.style.setProperty("--e", v);
}
addEventListener("scroll", () => { if (!raf) raf = requestAnimationFrame(tick); });
```

네 가지가 전부 빠져 있다.

| 빠진 것 | 결과 | 레퍼런스의 대응물 |
|---|---|---|
| **감쇠(lerp)** — `cur += (target - cur) * α` | 목표값에 즉시 도달. 휠 한 칸 = 애니메이션 한 칸(계단) | GSAP `scrub: 1`(≈1s 지연 추종) · Lenis `lerp .1` |
| **상시 rAF 루프** | 스크롤이 멈추면 같은 프레임에 정지 — **여운(settle)이 없다** | 상시 루프에서 매 프레임 `cur` 를 갱신 |
| **속도 항** | 빠르게 굴리든 천천히 굴리든 같은 위치=같은 그림. 관성감 0 | 속도로 스큐·블러·스케일·오버슈트를 준다 |
| **스무스 스크롤** | 마우스 휠의 이산 단계(100px)가 그대로 노출 | Lenis/Locomotive/ScrollSmoother 가 스크롤 자체를 보간 |

부수적으로 `Math.abs(v - last) > 0.0015` 임계는 값을 **양자화**한다. 느린 스크롤에서 갱신이 띄엄띄엄
일어나 계단이 하나 더 생긴다.

## 3. 왜 r2(70점)보다 나빠졌나

r2 는 GSAP ScrollTrigger 를 인라인하고 `scrub` 을 썼다. r3→r4 에서 **핀 엔진을 자작으로 바꾸며
`scrub: n` 의 감쇠까지 함께 버렸다.** 정착 타이밍(LC-48)·크기(LC-51)·무관문(LC-49)은 이겼는데,
**모션의 질감**은 r2 보다 후퇴했다. 점수가 70 → 60 → 65 로 움직인 궤적과 맞는다.

## 4. 두 번째 지적 — "누르지 않으면 애니메이션이 없다"

r4 의 자율 모션은 드럼(110px/s)·켄번즈(24s 에 5%)·패널 순환(5.2s) 셋뿐이고, 나머지 7개 섹션은
**스크롤 또는 클릭을 기다린다.** 폴드 픽셀 변화는 2.5초에 4.58% 로 0 은 아니지만,
**주기가 길고(24s) 진폭이 작아(5%)** 사람이 알아채는 문턱 아래다. 즉 "있지만 안 보이는" 모션이다.
레퍼런스 대역은 rx5-c 가 잰다.

## 5. 처방 (수치는 rx5-b·rx5-c 실측으로 확정)

1. **스크럽에 상태를 준다** — 상시 rAF + `cur += (target - cur) * α`. α 는 실측 대역에서.
2. **스무스 스크롤** — Lenis(MIT, ~7KB gz) 인라인 또는 자작 wheel 보간. 네이티브 스크롤 유지 여부는 접근성과 함께 판단.
3. **속도 결합** — 스큐/블러/스케일 중 하나만, 상한을 두고(레퍼런스 실측치 이내).
4. **양자화 임계 제거** — 상시 루프에서는 불필요.
5. **자율 모션 바닥** — 화면당 "보이는" 모션 1개: 주기 상한과 진폭 하한을 규칙으로(LC 신설).
6. **GSAP 재도입 판단** — `scrub: n` 하나로 1·4 가 해결된다(114.7KB raw / 예산 내). 자작 lerp 와 비교해 결정.
