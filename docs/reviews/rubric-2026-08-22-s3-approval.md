# §3 모델 평가자 개정 — 최종 승인

대상: RUBRIC.md §3 재제출본
일시: 2026-08-22

**판정: APPROVE_WITH_CONDITIONS** — C1~C6

핵심 지적: 세 arm이 같은 호스트를 쓰면 `자기 계열`이 셋 전부이거나 공집합이라
`bias_j`가 전 항목 N/A가 된다. 호스트만으로 조인한 진단은 아무것도 잡지 못한다.

## 1. 회피 → `bias_j`가 성립 불가를 푸는가

푼다. 원래 결함은 회피 1건 = 남은 2 = 전항 무효였다. §3.2(95–99행)가 회피를 삭제하고 3종이 전부 채점하므로 분모는 비지 않는다. `INSUFFICIENT_RATERS`를 §4.5·§7·§8에 넣는 요구는 소멸한다. 회피로 돌아가거나 4번째 계열을 요구하지 않는다.

**같은 호스트 → 비교 유지** 논거(118–120행)는 가법 `(평가자 × 호스트 계열)` 상수에만 맞다. 세 arm에 같은 +δ면 차이는 그 성분에 대해 비뚤리지 않는다. 레인 A는 이미지도 전부 Grok Imagine(§1 34행, §3.2 113행)이라 이 성분도 공통이다.

그 문장이 비교 전체를 보존한다고 말하면 틀린다.

- 같은 호스트에서 자기 계열 = 세 arm이거나 공집합이다. `mean(타 계열)` 또는 `mean(자기 계열)`이 비어 `bias_j`(101–105행)는 N/A다. CI 하한 > 0이 성립하지 않으므로 `SELF_PREFERENCE`는 안 붙는다. `COMPROMISED`와 같은 처리라는 말은 플래그가 붙을 때에만 성립한다.
- 호스트가 같아도 산출물 분포는 방법론이 만든다. grok가 omd 모양을 더 높이 주는 친화는 공통 +δ가 아니고, 식이 계열 대비가 없어 구분하지 못한다. 이 성분은 통과한다.
- 레인 B 네이티브 이미지는 공통 모드가 아니다. 표는 Impeccable `gpt-image-2 → openai`(115행)만 있고 omd·hallmark 행이 없다. 시각 축에서 평가자×이미지 계열은 arm 간에 다르다. 처치이거나 교란인데, 본문은 둘을 동시에 주장한다.

## 3. 미정 arm 호스트

공유 호스트가 **어느 모델인지**는 §9(546행) 실행 전 결정으로 충분하다. 이 승인을 막지 않는다.

세 arm이 **서로 다른** 호스트를 쓸 수 있는지로 남기는 것은 막는다. 그때 비교 대상이 팩이 아니라 팩+모델이 되고 `bias_j`는 처치와 공선이다. 본문은 “표준 설계다”(118행)만 있고 SHALL이 아니다. 114행 “어느 모델에서 돌릴지”는 공유 선택과 암별 선택을 같이 연다. 이 분기는 지금 닫을 규칙이다.

## 4. 동결 전 조건 (C1–C6)

회피·4번째 계열·`INSUFFICIENT_RATERS` 부활은 조건이 아니다.

1. 같은 호스트 SHALL. 어느 공유 모델인지는 §9.
2. `자기 계열` 조인 키를 (H) 호스트만 / (H∪I) 호스트 또는 이미지 중 하나로 고정. `|own| ∈ {0,3}`이면 `bias_j = N/A`, `SELF_PREFERENCE`를 N/A에 붙이지 않음. (H∪I)를 고르면 레인 B 시각 축이 섞인 총점의 단독 우승이 닫힌다고 본문에 쓸 것.
3. 레인 B 이미지 계열을 지금 표에. 호스트 미정과 다르다. omd ≈ Grok Imagine, Impeccable `gpt-image-2`, hallmark Nanobanana/Recraft (`3track-plan-2026-08-22-grok.md` 62행).
4. “arm 간 비교는 유지된다”(119행)를 가법 호스트 정체성으로 한정. 리포트가 쓰지 못할 문장: 같은 호스트이므로 자기선호가 없다 / `bias_j`로 재서 통과했다.
5. `bias_j`는 레인별·축별. bootstrap 군집은 §7(518–521행)과 같게 브랜드 1차, run 2차.
6. §7 예비는 결원 슬롯의 같은 계열 재호출. 4번째 계열 투입 금지.

C1–C6가 본문에 들어가기 전에는 이 개정을 동결 본문으로 채택하지 않는다. T3-3과 `RUBRIC_FROZEN_SHA`는 닫힌다.

VERDICT: APPROVE_WITH_CONDITIONS
