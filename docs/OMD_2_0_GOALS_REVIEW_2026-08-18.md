# OmD 2.0.0 목표 리뷰 — 2026-08-18 (ONZIP 판정 이후)

> 사용자 총평: "이 정도면 UIUX Pro나 Impeccable + shadcn 쓰고 말지, 굳이 디자인
> 시스템 안 만들어도 저것보단 낫겠다는 느낌. 하네스도 디자인 시스템도 결과물도
> 없는 것보다 못하다." — 이 판정을 기준점으로 삼는다.

## 1. 판정 수용 — ONZIP에서 확인된 결함

| # | 결함 | 근본 원인 |
|---|---|---|
| 1 | 한글이 세리프 폴백으로 렌더 — 언어권 타이포 무시 | 시각 계약의 "display/body 페어" 규범이 라틴 전제. 한글 스택(Pretendard/Noto Sans KR), keep-all, 행간·자간 규칙이 시스템에 없음 |
| 2 | "data.json products를 내림차순 정렬한…" 구현 어휘가 UI에 노출 | 패치 8의 "KPI 정의 병기"를 레지스터 규정 없이 지시 → 모델이 엔지니어 말투로 이행. 정의는 사용자 언어("리뷰 많은 순")여야 함 |
| 3 | 라우트 전환 시 스크롤 위치 유지 버그 | SPA 기본기(scroll restoration, 포커스 이동, per-page title) 체크리스트 부재. 어떤 감사도 이를 측정 안 함 |
| 4 | 카드 패딩·간격 방치 (이미지-본문 폭 불일치, 행간 리듬 없음) | 컴포넌트 "내부 해부"(media/body 패딩, 라벨-제목-가격-메타 행 간격) 스펙이 계약에 없음. 서점용 헤어라인 장르를 커머스에 그대로 적용 — 장르-도메인 적합성 규칙 부재 |

## 2. 더 근본적인 문제 — 측정과 품질의 괴리

- e9 "게이트 통과(3승 6무 0패)"는 **결정론적 감사**(상태 도달·aria·반응형 오버플로·
  데이터 충실도)의 통과다. 이 감사들은 위 4개 결함 중 **하나도 잡지 못한다.**
- 자가 비평 루프(critique.md)는 소스 코드만 읽고 채점했다. **모델이 자기가 만든
  화면을 한 번도 보지 못한 채** "Execution 4점"을 매겼다.
- 결론: 우리는 측정 가능한 것을 최적화했고, 그 순간 측정이 목표를 대체했다.
  벤치마크 승리는 유지되는 사실이지만, **v2.0.0 릴리스 근거로는 무효**다.

## 3. 2.0.0의 약속 재확인

> **"디자인 시스템 우선 하네스는, 스킬 없이/프롬프트만으로/shadcn 조립으로 만드는
> 것보다 눈에 보이게 나은 제품을 만들고, 그 시스템이 DESIGN.md로 이식된다."**

도달 판정 기준을 결정론 감사에서 다음 3중 게이트로 교체한다:

1. **G1 결정론 감사** (현행 유지 — 필요조건일 뿐)
2. **G2 렌더 비평 게이트** — 실제 렌더된 스크린샷(주요 페이지 × 뷰포트)을 보고
   하는 비평을 통과. 자가 비평도 스크린샷 기반으로 전환.
3. **G3 인간 판정 게이트** — 블라인드로 경쟁 산출물(UIUX Pro, Impeccable,
   shadcn 조립 베이스라인 포함)과 나란히 놓고 "**이건 쓰겠다**"는 판정을 받는다.
   이 판정이 나기 전까지 v2.0.0은 릴리스하지 않는다.

## 4. 재건 계획 (패치 9 사이클)

우선순위순. 각 항목은 하네스 규범 + 검증 수단을 함께 갖춘다.

1. **렌더-피드백 루프 (하네스 구조 변경)** — 빌드 후 하네스가 주요 페이지를
   렌더한 스크린샷을 모델에게 돌려주고, 모델은 화면을 보고 1회 수정한다.
   벤치마크 셀에서는 외부 렌더러(감사 인프라)가 스크린샷을 공급하는 2-패스
   구조. 자가 비평은 소스가 아니라 화면에 대해 수행.
2. **로케일 타이포 계약** — 콘텐츠 언어를 감지해 언어권 규칙 적용. 한국어:
   Pretendard→Apple SD Gothic Neo→Noto Sans KR 스택(디스플레이·본문 모두 한글
   커버 페이스), `word-break: keep-all`, 본문 행간 1.6–1.8, 한글에 타이트
   트래킹 금지, 국문+숫자 혼용 시 숫자 전용 처리, 세리프 디스플레이는 한글
   전용 페이스가 있을 때만.
3. **UI 카피 레지스터 규칙** — 구현 어휘(data.json, length, 함수명) 화면 노출
   전면 금지. 집계 정의는 사용자 언어("리뷰 많은 순 상위 4개"). 샘플 고지는
   푸터 1줄로 강등, 배너 금지.
4. **SPA 기본기 체크리스트** — 라우트 전환 시 scroll-to-top(+뒤로가기 복원),
   포커스 이동, per-page `document.title`, 이미지 lazy 규칙. 멀티페이지
   감사기에 라우트 전환 스크롤 검사 추가.
5. **컴포넌트 해부 스펙** — 카드/리스트 행의 내부 구조를 토큰으로 고정:
   media 폭=본문 폭, 본문 패딩 스텝, 라벨-제목-가격-메타 행 간 간격 스케일,
   액션 정렬. "카드를 만들라"가 아니라 "이 해부를 채우라".
6. **장르-도메인 적합성 표** — 커머스=명확한 카드 표면·강한 가격 위계,
   운영 대시보드=밀도·상태 우선, 에디토리얼=룰 밴드. 서점에 맞던 장르를
   커머스에 이식하는 실패를 규칙으로 차단.

검증: ONZIP을 같은 fixture로 재도전 → G1+G2 통과 후 사용자에게 G3 판정 요청.
"이건 쓰겠다"가 나올 때까지 이 사이클을 반복하며, 그때까지 2.0.0은 열지 않는다.

## 5. 유지되는 것

- 컨트롤러/드라이체크 파이프라인(25/25), fixture-gen, 감사 인프라, 봉인 규율은
  전부 유효한 자산이다. 문제는 인프라가 아니라 **품질 정의**였다.
- e6–e9 기록은 결정론 게이트의 역사로 보존한다. 재해석하지 않는다.
