# oh-my-design

> AI 코딩 에이전트에 품질 등급이 표시된 디자인 근거를 연결하는 오픈소스 하네스. Claude Code, Codex, OpenCode에는 전체 번들 스킬 31개와 에이전트 정의 20개를, Cursor 2.4+에는 호환 Agent Skills 30개와 작은 프로젝트 rule, 로컬 카탈로그를 설치합니다. 품질 등급이 표시된 DESIGN.md 레퍼런스 523개 중 verified_v2 301개, partial 109개, legacy 113개이며 공개 데모에는 verified_v2를 사용합니다.

## 제품 모델

oh-my-design의 고유한 흐름은 다음과 같습니다.

`검증된 레퍼런스 → 프로젝트 DESIGN.md → 실제 구현 → 정합성 재검증`

CLI는 두 번째 디자인 앱이 아니라 부트스트래퍼입니다. Claude Code, Codex, OpenCode에는 채널별 스킬·전문 역할·로컬 카탈로그를, Cursor에는 호환 Agent Skills와 `.cursor/rules/omd-design.mdc`, 공용 `.claude/data` 카탈로그를 설치하고 상태를 진단합니다. 실제 디자인 작업은 각 채널에 설치된 기능 범위 안에서 자연어로 요청합니다. 코어 설치와 로컬 흐름에는 별도 AI 호출, API 키, 데몬, MCP 서버가 필요하지 않습니다.

## 설치와 진단

```bash
npx oh-my-design-cli@latest
```

에이전트를 재시작한 뒤 한 번 검증합니다.

```bash
npx oh-my-design-cli@latest doctor
```

채널별 비대화형 설치:

```bash
npx oh-my-design-cli@latest install-skills --agent codex --all
npx oh-my-design-cli@latest install-skills --agent claude-code --all
npx oh-my-design-cli@latest install-skills --agent opencode --all
npx oh-my-design-cli@latest install-skills --agent cursor --all
```

## 첫 프롬프트 — Claude Code, Codex, OpenCode

```text
가족 자산관리 앱에 차분하고 신뢰감 있는 디자인 시스템을 잡아줘.
검증된 레퍼런스를 추천하고 차이를 설명한 뒤 DESIGN.md 작성 전에 확인해줘.
```

그다음에는 구체적인 제품 화면을 요청합니다.

```text
DESIGN.md를 적용해 홈 화면을 개선해줘.
기존 라우트와 동작은 보존하고 결과를 검증해줘.
```

## Cursor 경로

Cursor 2.4+는 `.cursor/skills/`에서 호환 OmD Agent Skills 30개를 읽고, 작은 프로젝트 rule과 공용 `.claude/data` 카탈로그를 함께 받습니다. 설치 후 Cursor를 재시작하고 자연스럽게 요청하거나 `/omd-init`을 직접 호출하세요. OmD 서브에이전트 정의와 활성화 hooks는 Cursor에 설치하지 않습니다.

구형 Cursor에서 `--cursor-rule-only`(rule + 카탈로그 호환 모드)를 쓴다면 다음 중 하나로 프로젝트 DESIGN.md를 만듭니다.

1. https://oh-my-design.kr/design-systems/<id> 레퍼런스 페이지(원문은 https://oh-my-design.kr/<id>/design.md)에서 `DESIGN.md`를 프로젝트 루트에 내려받거나,
2. Cursor에게 `Read .claude/data/references/toss/DESIGN.md and create a root DESIGN.md for this product using confirmed values only. Keep unknown facts absent.`라고 요청합니다.

이후 `@DESIGN.md를 읽고 동작은 유지한 채 홈 화면을 다시 디자인해줘`라고 요청합니다. rule의 우선순위는 `DESIGN.md` → `.omd/preferences.md`의 대기 중 교정 → 프레임워크 기본값입니다.

## 공개 스킬 10개

`npx skills add kwakseongjae/oh-my-design`이 보여 주는 스킬이며, 하나씩 따로 설치할 수도 있습니다(`--skill <이름>`). `npx oh-my-design-cli`는 전체 번들 스킬 31개를 설치합니다. 이 10개에 워크플로가 스스로 부르는 내부 스킬(취향 루프, shim 동기화, 리뷰·글쓰기 역할, 라이브 캡처, 실험)이 더해지며, 내부 스킬도 그대로 동작하고 목록에만 나오지 않습니다.

- 시스템: `omd-init`, `omd-apply`, `omd-autopilot`
- 인터페이스 품질: `omd-feel`, `omd-restraint`, `omd-slop-audit`
- 문장: `omd-humanize`
- 화면: `omd-landing`, `omd-shader-hero`, `omd-cjk-type-shader`

## 핵심 계약

1. 프로젝트 `DESIGN.md`가 UI 작업의 정본입니다.
2. 모르는 레퍼런스 데이터는 그럴듯한 폴백으로 채우지 않고, 가장 작은 미확정 필드·항목·빈 그룹만 생략합니다.
3. 마케팅·기업·폰트 카탈로그·제품 화면은 서로 다른 증거 도메인입니다.
4. 사용자는 Home → `/design-systems/[id]` 레퍼런스 페이지에서 레퍼런스를 보고 DESIGN.md를 복사·다운로드합니다.
5. UI 작업은 실제 제품 라우트와 상태를 검증한 뒤 완료합니다.
6. 사용자 교정은 `.omd/preferences.md`에 범위 있는 선호로 남깁니다.
