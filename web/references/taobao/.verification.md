# Taobao — Verification Notes (2026-09-22)

Pipeline: CN expansion wave 2, brand #2 · Brand: Taobao (淘宝), Alibaba Group

## Scope and collector boundary

- Playwright-driven Chrome, 1440×1000, `zh-CN` with a matching `accept-language`, light
  scheme forced, `getComputedStyle` on the document element and on individual controls,
  clicks suppressed in the capture phase.
- Logged out. No account was created and no sign-in was attempted.
- Desktop only. The mobile surface and the app were not measured.

## Namespace ownership — the nonsense-path control

`https://www.taobao.com/zz-this-does-not-exist` does **not** serve the homepage. It redirects
to `https://error.taobao.com/tbpc/error.html?from=…`, a distinct 827-character error page —
so this site is not a catch-all and the homepage reading is a real route.

The redirect target is more useful than the control it was run for: the path is literally
`/tbpc/`, and the error page carries three of the same properties
(`--tbpc-primary-theme-color` `#ff5000`, `--tbpc-secondary-color` `#7a7a7a`,
`--tbpc-primary-theme-alpha-color` `#fff1eb`). `--tbpc-` is Taobao's own PC namespace,
loaded even on the error route. The error page's other two properties (`--bg-primary` `#fff`,
`--primary` `#3178f6`) belong to the error template and are **not** recorded.

`design.taobao.com` does not resolve (NXDOMAIN), so there is no official Taobao
design-system site to cite. Alibaba's Fusion Design (`fusion.design`, 200) is a component
library published by Alibaba, not a Taobao brand reference, and is not cited.

### The measurement that had to be redone

The first pass read focus per control, interleaved with that control's hover and mousedown.
It reported `:focus-visible` true on control [0] and **false** on control [1] — which reads
like a finding and is not one. Chrome's `:focus-visible` heuristic keys on the last *user*
interaction anywhere on the page, so control [0]'s `mousedown` set the modality to pointer
and control [1]'s later programmatic `.focus()` was then suppressed. Per-control ordering is
not enough; the contamination crosses controls.

Re-measured with the passes fully separated — rest and focus read for **every** control
before the mouse moved at all, then hover and press — **both** controls report
`:focus-visible` true. The earlier false is discarded as a probe artifact.

This extends `docs/MEASUREMENT_METHOD_2026-09-22.md` §2, which fixed the order *within* a
control. Other references measured with the per-control order and reporting a focus false —
weibo among them — may carry the same artifact and should be re-checked before their focus
claims are relied on.

### What the empty state diff means

`:hover` matched true on both controls while the hover reading was taken, so the state was
live and simply has nothing declared. `:focus-visible` matched true while `outline-style`
stayed `none`, so focus is recognised and draws nothing. Both are recorded as measurements
of the surface, not as gaps in the capture. The `hover` / `pressed` / `focus` values in the
token block are therefore the rest values, and §4 and §14 say so in the same words.

## Second surface — world.taobao.com

`https://world.taobao.com/` (HTTP 200, title "Taobao | 淘寶", 1,738 characters) returned
**the same 28 property names with zero value differences** from `www.taobao.com`. This is a
cross-confirmation, not merely proof of ownership: the `--tbpc-*` set is brand-wide, so a
token read from the home route is not a page-local override.

## Surfaces measured and rejected

`https://s.taobao.com/search?q=…` returned HTTP 200 with an **empty title and 160 characters
of body text** — a shell, not a rendered search page. It exposed eleven `--tbpc-*` properties
the home route does not, including `--tbpc-layout-page-margin-lg/xl` `48px`,
`-xxl/xxxl/xxxxl/xxxxxl` all `80px`, and `--tbpc-split-main-width` `1440px`.

Not recorded, for two reasons. The page rendered nothing, which is the shape that
disqualified zhipu in this same wave. And `--tbpc-split-main-width` came back as exactly the
viewport width, so these are resolved-at-this-viewport values, not the authored scale —
six "steps" collapsing to two distinct numbers is what a clamp looks like, not a spacing
system. `tokens.spacing` is therefore absent rather than guessed.

## Tier 2 cross-checks

getdesign.md and refero.design return no Taobao record — the ordinary CN outcome, and why the
regional rule requires two brand-owned sources. Both token sources here are Taobao-owned.
The third source, Alibaba Group's business page, is first-party for the company facts in §1
and §11 and is cited for nothing else.

## Evidence limitations

- **Two controls.** Both are the same orange fill; no secondary, ghost, input, tab or toggle
  component was measurable on the logged-out home.
- **No font token and no webfont.** `system-ui` and `PingFang SC` are the OS; `family` is
  absent rather than filled with a system stack.
- **No shadow, no spacing scale, no motion values** — none exist in the 28 properties, and
  the only surface serving layout tokens did not render.
- **`--tbpc-disable-alpha-color` `rgba(108,20,20,.2)`** is recorded in prose as found. It is
  a dark red where the rest of the ramp is black, and no rendered use of it was observed, so
  it is described and not promoted to a token.
- Desktop 1440×1000, light scheme, logged out.
