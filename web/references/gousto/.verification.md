## Namespace ownership and the nonsense-path control

212 first-party root custom properties beyond **31 `--cc-*`** vars, which match the open-source
"vanilla-cookieconsent" (orestbida/cookieconsent) library byte-for-byte in variable naming —
confirmed by `window.initCookieConsent` being present and `.cc-link` DOM elements. Excluded
entirely. `--cc-font-family` chains to Gousto's own Axiforma stack, the one leak of brand data into
the vendor namespace — not evidence the vendor variables themselves are brand tokens.

No `--tw-*`, `--mui-*`, `--mantine-*`, or other known framework prefixes were found in the
enumeration; the remaining 212 are first-party, despite reading as several generations of
component-library/redesign work layered on the same site (four parallel type-scale namespaces,
three parallel grey ramps).

**Nonsense-path control:** `https://www.gousto.co.uk/zz-this-does-not-exist` → HTTP 200, "Oh
crumbs!" 404 body, 785 characters — byte-identical to `/about-us` and `/our-story`, which are
therefore not real pages despite their 200 status. `https://www.gousto.co.uk/jobs` → HTTP 200, a
genuinely distinct 3,862-character page ("Give your career some Gousto"), confirming the control is
discriminating correctly. No `/design-system`, `/brand`, or similar path returns a distinct 200;
given the SPA's fallback behaviour, this reference does not claim a design-system page exists.

**"Zest" — not used.** Searched directly for "Gousto" + "Zest" + design system; nothing ties the
two. The only design-system material found is a third-party portfolio case study by Dominic Pegg (a
former Gousto product designer, cross-checked against a Gousto Engineering "Meet the Team" post)
describing an unnamed system — its host's TLS handshake fails (`ERR_SSL_PROTOCOL_ERROR`, confirmed
independently, not a tool restriction), so its content beyond the search snippet could not be
verified and is not used as a source for any claim.
