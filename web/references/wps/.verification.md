Pipeline: CN expansion wave 3, brand #1 · Brand: WPS Office / 金山办公 (Kingsoft Office)

## Namespace ownership — two controls, and the second one mattered

**Nonsense path.** `https://www.wps.cn/zz-this-does-not-exist` returns a real **HTTP 404**
with **zero** custom properties and 26 characters of body text. This site is not a catch-all,
so the homepage reading is a real route. (Compare hisense.com, checked in the same sweep,
which returns its homepage for any path and was set aside for that reason.)

**Is `--kd-*` somebody else's library?** This is the trap that disqualified TDesign, Arco and
the rest, and the prefix is short enough to belong to anyone. A search for a Chinese design
system called "KDesign" returns **Kingdee's** `kingdee.design` — a different company
(金蝶, not 金山) whose name transliterates the same way. So the question had to be answered,
not assumed.

Two things answer it:

1. **Neither `kingdee.design` nor Kingsoft Cloud's `design.ksyun.com` declares a single one of
   the 293 `--kd-*` names.** Overlap: 0 and 0. (Limit of this test: both are marketing shells
   and may simply not load their own library's tokens, so it is corroborating, not decisive.)
2. **The values are wired to WPS's own brand.** `--kd-color-line-public` is
   `rgba(30,95,199,1)`, which is `#1e5fc7`, which is `--wps-color-primary`. A stock
   third-party library would carry the library's default here, not this product's blue. And
   the rendered component class on the page is `kdv-button`, matching the prefix.

Taken together: `--kd-*` is Kingsoft's own system, themed for WPS.

### Focus

All five controls match `:focus-visible` and **change no property**. `outline-style` is `none`
at rest and still `none` under focus, which means the author overrode the browser's UA ring
rather than simply not adding one. Recorded as a measurement.

Read per `docs/MEASUREMENT_METHOD_2026-09-22.md` §2 (rest and focus for every control before
the mouse moves) and §2.5 (an `auto` outline would have been Chrome's, not the brand's — none
appeared here).

### The one control that was not declared

The blue hero button sits inside the carousel and another layer covers it. Hover was attempted
twice and failed both times: once with raw pointer moves (`:hover` matched false at the
control's centre) and once through `web/scripts/probe-component-states.mjs`, which reported
`locator.hover: Timeout 8000ms exceeded` and printed the state as **못 쟀음 — unmeasured**.
Its rest and focus readings are real. It is documented in §4 and left out of `components`,
because a control whose hover nobody has seen is not a component here.

**Unmeasured is not absent.** This is the distinction the probe script was changed to keep
visible on 2026-09-22, after a state failure had previously killed the whole run.

## Evidence limitations

- **One measured surface.** kdocs.cn was not measured for tokens; the desktop application and
  the editors were not opened.
- **No webfont and no brand face.** `--kd-font-family` and `--wps-font-family` resolve to a
  pure system stack, so `tokens.typography.family` is absent rather than filled with it.
- **No shadow token and no shadow observed**; the z-index scale is recorded in prose.
- **No spacing scale.** `--kd-*` publishes none, and the `--wps-*` gaps are this page's.
- Responsive variants are declared in the token names (`-compact`, `-mobile`) but **no second
  viewport was measured**, so §8 states the intent and claims no breakpoint.
- Desktop 1440×1000, light scheme, logged out.
