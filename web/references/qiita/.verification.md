`--line-*` 5 · `--markdown-*` 3 · `--advent-*` 2 · `--scrollbar-*` 1 · `--elevation-*` 1. No

**But five entries inside `--color-*` are other companies' brand tints**, authored by Qiita and

Share targets and a partner. They are recorded in the reference as `social-*` and `partner-*`
so a consumer cannot mistake GitHub's near-black for Qiita's ink. `--color-twitter` being
`#000000` rather than the old blue dates the token to after that rebrand.

No nonsense-path control was run on this host; the reference cites **one route only**, so no
sub-route is relied on. Recorded as a limitation below.

### The font question, measured here

**`tokens.typography.family` is absent, and the reason needs stating** because the census says
otherwise at first glance.

```
census family (first name in stack):  YakuHanJPs ×1,554
document.fonts entries:               Material Symbols Outlined (loaded)
                                      FontAwesome              (unloaded)
full stack: YakuHanJPs, -apple-system, "system-ui", "Segoe UI",
            "Hiragino Kaku Gothic ProN", "Hiragino Sans", "Noto Sans JP",
            "BIZ UDPGothic", Meiryo, sans-serif
```

**`YakuHanJPs` is not among the loaded faces.** It leads the stack and falls through; the text
renders in the OS stack. `document.fonts.check('16px YakuHanJPs')` returns **`true`**, which is
not evidence — `check()` answers "can this be drawn without loading anything more", and a
fallback satisfies it.

This is the case that prompted `docs/MEASUREMENT_METHOD_2026-09-22.md` §2.6, and auditing the
rest of today's references against it found one error elsewhere (deepseek's Fragment Mono).

**Two more census entries are artifacts**, named so nobody promotes them:
`Times` ×236 is non-visual `<html>` / `<head>` / `<script>` nodes taking Chrome's serif
default, and `Arial` ×156 is unstyled `<input>` and `<button>` elements falling to the UA's
form-control font — real on the page, but not authored by Qiita.

### Focus — six families, zero authored rings

Every one of the six computes `outline: rgb(0, 95, 204) auto 1px` under focus. `auto` is the
tell (`docs/MEASUREMENT_METHOD_2026-09-22.md` §2.5), and there is no focus token among the 129.

Six independent component families agreeing is strong, but it is still six controls out of a
page, and an article route or the search input was not sampled. The reference states the
finding as measured and does not extend it to "site-wide".

### The primary button is not fixed, and that is a placement decision

The header pairs 新規登録 **filled** with ログイン **outlined**. A recirculation panel lower
down reverses them. Both use the same two components with the same values, so this is where a
button sits, not two different primaries. Flagged here so it is not later read as an
inconsistency in the palette.
