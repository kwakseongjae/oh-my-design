# SmartHR — Verification Notes (2026-09-21)

Pipeline: live re-measure of an existing `legacy_snapshot` reference · Brand: SmartHR (kufu, Inc.)

## Scope and collector boundary

- Measured with Playwright-driven Chrome (1440×900, light), reading
  `getComputedStyle(document.documentElement)` for published custom properties and computed
  styles on rendered components. No stored collector bundle exists for SmartHR.
- **Two first-party surfaces, deliberately kept separate:**
  - `smarthr.design/products/design-tokens/` — the design system's own site. Publishes 22
    `--color-*`, 16 `--font-size-*` and 2 `--leading-*` custom properties.
  - `story.smarthr-ui.dev` — the official smarthr-ui Storybook (988 stories, 144 components).
    smarthr-ui publishes **no** custom properties of its own; values compile into Tailwind
    utility classes under the `shr-` prefix, so component values are read off rendered DOM.
- The docs site is documentation, so the PayPay trap applies: not every property on it is a
  product token. `--color-divider-search-h2` and `--size-content-width` are docs-site chrome
  and are **not** promoted. Only roles corroborated by a rendered component, or named as a
  palette role, are recorded.
- SmartHR's product is behind authentication. No authenticated product surface was captured.

### Fonts

- **No family token is published.** The design system's token set has `--font-size-*` and
  `--leading-*` and no font-family entry, so `tokens.typography.family` is omitted rather
  than filled.
- **smarthr-ui components compute `system-ui`** — the OS UI font. Recorded as an observation;
  a system stack is never promoted to a brand face.
- **smarthr.design renders `SDSYuGothic`** (a webfont scoped to the design-system site) and
  **smarthr.jp renders `AdjustedYuGothic`**. Three surfaces, three faces, none a product-font
  token.

## Source-domain separation

| Domain | Sources | What it supports | What it does not support |
|---|---|---|---|
| Design-system documentation | `smarthr.design/products/design-tokens/` | Named palette roles, the 16-step size scale, the 2 leading tokens | Component geometry or state; and its own chrome tokens are not product tokens |
| Published component library | `story.smarthr-ui.dev` story frames | Component geometry, variants, hover/pressed/disabled values | Which components the authenticated product composes, or its density |
| Official repository | `github.com/kufu/smarthr-ui` | That smarthr-ui is SmartHR's own library | Current computed values |
| Corporate marketing | `smarthr.jp` | Font observation only (`AdjustedYuGothic`) | Any product token — a separate evidence domain |

## Earlier values removed or bounded

- Nine of fifteen declared colours held up; the four semantics and `accent-orange` did not,
  and all four semantics were wrong in hue family, not just in shade (`success` was declared
  a green and measures a teal).
- The four `notice-*` tint components and the generic `badge` are removed: no published
  component in 144 matches them. `card` is removed for the same reason.
- `rounded.sm` (4) and `rounded.lg` (8) are removed; only 6px and the pill were observed.
- §4's roster note previously said "61 published, none measured here". It now reads 144
  published, 8 measured.

## Evidence limitations

- SmartHR's actual product is behind authentication. Everything here is the **published
  design system and its component library**, not the running product; §5 (layout), §8
  (responsive) and §15 (motion) remain earlier-pass prose and are not covered.
- 8 of 144 published components were measured. The rest are named in the roster, not claimed.
- No dark theme is published by either surface, and none was measured.
- Tier 2 cross-checks: getdesign.md and refero.design return no SmartHR record, which is the
  ordinary JP outcome and why the regional Tier-1 ≥ 2 rule applies.
