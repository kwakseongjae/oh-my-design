# /hangul before/after eval (2026-09)

A summary of OmD's before/after eval of this skill, run on 2026-09-29. The full write-up, the eval plan with the prompt text, and the raw per-run results live in the oh-my-design repository (`docs/research/2026-09-29-growth/`, raw results under `raw/hangul-eval/`), not in this skill folder.

**Result:** without the skill, 17 of 18 runs broke at least one Korean typography rule (BLOCK or WARN). With `/hangul`, all 18 runs had 0 BLOCK and 0 WARN.

## Design

- **Prompts:** 3 Korean UI tasks: p1 fintech hero, p2 mobile settings page, p3 pricing section.
- **Arms:** A has the prompt only. B has the same prompt plus one line: "이 작업에는 hangul 스킬을 적용한다: .agents/skills/hangul/SKILL.md를 읽고 그대로 따른다", with the skill folder copied into the project.
- **Runs:** 3 per prompt × arm × channel, 36 total.
- **Channels:**
  - Codex CLI 0.158.0, `gpt-6-astra`, `model_reasoning_effort=medium`. A first attempt at max effort ran over the 20-minute cap and was discarded.
  - Claude subagents on the `sonnet` model alias.
- **Workspace:** a fresh copy of `create-next-app` 16.3.7 per run, keeping its realistic defaults (`lang="en"`, Geist via `next/font`). The template's AGENTS.md and CLAUDE.md were removed. Template SHA-256 prefix `7616f2ba63d7ee9d`.
- **Scoring:** this skill's checker, `scripts/check.mjs --json`, on each run directory.

Claude's baseline has fewer BLOCK-level defects, but 8 of 9 no-skill runs still carry WARN-level ones, mostly negative tracking on body text, and the skill removes those too.

## What the difference looks like

- **Codex without the skill** tightened headline tracking to about −0.06em (e.g. −2.8px, −3.5px). Among the 67 measured Korean services, no heading goes below −0.03em except one outlier at −0.05em. Codex also set `lang="ko"` on its own in both arms.
- **Codex with the skill:** tracking 0 to −0.03em, the Pretendard stack first, `keep-all` plus `overflow-wrap` on headings.
- **Claude without the skill** most often put `tracking-tight`-style negative tracking on 14–16px body text, and twice used `break-all`.

## Caveats (state these whenever the result is quoted)

1. **The checker encodes the skill's own rules**, so B scoring zero is partly expected. The evidence for value is that A breaks rules grounded in public specs and design systems (W3C klreq / CSS Text, KRDS / SEED / TDS) and in OmD's measurement of 67 Korean services.
2. **B names the skill explicitly** (one added line). It measures what the skill's content does once loaded, not whether it triggers automatically.
3. **Small n:** 3 runs per cell and one model per channel. Claude subagents may carry the session's project context; both arms are equally exposed.
4. **Static scoring only.** `check.mjs` reads source, not rendered pages. A before/after screenshot pair is still to be made for the README.
