# /hangul — UX writing rule sources

Every writing rule in `SKILL.md` §3b (HW-1 … HW-14) with its evidence, tier and sources. Quotes are verbatim where marked "…" and kept under 25 words; everything else is paraphrase. A rule appears in the main table only if each factual claim in it has a source that was fetched. Claims we could not verify are in **Unverified** at the end and are not used as rules.

Checks added on 2026-10-25 (more loanwords, dependent nouns, punctuation and dates, Japanese- and English-shaped frames, honorifics on things, document rules HW-D1 … D4) are sourced in `korean-issues.md`; how each situation is written is in `situations.md`.

Research base: five research passes run on 2026-10-24 over Toss, Karrot, Korean platform companies, Korean enterprises and financial firms, and Korean government and academic sources, plus spot checks of the orthography and dictionary by the author the same day. The working notes are OmD's internal research (`docs/research/2026-10-24-ux-writing/`, local-only, not committed to the public repository).

## Tiers

| Tier | Meaning | copy-check severity |
|---|---|---|
| SPEC | 「한글 맞춤법」 and its punctuation appendix (문화체육관광부 고시 제2017-12호, published by 국립국어원), and headwords of the 표준국어대사전 | BLOCK for a misspelling; WARN for spacing; FYI for punctuation that a house style may override |
| DS | Published Korean design-system and writing guidance: KRDS (행정안전부), the Apps in Toss developer guides (토스), SEED Writing and component docs (당근), the 국립국어원 plain-language guides, and the 금융위원회·금융감독원 guideline for senior-friendly finance apps | WARN when the check is mechanical; FYI when the rule depends on intent the checker can't see |
| DATA | A measured result: a survey or experiment with a stated sample, a company's published test, or OmD's own eval | as the rule it supports |
| OP | A company blog or talk without a measurement, a third-party agent harness, or this skill's own call (marked "skill call") | FYI |

When the project's DESIGN.md sets a voice, speech level, address term or house spelling, it overrides every tier here. These rules fill only what the brand leaves unset.

These rules hold in every situation. The situation (app, site, product, report, deck, notice, email, press, docs, hiring) sets the speech level, the build and the flow on top of them, with the checks it adds: [`situations.md`](./situations.md). What goes wrong in Korean in particular, by family, is in [`korean-issues.md`](./korean-issues.md).

## Checker scope (copy-check.mjs)

- **What it reads.** Text nodes in HTML, JSX/TSX, Vue, Svelte and Astro (joined per element, so `잔액이 <b>{n}원</b> 부족해요` is one sentence), attribute values (placeholder, title, alt, aria-label, props on components), string and template literals in JS/TS with the call, key or variable around them (including those in event handlers such as `onClick={() => setToast('저장했어요')}`, read by the call rather than the element), and JSON message files.
- **Roles.** Guessed from the element (button, h1–h6, label, a), the component name (Button, Toast, EmptyState), class names, prop and key names (errorMessage, ctaLabel, placeholder, title), and the call (toast()). A class that names a hint, caption or note (`button-hint`, `field-help`) marks helper text. A logo or wordmark's text is a name, not copy, and no rule reads it. A string whose role can't be guessed is "body". Two flags cut across roles: *error* (an error-named component, class, key or call, or error words in the text) and *dialog* (a Dialog, Modal or Sheet component, a dialog class, or alert()/confirm()). TypeScript generics such as `useRef<HTMLDialogElement>` are read as code, not as tags.
- **Left out on purpose.** Strings inside arrays of records (in JSON, any array of objects; in JS/TS, an array named for content users write or own, such as `listings`, `products`, `posts`, `people` or `members`), strings under keys for someone else's voice or data (prompt, say, example, alias, keyword, tag, q/question), console and logger calls, test and story files, generated files, and code blocks. Legal text (a component, key or file named terms, policy, privacy, 약관) is left out of HW-11, and of HW-9: a consent notice must say what refusing costs.
- **Documents.** Markdown (`.md`, `.mdx`) and text (`.txt`) files are read paragraph by paragraph: front matter, fenced and inline code, comments, HTML tags and link targets are skipped; headings, list items, table cells, quotes and image alt text keep their role. HW-4 and HW-8's system-wording note don't apply to documents, and the document rules HW-D1 … D4 do (`korean-issues.md`).
- **Situations.** `--context=<situation>` or a pragma sets one of `app`, `site`, `product`, `report`, `deck`, `notice`, `email`, `press`, `docs`, `hiring` per file (`situations.md`); detection recognizes only reveal.js, Marp and Slidev decks.
- **HW-11** treats one file as one screen or one document and counts statements only; questions and requests ("~할까요?", "~하세요") sit with either level.
- **HW-12** also notes a claim with nothing behind it ("업계 최초", "100% 만족", "최고의") and a short consent label that reads as a benefit ("혜택 알림 받기"), and HW-P5 ("장애자", "장애우") runs in every situation (owner 2026-10-25).
- **Limits.** It sees source, not the running product: no runtime strings, no text in images, and no knowledge of which strings share a screen. Spelling patterns are fixed lists; a misspelling outside them passes. "-에요" after a vowel is flagged as WARN because 에 can be a particle ("학교에요"); read those in context.

## Unverified (not used as rules)

- **Language mixing on one screen.** Only the toss/apps-in-toss-harness quality bar (G6-4) states it; no official Toss, Karrot, KRDS or 국립국어원 source does. 국립국어원 asks for Korean words where possible, which HW-7 covers.
- **Push length caps (title 7, body 25 characters).** Apps in Toss's limits for its own mini-app pushes; platform-specific, not a general rule.
- **Ranges with a hyphen only.** Karrot's house rule; 「한글 맞춤법」 allows both the wave dash and the hyphen.
- **Closed-up status values (예약중).** Karrot's house rule; SEED itself writes 검토 중 elsewhere.
- **해요체 for everything.** Toss's platform rule, not a general one (see HW-11).
- **'-실게요' ("이쪽으로 오실게요").** Widely called ungrammatical, but no 국립국어원 source was fetched this session.
- **Measured effects of specific copy.** Toss's banner tests (impressions ×10–20, CTR ×2–6, +20%p) report no sample size or design, and cover promotional banners, not product UI. Baemin's minimum-order-bar tests report directions only. No Korean A/B test of error wording or CTA labels with a stated sample was found.
- **공정거래위원회 「온라인 다크패턴 자율관리 가이드라인」 (2023-07-31).** Third-party summaries say it lists emotional language under pressure patterns and treats it as a problem only when it prevents accurate understanding; the official text was not fetched.
