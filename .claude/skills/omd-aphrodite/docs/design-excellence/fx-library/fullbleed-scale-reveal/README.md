# fullbleed-scale-reveal — 62% 에서 시작해 화면 끝까지 자라고, 거기서 머문다

| | |
|---|---|
| 계열 | 스크롤 · 이미지 |
| CSS-only | 아니오 — JS 38줄 (JS 가 없으면 `--e:1` 로 **풀블리드 정적 이미지**로 남는다) |
| 인라인 크기 | CSS 84줄 + JS 38줄 / **gzip 2.5KB** (raw 5.1KB) |
| 다크/라이트 | 둘 다 — 형태 효과. 자막 그라디언트만 라이트에서 알파를 낮춘다 |
| 라이선스 | 이 구현은 oh-my-design 자작, MIT. 외부 의존 0 |
| 난이도 | 중 |

## 왜 만들었나 — 실측된 문제
힉스젠 r3 렌더를 1440×900 에서 계측했더니, 미디어가 있는 10개 섹션 중 **6개**에서
가장 큰 이미지가 뷰포트 폭의 **40% 미만**이었다(중앙값 35.7%vw, 최소 11.5%vw).
"이미지를 소극적인 사이즈로 쓴다"는 지적은 취향이 아니라 수치였다.
이 효과는 그 반대를 **기본값으로 강제한다: 시작이 이미 62%, 끝은 100%.**

## 핵심 — 움직이는 값은 `--e` 하나다
JS 는 스크롤 진행을 `--e`(0..1, out-cubic) 하나로 환원해 컨테이너에 쓴다.
배율·라운드·자막 불투명도·진행 눈금이 전부 그 한 변수의 함수다.

```
scale  = 0.62 + 0.38 · e
radius = 26px · (1 − e)
cap    = clamp(0, (e − .55) · 2.6, 1)
```

`e = progress / settle` — **`settle` 이 이 효과의 전부다.**
`data-fx-settle="0.55"` 이면 핀 여정의 55% 에서 다 자라고, **남은 45% 동안 그대로 머문다.**
이 hold 구간이 "시원시원함"이다. hold 가 없으면(=`settle` 1.0) 이미지는 화면 끝에 닿는 순간
바로 밀려 나가고, 사용자는 큰 그림을 **본 적이 없게 된다.**

## 왜 ScrollTrigger 를 쓰지 않았나
GSAP+ScrollTrigger 는 이미 `scroll-gsap/` 에 인라인돼 있고 예산 114.7KB 를 쓴다.
이 효과가 필요한 것은 `rect.top / (offsetHeight − innerHeight)` 한 줄이다.
GSAP 을 이미 로드한 페이지라면 아래로 그대로 갈아 끼워도 동작이 같다:

```js
ScrollTrigger.create({
  trigger: ".fx-fbs", start: "top top", end: "+=" + (1.9 * innerHeight), scrub: .35, pin: ".fx-fbs__pin",
  onUpdate: s => el.style.setProperty("--e", Math.min(s.progress / 0.55, 1).toFixed(4)),
});
```
**`end: "bottom bottom"` 은 쓰지 않는다** — 섹션 높이가 바뀌면 settle 지점이 같이 흔들려
hold 가 사라진다. 여정 길이는 `+=` 로 명시한다.

## 금기
- **`--fx-fbs-min` 을 0.5 미만으로 두지 않는다.** 그러면 다시 "소극적인 이미지"다. 0.6~0.75 가 범위다.
- `settle` 0.75 초과 금지. hold 가 25% 미만이면 머무는 느낌이 안 생긴다.
- 한 페이지에 3개 초과 금지. 핀 구간이 190vh 씩 붙어 문서가 끝없이 길어진다(핀 구간 ≤ 4/페이지 규칙).
- 프레임 안에 **읽어야 하는 본문**을 넣지 않는다. 확대 중에는 글자 크기가 계속 변한다. 제목 한 줄 + 라벨까지.
- 같은 섹션에 유휴 3D 동사(`poster-cylinder`/`coverflow-ring`/`wide-drum`)를 겹치지 않는다. **스크롤 동사 1개.**
- 조상에 `overflow: hidden` 이 있으면 `position: sticky` 가 죽는다. 가장 흔한 실패 원인이다.
- `width: 100vw` 로 만들지 않았다 — 스크롤바가 있는 데스크톱에서 가로 오버플로가 난다. 프레임은 `width: 100%` 이고 **부모 섹션이 전폭**이어야 한다.

## 성능 조건
- 프레임당 쓰기 = 커스텀 프로퍼티 1개. 합성만 움직인다(transform·opacity). 레이아웃 0.
- `will-change: transform` 은 프레임 1개에만.
- `IntersectionObserver` 로 화면 밖에서는 스크롤 리스너를 **떼어 낸다**(rAF 만 끄는 게 아니라).
- 변화량이 0.002 미만이면 쓰기를 건너뛴다 — 정지 상태에서 스타일 재계산이 돌지 않는다.

## 모바일 / 리듀스드 모션
- ≤720px: 시작 배율 0.78, 여정 160vh. 작은 화면에서 0.62 는 너무 작다.
- `prefers-reduced-motion: reduce` → **② 완성 상태로 스냅.** 핀을 없애고(`position: static`) 이미지를 `min(84svh, 720px)` 정적 블록으로 남긴다. 이미지는 정보이므로 지우지 않는다.
- 호버 없음. 터치 기기에서 잃는 것이 하나도 없다.

## 이미지 슬롯
`.fx-fbs__ph` 색면 → `<img src="…" alt="">` 또는 `<video muted playsinline loop autoplay>`.
**1600px 이상 원본을 쓴다** — 끝에서 화면 전체를 덮으므로 저해상도가 그대로 드러난다.

## 검증 (헤드리스 크로미움 1440×900, 2026-09-04)
| 여정 | `--e` | 프레임 폭 | 라운드 |
|---|---|---|---|
| 0% | 0 | 62.0vw | 26px |
| 15% | 0.618 | 85.5vw | 9.9px |
| 30% | 0.906 | 96.4vw | 2.4px |
| 45% | 0.994 | 99.8vw | 0.15px |
| **55%** | **1** | **100vw** | **0px** |
| 70% / 98% | 1 | 100vw | 0px (hold) |

콘솔 에러 0 · 가로 오버플로 0px · reduced-motion 에서 에러 0 · 핀 해제 확인(1440×900 에서 프레임 높이 720px = 80vh 정적).

`data-fx-settle`(다 자라는 지점, 기본 0.55) · `fxLib.mountFullbleed(root, { settle })`
