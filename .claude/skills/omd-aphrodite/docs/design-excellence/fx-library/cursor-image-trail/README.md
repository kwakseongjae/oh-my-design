# cursor-image-trail — 프레임이 아니라 거리로 떨군다

| | |
|---|---|
| 계열 | 호버 · 커서 |
| CSS-only | 아니오 — JS 38줄 |
| 인라인 크기 | CSS 30줄 + JS 38줄 / 약 2.2KB |
| 다크/라이트 | 둘 다 (라이트는 그림자 알파를 낮춘다) |
| 라이선스 | 이 구현은 oh-my-design 자작, MIT. 외부 의존 0 |
| 난이도 | 중 |

## 핵심 — 대부분의 구현이 틀리는 두 가지
1. **`pointermove` 마다 떨구면 안 된다.** 프레임 기준으로 만들면 마우스를 천천히 움직일 때 같은 자리에 이미지가 쌓이고, 빠르게 움직이면 듬성해진다. 기준은 **누적 이동 거리**(기본 96px)여야 사람이 "궤적"으로 읽는다.
2. **DOM 을 만들지 않는다.** 요소 12개를 풀로 두고 `n % pool.length` 로 돌려쓴다. `createElement`/`remove` 를 반복하면 마우스를 몇 초만 흔들어도 GC 가 튄다.
   애니메이션 재시작은 `removeAttribute` → `void el.offsetWidth` → 재부여. 리플로우 1회는 의도적 비용이다.

소멸(등장·유지·블러 소멸)은 CSS `@keyframes` 가 전담한다. JS 는 위치와 각도만 넘긴다 — 그래서 38줄이다.

## 성능 조건
- 풀 크기 = 화면에 동시에 살아 있을 최대 장수. `life / (gap / 평균속도)` 로 잡는다. 기본값(900ms / 96px)에서 12장이면 넉넉하다.
- `will-change: transform, opacity` 는 풀 요소에만. 12장 = 레이어 12장이 상한이다.
- 소멸 구간의 `filter: blur()` 는 마지막 38% 에만 걸린다. 전 구간에 걸면 GPU 가 죽는다.
- `pointer-events: none` 필수. 트레일이 커서를 가로채면 아래의 링크가 안 눌린다.

## 금기
- **읽어야 하는 텍스트 위에 깔지 않는다.** 데모 2번(임계 24px / 수명 2.4s)이 그 반례다.
- 히어로 CTA 영역에 겹치지 않는다. 클릭하러 가는 길에 이미지가 터진다.
- 한 페이지에 두 구역 이상 두지 않는다.
- `overflow: hidden` 을 지우지 않는다. 지우면 트레일이 섹션 밖으로 새어 나가 스크롤바가 생긴다.

## 모바일 / 리듀스드 모션
- `@media (hover:none)` 과 `prefers-reduced-motion` 양쪽에서 **`display:none`** — 요소 자체를 없앤다. 트레일은 정보가 아니라 장식이므로 제거가 정답이다(fan/cylinder 와 다른 처리다).
- JS 도 두 조건에서 마운트 자체를 건너뛴다.

## 이미지 슬롯
`.fx-trail__ph` → `<img>`. 풀 12장 = 서로 다른 결과물 12장을 넣으면 "생성량"이 그대로 서사가 된다.
Higgsgen: 장르가 섞이도록 고른다.
