# /hangul before/after eval (2026-09)

A summary of OmD's before/after eval of this skill, run on 2026-09-29. The full write-up, the eval plan with the prompt text, and the raw per-run results live in the oh-my-design repository (`docs/research/2026-09-29-growth/`, raw results under `raw/hangul-eval/`), not in this skill folder.

**Result:** without the skill, 17 of 18 runs broke at least one Korean typography rule (BLOCK or WARN). With `/hangul`, all 18 runs had 0 BLOCK and 0 WARN. These are the numbers as scored on 2026-09-29. The checker was revised on 2026-09-30, after the eval, and the same outputs were rescored (see [Rescore](#rescore-with-the-revised-checker-2026-09-30)). The headline holds at 17 of 18 and 0 of 18. Claude's no-skill runs with a BLOCK drop from 3 of 9 to 1 of 9.

## Design

- **Prompts:** 3 Korean UI tasks: p1 fintech hero, p2 mobile settings page, p3 pricing section.
- **Arms:** A has the prompt only. B has the same prompt plus one line: "이 작업에는 hangul 스킬을 적용한다: .agents/skills/hangul/SKILL.md를 읽고 그대로 따른다", with the skill folder copied into the project.
- **Runs:** 3 per prompt × arm × channel, 36 total.
- **Channels:**
  - Codex CLI 0.158.0, `gpt-6-astra`, `model_reasoning_effort=medium`. A first attempt at max effort ran over the 20-minute cap and was discarded.
  - Claude subagents on the `sonnet` model alias.
- **Workspace:** a fresh copy of `create-next-app` 16.3.7 per run, keeping its realistic defaults (`lang="en"`, Geist via `next/font`). The template's AGENTS.md and CLAUDE.md were removed. Template SHA-256 prefix `7616f2ba63d7ee9d`.
- **Scoring:** this skill's checker, `scripts/check.mjs --json`, on each run directory (checker SHA-256 prefix `b197bce319c560c7`). Rescored on 2026-09-30 with the revised checker; see below.

## Rescore with the revised checker (2026-09-30)

**Why the checker changed.** Launch content for this skill rendered the eval outputs in headless Chrome. Five of the recorded findings turned out not to be Korean typography defects:

- **The three Codex HG-11 WARNs** (no-skill arm). p2-A-r2 italicises "A little more you." in Georgia, a Latin face with a real italic. In p2-A-r3, the old line regex read the text after an empty `<i/>` dot ("이용 중") as the italic's content. p3-A-r3 italicises Latin logo text ("fastfive" and others).
- **The two Claude HG-8 BLOCKs** (no-skill arm). Both are referral-URL boxes (p2-A-r2, p2-A-r3), which have to break anywhere with or without `break-all`.
- **HG-7 on a Latin wordmark**, which moved no count. HG-7 also flagged the wordmark "moa." (`letter-spacing: -2px`) in Codex p1-A-r3. The minified stylesheet puts it on the same line as the Hangul h1 at −3.3px, and the checker reports one finding per line and rule, so that line stays a BLOCK for the h1.

**What changed.** `check.mjs` now traces each rule and class to the elements it reaches and reads their text, attributes excluded. HG-7 is skipped only when every reached element holds non-Hangul text. HG-11 fires only on confirmed Hangul. HG-8 drops to FYI for a URL, email or long unbroken token. Untraceable text keeps the old severity for HG-7 and HG-8 (`rules.md`, "Checker scope"). The outputs were not regenerated: the same 36 run directories were rescored. Re-run over them, the old checker reproduces the recorded results exactly (36 of 36 runs, finding for finding).

## What the difference looks like

- **Codex without the skill** tightened headline tracking to about −0.06em (e.g. −2.8px, −3.5px). Among the 67 measured Korean services, no heading goes below −0.03em except one outlier at −0.05em. Codex also set `lang="ko"` on its own in both arms.
- **Codex with the skill:** tracking 0 to −0.03em, the Pretendard stack first, `keep-all` plus `overflow-wrap` on headings.
- **Claude without the skill** most often put `tracking-tight`-style negative tracking on 14–16px body text, and twice used `break-all`. Both `break-all` uses were on URL boxes, and the revised checker reports them as FYI.

## Caveats (state these whenever the result is quoted)

1. **The checker encodes the skill's own rules**, so B scoring zero is partly expected. The evidence for value is that A breaks rules grounded in public specs and design systems (W3C klreq / CSS Text, KRDS / SEED / TDS) and in OmD's measurement of 67 Korean services.
2. **B names the skill explicitly** (one added line). It measures what the skill's content does once loaded, not whether it triggers automatically.
3. **Small n:** 3 runs per cell and one model per channel. Claude subagents may carry the session's project context; both arms are equally exposed.
4. **Static scoring only.** `check.mjs` reads source, not rendered pages. Rendering the outputs showed five findings that were not Korean typography defects, which led to the 2026-09-30 revision above. Rendering can also show defects the source checker misses: at 360px, a heading in Codex p1-A-r3 (no skill) breaks mid-word as `…함께하고 있어 | 요.` (launch-content notes, 2026-09-30). The optional `scripts/render-check.mjs` now checks rendered line breaks, but this eval was not rescored with it. A before/after screenshot pair is still to be made for the README.
