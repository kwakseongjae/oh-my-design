# /hangul — rule sources

Every rule in `SKILL.md` §3 with its evidence, tier and source URL. Evidence quotes are verbatim where marked "…", otherwise paraphrased. A rule appears in the main table only if every factual claim in it has a URL. The one exception is the `Intl.NumberFormat('ko-KR')` output in HG-13, which is a local Node run anyone can reproduce. Everything else is in **Unverified** at the end.

Research base: `docs/research/2026-09-29-growth/hangul-canon.md` (canon rows H-01…H-27) and `hangul-measure.md`. The key DS and spec numbers were re-checked on 2026-09-29 against the original pages (raw HTML via curl, plus WebFetch); see the **Verification log**.

## Tiers

| Tier | Meaning | AUDIT severity when violated |
|---|---|---|
| SPEC | W3C/CSS specifications and notes (klreq, CSS Text, W3C i18n), MDN pages summarizing them, and the Korean orthography (국립국어원) | BLOCK when the defect is confirmed; WARN when the target text can't be confirmed |
| DS | Public Korean design-system docs (KRDS, SEED, Toss TDS) and official font docs (Pretendard) | BLOCK or WARN, per rule |
| DATA | OmD's measurement of 67 Korean services, captured 2026-07-11..13 on public web surfaces ([measured-67.md](./measured-67.md)) | WARN, or BLOCK when a hard rule ("never below") is set from it |
| OP | A named practitioner source, or this skill's own call derived from sourced facts (marked "skill call") | FYI |

When a project's DESIGN.md sets a value, it overrides every tier here.

## Unverified (not used as hard rules)

- The 1.7 upper bound for long-form line-height. Only lqez's 2018 observation of 1.6–1.8 exists; the cap is a skill call.
- What an OS actually falls back to (Apple SD Gothic Neo, Malgun Gothic, Noto Sans CJK) and which weights those fonts ship. No Apple or Microsoft document was consulted.
- How the browser picks a substitute weight when the requested one isn't loaded (the MDN font-weight fallback rules were not fetched). SKILL.md only says the weight "may not render as written".
- That `text-transform` has no effect on Hangul. No source states it; SKILL.md avoids the claim.
- How `text-wrap: balance | pretty` interacts with Korean and keep-all. MDN doesn't mention CJK.
- Whether `word-break: auto-phrase` supports Korean in 2026. The last source is the 2023-12 Chrome blog.
- Browser initial values for `text-autospace`. Sources conflict (canon §3).
- The text of 한글 맞춤법 §43 itself. Only the 국립국어원 Q&A answer was read.
- WCAG 3.1.1 (Language of Page). Not fetched; HG-2 rests on the W3C i18n article.
- Naver and Kakao design-system typography docs. Not consulted.
- The folk claim that "−1px to −2px letter-spacing is normal for Korean fonts". No source. lqez 2018 saw −1px to +0.8px, and OmD's data floor is −0.03em for headings.
- How often each failure mode actually appears in agent output. No data yet; the eval plan measures it.
- Whether TDS React Native units map 1:1 to CSS px. They're compared as equal here.
- The exact default `font-sans` stack of each Tailwind version. The checker only relies on it naming no Korean face.
