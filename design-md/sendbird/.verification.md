## 2026-09-21 — the UIKit Storybook, and why a full component library still isn't enough

`sendbird.github.io/sendbird-uikit-react` was found by the GitHub sweep
(`docs/SURFACE_SWEEP_2026-09-21.md` §5); nothing here had cited it. 38 stories, 18 components,
**90 `--sendbird-*` custom properties**. `ds.url` now points at it rather than at the docs
overview, because this is the surface that can be measured.

**Why `tokens.source` was `prose-derived` and now is not.** The June pass read values from
UIKit *source* — Android `colors.xml` and component SCSS — which is transcription, so
`prose-derived` was the honest label at the time. Today those same values were read from
rendered DOM in a browser. That is what makes `live-extract` true now; the field was not
wrong before, the method changed.

### Raw samples — UIKit Storybook, 2026-09-21

All button variants `40px` tall, `border-radius: 4px`, `13.3333px / 400` Roboto:

- Primary :: background `rgb(116, 45, 221)`. Hover `rgb(98, 17, 200)`; pressed `rgb(73, 19, 137)`;
  focus border `rgb(255, 255, 255)`.
- Secondary :: background transparent. Hover and pressed border `rgb(116, 45, 221)`.
- Danger :: background `rgb(222, 54, 11)`. Hover `rgb(191, 7, 17)`; pressed `rgb(157, 9, 30)`;
  focus border `rgb(255, 255, 255)`.
- Disabled :: background `rgb(224, 224, 224)`; color `rgb(16, 16, 16)`.
- Checkbox :: `22px`, `border-radius: 2px`; focus background `rgb(116, 45, 221)`.
- Toggle :: `20px` track, `border-radius: 12px`, off `rgb(189, 189, 189)`; focus `rgb(116, 45, 221)`.

10 of the 16 declared colours resolve as published `--sendbird-*` tokens, positionally named:
`primary` is `light-primary-300`, `primary-hover` `light-primary-400`, `primary-active`
`light-primary-500`, `error` `light-error-300`, `success` `light-secondary-300`, `info`
`light-information-100`, `muted` `light-background-100`. **The June values were exactly right.**

`light-*` and `dark-*` variants both ship; the dark theme was not measured and is not claimed.

### Two surfaces, kept apart

The other six colours — `#0d0d0d`, `#424242`, `#f2f3f7`, `#e3e5ef`, `#d1d1d1` — have no UIKit
token. They are `sendbird.com` marketing values, keep their 2026-06-01 date, and are marked as
such in §2. `#f2f3f7` was re-confirmed live today.

A note on instrument discipline: measuring `sendbird.com` today, the only controls my filter
found were the **cookie-consent banner's** buttons (`#0d0d0d` pill at 24px radius — which
happens to match the declared `cta-dark-pill`). The banner was hidden with CSS rather than
accepted, and none of its values were recorded. A consent widget is not the brand's component,
even when it is styled like one.

### Evidence limitations

- **Three of ten interactive components carry no observed state**, so this stays `partial`:
  `cta-dark-pill`, `cta-outline-pill` and `input-newsletter` — all three on the marketing site,
  none of them in the UIKit Storybook. Their June values are retained with their June date.
- This is the structural finding, not a gap in effort: a complete published component library
  is **not sufficient** for `verified_v2` when the reference also documents a marketing surface
  the library does not cover. asana hit the same wall from the other direction.
- The UIKit dark theme is published and entirely unclaimed. No authenticated or embedded
  production chat instance was measured.
